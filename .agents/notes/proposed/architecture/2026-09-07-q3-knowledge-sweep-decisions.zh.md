# Agent Note: 2026 年 6 月至 9 月知识扫描的决定

Status: proposed

[English](2026-09-07-q3-knowledge-sweep-decisions.md) | 中文

## 问题

实验室针对这四个目标的计划，建立在一份截至 2026 年上半年的知识之上。在随后的三个月里，本 harness 同时变成了一个被训练的对象与一个被度量的对象，奖励的完整性被量化，且结果比原先假设的更差，120B 级别的开放权重版图更换了许可证，通用型模型的监管被逐个司法辖区地梳理了一遍，而竞争对手发布了常驻运行的 fleet 与自我改进的 harness，并附带了公开结果。建立在旧图景之上的决定，将会以已知的方式出错。证据现在存放在 [2026-q3 知识包](../../../../data/knowledge/2026-q3/manifest.json) 中；本 note 记录的是实验室据此做出的各项决定，以及它排入队列的切片。每个事实只有一个归属位置：数字与 URL 都留在知识包的主题 skill 与语料库中。

## 提案

采纳下面这二十项决定，按目标分组，作为这份计划对该窗口的回应；每一项都点名它所触及的那条 seam。

### 目标 1，harness

1. 在工具桥（`dsh-mcp-tool-server`）上提供双时代的 MCP 对外接口：2026-07-28 的无状态版本与当前版本并存。
2. `dsh-scorekeeper` 中缓存正确的计费：原始输入、缓存读取与有效输入各自作为独立事实；任何 composition 之间的成本比较都使用有效输入，而每次 certified 运行的 token 数、无操作轮次与失败类别向量都成为一等事实。
3. 在 `dsh-fleet` 与 `dsh-shifts` 中，于计划冻结时进行预检式的路由校验。
4. 模型无关性依然是产品层面的论点；运营方自己的 Claude Code 安装只是多条路由中的一条，而 fleet cell 的命名方式是 harness 乘以模型乘以运行时。

### 目标 2，软件创建

5. 一个 Harbor 适配器，使 harness 能在外部排行榜下不加改动地运行；再加上通过 `dsh-program` 完成的一次 Terminal-Bench Challenge，作为 certified 部分进展的外部效度检验。
6. 奖励来源标签：由 certificate 裁定的奖励是一个层级，评审裁决是另一个层级，两者绝不混合。

### 目标 3，模型

7. 目前领先的基座候选是 Mistral-Small-4-119B-2603（Apache-2.0，总参数 119B，激活参数 6.5B，欧洲产），并以 Leanstral-1.5-119B-A6B 作为微调后再发布的先例；模型压缩阶段从一开始就已纳入计划；这项决定本身由实验室负责人拍板，并在任务清单中保持开放。
8. LLM 路由是 token 采集的分界线：跑在训练器所提供路由上的、harness 原生的运行会产出策略 token；委托给外部实现者的运行只是度量，绝不构成训练行，由导出时 stamp 上的 `implementer` 字段强制执行这一点。
9. 训练默认值：每一个优势值的符号都由验证者决定，任何 shaping 项都只能对它做缩放；LoRA 采用 1e-3、rank 64，规模比照一个稠密模型来定，取激活参数与总参数的几何平均值；针对并行调用坍缩、已发布的惩罚词表，作为第一个 shaping 集合。
10. curator 的下一个脱敏配置，是一种带类型化 slot 的边界，使用保留格式的合成密钥，且只以预先埋入的凭证作为验收依据；答案挖矿（git 历史、reflog、blame、网络检索）被列为一种篡改模式，其验收测试是一个公开的召回集。
11. 增加第二个导出汇点，采用 Hub 可检测的 trace 格式，默认私有，遵循相同的数据使用条款。
12. 压缩（compaction）现在成为一个实验变量，以后会成为一个经过训练的 seam。

### 目标 4，改进循环

13. 在一个已还原的 fixture 上做 gold-patch 校验，是进入注册表与获得任何 certificate 的前提条件，存活率按每个导入集合分别发布；一个适配器负责接纳 Harbor 的任务树。
14. 行为 monitor 的裁决是一条被记录的篡改裁决，依据当前策略的 rollout 结果刷新，并配有蜜罐路径，使其中一部分具备确定性。
15. 实验在配对区间之外还报告一个留出可靠性估计，以及一个按难度分层的细分；晋升裁决采用「保留并扩展」规则（每个 cell 上净收益为正，且退化幅度有界）。
16. 环境从实验室自己的 certified 运行中重建，绝不导出留出材料。
17. 源自 ruflo：对 composition manifest 做签名的 witness；在观测台的渲染路径中加入报告规则；把一个 shift 产出的去向记在它的 ledger 上，并带有一个滞后的使用率。
18. shift 采用事件驱动的唤醒机制，以一条被记录的 ledger 事件的形式呈现。

### 治理与商业

19. 欧盟 AI 法案所需的产物，由 composition manifest、数据使用条款、签署记录，以及带累计算力的训练运行记录生成；发布物的形态是一份 AI 物料清单，携带该领域自身文档所欠缺的字段；一份按司法辖区划分的义务表，随附在每份客户合同的技术附件中；运行器的 certificate 导出变为可签名的，以此回应第三方签名证据的要求。
20. 基座模型的许可证按版本钉定在 lineage 记录中；许可证变更是一次供应链事件。

## 扫描是如何进行的

三个研究 agent，每个来源一个（GitHub、Hugging Face、arXiv），都遵循同一份任务简述：2026-06-01 到 2026-09-07 之间与四个目标相关的技术前沿，一手来源优先，每个数字都带 URL，证据分为一手、二手或声称三个等级。它们各自的简报与条目由 `data/knowledge/tools/build-pack.mjs` 合并为一个语料库，按 URL 去重，并分发到八个主题 skill 上；该知识包通过文件系统 skill 提供方提供给 agent，具体方式见[知识包 note](2026-09-07-knowledge-packs.md)。第四个 agent 从一次浅克隆出发，把 ruflo 与本 harness 做了比较；这一结果就是[ruflo 对照 note](2026-09-07-ruflo-comparison.md)。

## 扫描给路线图带来的改变

Village note 的落地阶段顺序保持不变；上文的第 2、4、5、9、10、13、14、15 与 17 项，成为其中具名的切片，而基座模型任务把决定 7 作为其推荐方案。有两项发现约束了这份计划，而不是扩展它：harness 的选择对成本的影响远大于对通过率的影响，因此没有成本数据就不发布排行榜行；以及 agent 主效应在公开的 agent-trace 基准测试上只占方差的一小部分，因此一个声称的差值需要一个留出可靠性估计，而不能只靠配对种子。

## 未决问题

- 基座模型的决定（Mistral-Small-4-119B-2603 对比已获许可的替代方案），以及它所隐含的硬件方案。
- harness 自己的 RL 运行，是使用外部训练器的端点（TRL、prime-rl），还是使用内部自建的路由，这一点仍未确定；无论哪种方式，token 采集的分界线都是一样的。
- 为 district 产出的评审配备人力：certificate 能提高一个 shift 产出内容的质量，却不能让它落地。

## 曾考虑的替代方案

- **把决定留在聊天记录与已发布页面中。** 拒绝：不持久，不与证据关联，且对在本仓库中工作的 agent 不可见。
- **用一份 note 把证据直接内嵌其中。** 拒绝：每个事实只有一个归属位置；数字与 URL 归知识包管，决定归本 note 管。
- **采纳三个 agent 提议的每一项行动。** 拒绝：三十项提议被收敛为受限于我们自身 seam 与证据质量的二十项；一个图记忆基质与一个低于噪声下限的训练结果，都在被舍弃之列。

## 验收标准

- 每一项编号决定都映射到一个任务或一个带有其 seam 的具名切片，且基座模型任务把决定 7 作为其推荐方案。
- 这些决定所依据的知识包连同其 manifest 一并提交，并通过 `verify-knowledge-packs`。
- 下一次季度扫描产出的是一个新的包与一份新的决定 note，而不是对本 note 的编辑。

## 风险

- 某个研究 agent 的错误会传导进一项决定；证据分级与一手来源规则限制了这一点，每一项决定在其上构建切片之前，都会对照其一手来源验证。
- 二十项决定超出了近期的产能；由 Village 的落地阶段顺序说了算，本 note 不会重新排序。
- 许可证与监管方面的解读，是对这些来源的工程解读，而非法律意见；客户合同需要在此之上征求法律顾问的意见。
