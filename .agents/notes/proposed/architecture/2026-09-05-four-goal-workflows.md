# Agent Note: The four goal workflows

Status: proposed

English | [中文](2026-09-05-four-goal-workflows.zh.md)

## Problem

DeepSeek Harness carries four goals for the lab it serves: the harness that makes any LLM the best agentic coder; the best agentic software creation delivered through that harness; a roughly 120B-parameter open-weight model trained with RLVR from fleet transcripts; and the auto-improvement loop that feeds both the harness and the model from the same fleet of sessions. Root [AGENTS.md](../../../../AGENTS.md) states everything is a plugin; a goal pursued outside that discipline — a hand-rolled orchestration script, an LLM judgment with no deterministic check behind it, a hand-off no session event carries — would be unbuildable from documented extension points and unreplayable from the session log.

Each goal therefore needs one long-running workflow: a Cordis plugin composition with a deterministic spine that carries authority (session-log folds, static gates, verifiers, schema validation, replay, statistics) and semantic joints that never decide alone (an LLM critiques, synthesizes, diagnoses, or proposes, and every semantic-to-deterministic hand-off is a structured output a deterministic stage validates). A first draft of the four workflows was measured against seven independent judge lenses; [the council review](../process/2026-09-05-workflow-council-review.md) records that process. This note fixes the design the review produced: one meta-agent roster, one set of structured hand-off schemas, and one scoreboard row schema serve all four workflows, so a component scored in one workflow is the same component scored in another.

## Proposal

Four workflows, one per goal, share seven principles, one meta-agent roster, a fixed set of structured hand-off schemas, and one scoreboard row schema. Each stage below is typed D (deterministic), S (semantic), DS (a semantic stage authoring into a deterministic executor), GATE (a static or archival gate with no human in the loop), HUMAN (an attributed human decision), or STORE (a durable projection or ledger), and carries a status of `implemented`, `partial`, or `proposed` against the plugins that exist in this repository today.

### Principles

- **P1 — Everything is a plugin.** Knowledge (skills, context providers, MCP servers), agents (presets, subagent providers), tools, policies, judges, scoreboards, environments, and datasets are all Cordis plugins; a workflow is a `cordis.yml` composition plus an orchestration script plus an environment suite plus completion standards, and is itself a `composition` component with members and lineage under the [component registry seam](2026-09-01-component-registry-seam.md).
- **P2 — Deterministic spine, semantic joints, evidenced by durable events.** Every stage is D or S; S never holds authority by itself, and a D gate is sound only when it reads a durable event the implementer cannot forge — the `environment/run` stamp before the first turn and a `verification/run` event for every executed check, passing or failing (see [the environment runner](2026-09-05-environment-runner.md)) — rather than a worker's self-report. Every S→D hand-off is a structured output validated against a JSON Schema; a rejected output returns to the S stage with the validation error as its directive.
- **P3 — The log is the dataset.** Each workflow leaves session logs that fold into trajectories, scoreboard rows, and Agent Notes; nothing model-visible bypasses the log, so every metric is recomputable from first principles.
- **P4 — The read barrier is filesystem and process authority, not a promise.** A validator-owned root the implementer's executor cannot read, monotonic tool guards, implementer presets that never compose a log-reading tool, and an invariant that rejects a certificate from a session that composed one replace an asserted "the implementer never sees it"; see [the verification, improvement, and oversight seams](2026-08-29-verification-improvement-oversight-seams.md). Cross-model judging routes a judge through a model different from the worker's; under one model licence, the second route is filesystem and process isolation plus a fresh judge session with no implementer context, never the same lineage grading itself.
- **P5 — Lineage and archive, content-addressed.** Every component, preset, prompt section, environment, and dataset carries `provenance` (`curated` or `synthesized`) and `lineage`, and a mutation mints a new content-addressed id so lineage survives a patch; a promotion is an Agent Note plus a PR, and the archive keeps every evaluated variant, losers included — Darwin Gödel Machine archive semantics — over a durable `dsh-archive` store, never only the current best.
- **P6 — Held-out discipline, decontaminated by content hash.** `heldOut` environments are never exported as training data and never shown to improvement agents; the [environment/run stamp's](2026-09-05-trajectory-export-and-environment-registry.md) content hashes of prompt, fixture, and checks are what decontamination and export withholding key on.
- **P7 — Budgets are explicit and durably enforced.** Every fan-out carries agent caps, token, and cost budgets from config, never from code constants; a budget policy plugin folds usage on `agent/pre-step` against those caps and blocks the goal durably on breach, and the observatory reads spend from the same logs.

### W1 — Harness capability program

Goal 1 — the harness that makes any LLM the best agentic coder. An archive-first search over harness variants: every run is stamped in its own session log, parents are sampled from an archive that keeps losers, the mutator never touches the evaluator, and only a staged paired experiment plus an attributable human promote a variant into source.

`@deepseek-ai/dsh-fleet`'s `LeaderboardRow` (stage 3, implemented) already carries `provider`, `model`, `environmentId`, `environmentKind`, `heldOut`, `isolation?` (absent when every cell of the row failed before a run), `runs`, `errors`, `certified`, `certificateRate`, `attemptsMean`, `inputTokens`, and `outputTokens`, one row per model route and environment, so W1's model matrix already folds today from certificates alone; it is a fold of one fleet run, and `@deepseek-ai/dsh-scorekeeper` folds the same rows back out of the persisted logs so a scoreboard survives the process; cross-run comparison, paired designs, and confidence intervals stay stage 9's job over the session logs, where `@deepseek-ai/dsh-experiments` now folds them from two arms of one frozen plan.

Parent selection (stage 6) draws a variant from the archive in proportion to quality × novelty × 1/(1+children) within islands per environment kind, and seeds an empty archive with master as generation zero, so the sampled parent — never `master` directly — is what the quarantined Harness Engineer mutates.

The Harness Engineer's `harness-lab` preset carries no scored `ctx.goals` or `ctx.completionStandards` and no `tool-cordis` façade over environments, standards, or trajectories, and every proposal is content-hashed and frozen before the novelty gate or the staged evaluation runs, so nothing semantic can retarget its own evaluation after seeing a result.

Staged evaluation (stage 9) runs a three-stage ladder — eight training-eligible environments at one repetition, then the diagnosis-and-lineage-derived cells at k paired repetitions with bootstrap confidence intervals, then the held-out suite once per Pareto-front variant and never shown to any semantic stage — and every result is archived alive or dominated, never discarded; a model-visible text change still requires a human diff review at promotion, and a snapshot re-record is never automatic.

### W2 — Certificate-first software factory

Goal 2 — the best agentic software creation through the harness. Compile the signed spec into hidden standards before anything else, run every goal as its own session under a program ledger, let the runner validate against a tree hash, admit humans where authority must be attributable, and release only what a certificate on the merged head proves.

Program ledger (stage 5) is durable `program/*` events mapping every goal of a program to its session, workspace, preset, isolation, budget, and status, so the orchestrator resumes from the ledger after a restart, and the `Plan` is derived from the compiled standards rather than authored freely beforehand.

The read barrier (stage 4) is filesystem and process authority, not a promise: a validator-owned root the implementer's executor cannot read, monotonic tool guards, implementer presets that never compose a log-reading tool, and an invariant that rejects a certificate from a session that composed one; a `host`-isolation certificate is only as strong as this enforcement, and every certificate records the isolation level it actually ran under.

Departments (stage 6) run as fresh top-level sessions created by the program service rather than as subagents pinned to a `never` approval outcome, so a department can ask a named human and run its own preset; a deny-capable monitor on `ctx.tools.guard()` denies deploy, secrets, production data, and egress by default and asks a bounded human class for the rest, and a budget breach blocks the goal durably rather than letting the department run past its cap.

Integration (stage 8) is itself a goal whose standard runs against the merged head, so a certificate never goes stale at merge; release (stage 10) signs the certificate on that merged head together with the review and the changelog, and deployment happens under that signature, never on an agent's initiative.

The project's own checks become `synthesized` environments only after admission — failing on the pre-state, passing on the reference, a gaming agent failing to certify — and a human assigns the training split before anything trains on them.

### W3 — Environment-first model pipeline

Goal 3 — a roughly 120B-parameter open-weight model trained with RLVR that beats frontier models on the fleet's tasks. The unit of data is a group of rollouts of one environment under one policy version, produced on demand by the runner. Fleet sessions feed a short SFT cold start and the environment factory; RL rewards come from hidden checks on a pristine fixture plus the patch, and every artefact down to the model card is generated from the same records.

| 9. Recalibration and feedback | Scorekeeper | STORE | partial | `EnvironmentStats`, `ScoreboardBatch` | existing: trajectories, scorekeeper; new: policy-version keying | — feeds W3's own calibration and W4 facts. |

The unit of data is a group of rollouts of one environment under one policy version, produced by the runner on demand, not a fleet session harvested after the fact; fleet sessions instead feed a short SFT cold start (including validator and diagnostician role sessions with deterministic rewards) and the environment factory.

Reinforcement learning (stage 5) runs outside the session log: the reward is computed on a pristine fixture plus the implementer's patch under host isolation with hidden checks, so any write under check-owned paths is a tamper verdict with reward zero, and truncated, aborted, or errored rollouts are masked rather than scored as failures; a correlation header on the LLM seam lets the trainer's inference proxy join token ids and logprobs to the session, turn, and step that produced them.

Held-out evaluation (stage 6) pins the harness variant so a checkpoint is never measured against a harness that co-evolved with it, and safety and alignment (stage 7) freezes every mitigation plan before it runs so nothing grades itself; the accountable officer's `ModelLineage` record generates the Article 53 documentation and fires an alarm at a configured fraction of the systemic-risk compute threshold.

Goal 4 — the loop that feeds both the harness and the model. A fast loop where agents write and refine skills in their department layer under a deterministic keep-or-retire scoreboard, and a slow loop where frozen experiments and attributable humans move knowledge into the fleet. Both read one content-addressed ledger; the observatory is a projection of the log, not a pipeline beside it.

The fast tier (stage 4) lets an agent write a skill after use and refine it by re-registration inside its own department layer — nothing here is fleet-shared, model-visible outside that layer, or exported — and only a candidate with evidence sessions and a declared scope of session, department, or client is eligible for the deterministic keep-or-retire scoreboard (stage 5), which compares paired present-versus-absent cells and marks a skill deprecated once its delta stays at or below zero over the configured number of runs.

The slow tier freezes a nominated proposal's digest before any cell runs (stage 6), derives cells from the diagnosis evidence plus a stratified held-in sample plus a held-out regression by a logged deterministic rule, and never lets an S field set priority; prompt sections, tool schemas, and skills always need a human at promotion (stage 8), while policy and presentation changes with no model-visible text may promote on the experiment alone.

The knowledge ledger (stage 9) keeps every `id@digest` with lineage, evidence sessions, results, and decisions, losers included, mirrored against the composition manifest so replay can tell exactly which components were in play; audit (stage 11) hash-chains persisted artefacts per checkpoint and signs daily manifests to write-once storage, with a per-client crypto-shredding key for erasure.

### Structured hand-offs

Every S→D hand-off across the four workflows validates against one of the following schemas; a rejected value returns to the producing S stage with the validation error as its directive.

- **`CapabilityMatrix`** — which model routes run which harness presets in this program. Fields: `cells[]` (`{provider, model, presetId, reasoningEffort, budgetEur}`); `harnessCommit` (string, the git sha of the harness under test); `createdAt` (epoch ms).
- **`SuitePlan`** — the environment cells of one run batch. Fields: `environments[]` (`{id, kind, heldOut, difficulty, domain}`); `seeds[]` (int, paired seeds shared by baseline and candidate); `isolation` (`none` / `process` / `host`, from config); `attemptBudget` (int, per session).
- **`EnvironmentRunReport`** — one environment run as one fresh session. Fields: `environment` (`EnvironmentId`); `sessionId` (`SessionId`, the durable record); `attempts[]` (`{attempt, results[{checkId, status, evidence}]}`); `certified` (boolean); `certificate?` (`VerificationCertificate`, present exactly when certified); `usage?` (`TokenUsage`, summed over assistant messages).
- **`ScoreboardBatch`** — scoreboard rows folded from a batch of sessions. Fields: `rows[]` (the scoreboard-row schema below); `harnessCommit` (string); `computedAt` (epoch ms).
- **`SessionDiagnosis`** — why one session failed or wasted budget, and who owns the fix. Fields: `sessionId` (`SessionId`); `taxonomy` (`tool-misuse` / `context-loss` / `spec-misread` / `verification-gaming` / `loop` / `environment-defect` / `model-limit`); `evidenceSeqs[]` (int, the event seqs the claim rests on); `rootCause` (string); `owner` (`harness` / `model` / `environment` / `spec`); `confidence` (0 to 1); `proposedExperiment?` (string).
- **`HarnessPatchProposal`** — a component-level change with its predicted effect and its rollback. Fields: `id` (string); `targets[]` (`ComponentId`); `changeKind` (`prompt-section` / `tool-schema` / `presentation` / `policy` / `skill` / `preset`); `rationale` (string, citing `SessionDiagnosis` ids); `predictedDeltas[]` (`{metric, cell, delta}`); `affectedCells[]` (string, the only cells re-run); `branch` (string); `rollback` (string).
- **`GateReport`** — the result of one static gate over a branch. Fields: `gate` (`typecheck` / `lint` / `coverage` / `doc-sync` / `snapshots` / `invariants` / `duplication` / `hygiene`); `passed` (boolean); `findings[]` (`{path, line?, message}`); `durationMs` (int).
- **`ExperimentResult`** — paired comparison of candidate against baseline on the affected cells. Fields: `proposalId` (string); `cells[]` (`{cell, baseline, candidate, delta, ci95}`); `seedsPaired` (int); `costEur` (number); `verdict` (`promote` / `reject` / `inconclusive`).

## Alternatives considered

**Best-only promotion.** An earlier design kept one merged head per generation and folded a losing variant back into nothing; every evaluated-but-unpromoted variant is now kept `alive` or `dominated` in a `dsh-archive` ledger, sampled for the next parent in proportion to quality × novelty × 1/(1+children) within islands per environment kind — Darwin Gödel Machine archive semantics, where low-scoring ancestors have proven necessary stepping stones toward the eventual best variant. This is rejected as the sole store because best-only hill-climbing has no stepping stones and no transparent lineage to audit for a fabricated result.

**Self-selected evaluation cells.** An earlier design let the same proposal choose its own affected cells and predicted deltas before any run, and nothing froze the proposal before results were visible. This is rejected because it lets a semantic stage fund and shape its own evaluation; cells now derive from `SessionDiagnosis` evidence plus component lineage by a logged deterministic rule, and every proposal is content-hashed and frozen before a cell runs.

**Reward computed in the implementer's workspace.** An earlier design ran checks against the same tree the implementer had just edited, so a certificate could pass because a test or a fixture was edited rather than because the task was solved. This is rejected because it is directly gameable — editing tests, `conftest.py`, or a package script earns a certificate — and reinforcement learning finds this exploit within tens of steps; checks now run on a pristine fixture plus the implementer's patch under `host` isolation with hidden checks, and a write under check-owned paths is a tamper verdict with reward zero.

**Fleet sessions as reinforcement-learning data.** An earlier design for the model pipeline harvested fleet sessions directly for training, but a fleet session carries no environment identity, no group, and no seed, so decontamination, curriculum sampling, and GRPO grouping had nothing to key on. This is rejected in favor of an environment-first, group-first factory: the unit of data is a group of rollouts of one environment under one policy version produced by the runner on demand, and fleet sessions instead feed a short SFT cold start and the environment factory.

**A single mutable knowledge store.** An earlier design called distilled skills, presets, and compositions "versioned plugins" but specified no digest, lineage, or generation identity for any of them, so a refined skill overwrote its prior body in place — a single mutable store under a plugin label, with no earlier generation to revert to and no way for a leaderboard to distinguish generations. This is rejected because lineage, decontamination, and rollback all need a stable identity per generation; every component and skill now carries a content-addressed id (`id@digest`) recorded in a log-only `CompositionManifest` event, and the `dsh-archive` ledger keeps every generation, retired ones included.

**Judges as gates.** An earlier design let a council's verdict decide blocking outcomes directly in places without excluding judge transcripts from training by default, so a judge whose own prior verdicts could later train the model it judges would acquire a stake in its own future scoring. This is rejected because a same-lineage judge grading an outcome that affects it mislabels far more often than a disinterested one; judge sessions now carry a route distinct from the worker and validator lineage, every judge verdict is advisory until a D gate or a human decides, and judge transcripts default to exclusion from every training export.

**Kept open: the artefact-lineage graph view.** An alternative representation draws nodes as durable records (a spec, a completion-standard revision, a certificate, a trajectory line, a dataset manifest, a model release) and edges as the sessions that produced one from another, with agents as edge labels rather than nodes; it makes "follow one artefact" and "diff two runs" native and turns W3 and W4's volumes into a Sankey diagram. It is not adopted here because it needs artefact ids the current schemas do not all carry yet (`SpecDraft`, `Plan`, and `SessionDiagnosis` have no stable identity of their own); it stays a candidate view once those ids exist.

**Kept open: training on validator and judge role sessions.** Training the model on the roles its own pipeline needs — validator sessions that authored a standard matching the curated reference, diagnostician sessions, disinterested judge sessions — would let the model improve at those roles the way a verifier-first pipeline trains on its own generator and checker calls. It is not adopted here because judge transcripts default to exclusion from training so a judge never acquires a stake in its own verdicts; whether validator and diagnostician sessions specifically are safe to include is left to be decided per component lineage rather than fixed by this note.

## Acceptance criteria

### W1

- The `environment/run` stamp and a `verification/run` event exist for every executed check, passing or failing, and a keyless test proves a certificate whose cited run is absent, has a different standard revision, or contains a failing check is rejected.
- `dsh-archive` records every evaluated `HarnessVariant` as `alive`, `dominated`, or `promoted`, never deletes a dominated entry, and a parent sampler draws from it in proportion to quality × novelty × 1/(1+children).
- A proposal from the quarantined Harness Engineer that touches an evaluator-owned path (`packages/improvement/**`, `packages/verification/**`, `scripts/run-gates.ts`, or a snapshot fixture) is a hard reject before any cell runs, proven by a fixture that submits such a patch.
- `@deepseek-ai/dsh-fleet` (`ctx.fleet`) runs a plan of environment × model × repetition cells through `ctx.environmentRuns` in a fresh workspace per cell, keeps a cell that cannot boot as `{ cell, error }` — a row with an error code, never a missing row — and folds a `LeaderboardRow` per model route and environment that never averages across `isolation` or `heldOut`; both stay columns a consumer partitions by. Its unit spec and its Loader-booted e2e (`examples/headless-agent/tests/fixtures/fleet-run`) already cover this.
- A model-visible text change produced by the loop — a mutated prompt section, tool schema, or skill body — cannot reach promotion without a human diff review of the re-recorded snapshot expectations.

### W2

- A keyless snapshot proves the read barrier: an implementer-role tool read under the standard's root is denied by fs policy while the same call from the validator succeeds, and a certificate from a session that composed a log-reading tool is rejected by invariant.
- `ProgramLedger` events map every goal of a program to its session, workspace, preset, isolation, budget, and status, and a Loader-booted example resumes a program from the ledger after a restart.
- A certificate's `treeHash` equals the merged head before a release record is generated; conflict resolution re-runs the checks rather than re-approving the per-goal certificates.
- A `signoff/recorded` event names the principal, the artefact hash, and the evidence in view for spec freeze, security or compliance relaxation, review acceptance, release, and training-data release, and none of these five transitions completes without one.
- The project's own checks enter training only after an `EnvironmentAdmission` record shows the pre-state failing, the reference passing, and a gaming-agent run failing to certify, plus a logged human split assignment.

### W3

- The `environment/run` stamp's content hashes of prompt, fixture, and checks are what a decontamination check keys on, and a fixture proves two runs of the same environment hash identically while a changed check hashes differently.
- A training run is refused if its reward did not originate from a `verification/run` event, and a fixture proves a write under check-owned paths of the pristine-fixture-plus-patch copy yields a tamper verdict with reward zero.
- Truncated, aborted, and errored rollouts are masked rather than scored as failures, proven by a fixture trajectory of each kind carrying no penalty in the training record.
- `EvalReport` pins the harness variant hash it ran under, and an evaluation on an unpinned variant is rejected as not comparable.
- A `ModelLineage` record generates the Article 53 documentation and the accountable officer's `SignoffRecord` before a `ModelRelease` exists.

### W4

- A `CompositionManifest` event names every component in play as `id@digest` at session start and on every preset, skill, or tool-set change, and an invariant rejects a skill result whose digest is absent from the manifest.
- A tier-1 skill candidate carries evidence sessions and a declared scope of session, department, or client, or is rejected by schema; the department scoreboard marks a skill deprecated only after paired present-versus-absent runs show a delta at or below zero over the configured number of runs.
- An `ExperimentPlan`'s proposal digest is logged before any of its cells run, and cells trace to `SessionDiagnosis` evidence plus a stratified sample by a logged deterministic rule, never to an S-set priority.
- The knowledge ledger's `id@digest` entries and the composition manifest's occurrences agree; a ledger entry with no matching manifest occurrence is flagged as never having been in play.
- Persisted artefacts are hash-chained per checkpoint and signed daily manifests reach write-once storage, and a per-client crypto-shredding key exists before any client-scoped erasure request can be honored.

## Rollout

1. **Landed** — the `environment/run` stamp, the `verification/run` event, and the runner that appends both: every executed run of a standard, passing or failing, is durable with its executor and workspace tree hash, a certificate needs a fully passing run of its revision, trajectories carry the attempt count, and `@deepseek-ai/dsh-fleet` (`ctx.fleet`) runs the cells and folds a leaderboard per route and environment. The `EnvironmentStats` fold that W1 stage 2 and W3 stage 2 read is the scorekeeper's pass@k over the stamped batches; keying it by policy version waits for the stamp to carry one.
2. **Blocking** — the read barrier as filesystem and process authority. A validator-root fs-policy plugin, monotonic tool guards, implementer presets without a log-reading tool, and an invariant on certificates; until then every certificate measures only what the implementer could read.
3. **Blocking** — attributable decisions and pinned data-use terms. `signoff/recorded`, `decidedBy` with an argument digest on approvals, `dataUse/terms` at session creation, shipped redaction rules, and a curator that records rule hits; without them no client auditor can verify a gate and no transcript may become training data.
4. **Major** — content-addressed identity: component and skill digests, and the composition manifest event. Lineage, leaderboards per version, quarantine of dynamic packages, and the manifest-versus-ledger invariant all key on `id@digest`.
5. **Landed** — the scorekeeper as a session projection (`@deepseek-ai/dsh-scorekeeper`): the `sessionFacts` unit beside goal and verification, a scoreboard folded from persisted logs and partitioned by route, environment, isolation, and held-out split, pass@k over the stamped batches, and a JSONL facts export. What remains is the archive ledger — `HarnessVariant` records over storage with parents, operators, evaluations, and status — and the field groups whose producers do not exist yet.
6. **Landed** — the budget policy plugin (`@deepseek-ai/dsh-budget-policy`): token, wall-time, and cost caps from config, folded from the session log on `agent/pre-step`, a `budget/breach` event, and a durable goal block no round driver resumes; the model sees nothing because the step never opens. What remains is wiring per-cell caps from the fleet plan.
7. **Landed** — the experiment service (`@deepseek-ai/dsh-experiments`): a plan frozen by a content digest before any cell runs, both arms through the fleet at paired repetition indexes under `experiment-<digest>-<arm>` stamp groups, per-environment and pooled bootstrap intervals seeded from the digest, and a projected token budget refused loud. What remains is the staged ladder, cells derived by rule from diagnosis evidence, presets as a second arm dimension, and per-cell caps enforced during the run rather than projected.
8. **Major** — structured output for top-level presets as a plugin. Attach the structured-output runtime to a preset's agent context; Intake, Program service, and Trajectory Analyst get forced schemas with logged rejection paths.
9. **Major** — trainer operator, model registry, model lineage, environment factory, and admission. W3 end to end, including the Article 53 documentation generated from the lineage record.
10. **Minor** — the deny-capable monitor on the tool guard. Impact classes deny by default, ask for a bounded class, and log `oversight/deny`; makes deployment and secrets human gates.
11. **Minor** — durable orchestration. Deferred: cells are idempotent by header hash × environment × repetition and recover from persisted child sessions; a journaling workflow engine provider arrives with the program ledger.
12. **Minor** — a live run viewer fed by session logs and workflow events. The client's `ui-workflow-run` renders run, phase, and member status only today; a model's-eye view at any seq is the view no competitor can prove complete.

## Risks

- **Oracle capture.** A patch author re-recording its own snapshot expectations turns a deterministic gate into a rubber stamp; only a human diff review of the recording route defends against it, and it is not automatic anywhere in these workflows.
- **Cheap reward under weak isolation.** Under `isolation: none`, checks run with the implementer's privileges in the implementer's own workspace, so a certificate there is not evidence a client or a trainer should treat as strong; leaderboards and training exports must partition by isolation, never blend it.
- **Survivorship in the fold.** A session that is skipped, torn by a restart, or interrupted mid-fan-out must still leave a scoreboard row carrying an error code; silently dropping it inflates every certificate rate computed from the remaining rows.
- **Data protection before export.** Redaction, consent, and residency events must exist and be enforced before any client transcript reaches an export; an export that runs ahead of the curator plugin and the pinned data-use terms is a confidentiality and residency incident, not a near-miss.
- **Judge and reviewer stake.** A judge or reviewer whose own verdicts could later train the model it grades, or whose approval volume is high enough to induce fatigue, degrades toward rubber-stamping; judge transcripts default to exclusion from training, and every human gate stays a named, attributed decision rather than an anonymous one.
- **Harness and model co-evolution.** Evaluating a model checkpoint on a harness that evolved against that same checkpoint's predecessor measures the pair, not either alone; `EvalReport` pins the harness variant hash for exactly this reason.
- **Orchestration loss.** Hours-long fan-outs run in-process today with no durable resume; without idempotent cells keyed by header hash × environment × repetition, a restart during a long fleet run or a long program double-counts or silently drops work.
- **Cost.** Role separation and staged evaluation spend more than a self-judging pipeline; per-goal and per-cell budgets from config, not code constants, are what keeps that cost bounded and visible.
