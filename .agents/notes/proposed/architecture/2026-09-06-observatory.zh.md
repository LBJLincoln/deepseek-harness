# Agent Note: The observatory, the page that publishes only what the logs prove

Status: proposed

[English](2026-09-06-observatory.md) | 中文

## Problem

[Village note](2026-09-05-daliesk-village.md) 已经确定了一个公开排行榜可以说什么——先有行再有排名、`% resolved` 与 `parity` 各以自己的名字出现、一个篡改列、一个 executor、组合摘要或 `pending`、成本只与其价格表摘要同时出现、Workshop 与留出会话被扣留——而[竞品基线 note](2026-09-06-competitive-baselines.md) 补上了让常驻声明可证伪的那一条性质：一个要么当前、要么显眼陈旧的页面。这些都还没有任何东西渲染。scorekeeper 已经能从持久化日志折叠出 `ScoreboardRow`，但两个诚实列没有字段可读：决定篡改列的最后一次运行的裁决，以及决定一行是否可被归因的、所运行 preset 的组合摘要。今天想要一个页面的消费者，只能在 scoreboard 之外从原始事件重算这两者，而这恰恰是发布规则要防止的、同一个数字的第二个产出方。

## Proposal

两处改动。scorekeeper 补上诚实列所需的两个事实，并在行上给出它们的聚合。一个新包 `@deepseek-ai/dsh-observatory`（`ctx.observatory`）在全部持久化会话上折叠出一个快照，扣留部署所配置的内容，并由它渲染出一个自包含的 HTML 页面与一份 JSON 文档。

### The two missing facts

`SessionFactsOutcome.tamper` 是最后一次记录运行的裁决——`passed`、`failed` 或 `tampered`——当日志根本没有记录任何运行时为 `not-instrumented`，而这正是 scoreboard 已经计入 `errors` 的同一批会话。裁决是运行载荷的字段；除 `tampered` 外的每个裁决都能由结果推出，因此一个仅从结果推导的折叠会把一次被篡改的运行悄悄按失败发布。

`SessionFactsIdentity.compositionSha256` 是会话中最后一个 `composition/manifest` 的 `compositionSha256`，日志中没有时缺席。它属于溯源而不属于结果：它命名了 agent 当时在用的组件集合，正是它让一行可以归因到某个 harness 变体，而不是归因到一条路由与"那一周的 harness 恰好是什么"这对组合。

`ScoreboardRow` 聚合这两者，再加上页面必须显示的 executor：

- `tampered` —— 该行中最后一次记录运行带 `tampered` 裁决的会话数。页面不需要第二个计数：一行的 `errors` 恰好就是它的未插桩会话，因为没有运行的会话没有裁决。
- `compositionSha256` —— 仅当该行的每个会话都陈述同一个摘要时出现，任一会话没有陈述或两者不一致时缺席。一个只覆盖一行中一部分的摘要，比没有摘要更糟。
- `certificateExecutors` —— 该行已认证会话的去重 executor，按首次出现顺序排列，与 `pricingDigests` 已经是的聚合完全相同。空表示该行没有认证任何东西，一个条目就是该行的 executor，两个则表示该行的证书彼此不一致，任何单一 executor 都不得印在其比率旁边。

### The snapshot

`ctx.observatory.snapshot()` 列出全部持久化会话头，通过 `ctx.scorekeeper.leaderboard()` 恰好在这些会话上折叠 scoreboard，然后对行做划分。扣留是一次行操作，因为它本来就是一次会话操作：scoreboard 的键携带 `district` 与 `heldOut`，因此被扣留行中的每个会话都被扣留，任何被扣留的会话都不可能进入公开行。快照对丢弃的内容计数——按原因分别计行与会话，区先于留出划分——而不是把它藏起来，因为一行的缺失会抬高由其余行算出的每一个比率。

`foldedAt` 是折叠运行的时刻。`newestSessionAt` 是折叠所读取的会话头中最新的 `createdAt`，当存储中没有会话时缺席；它是陈旧规则读取的值，也是页面打印的值。`refreshIntervalMs` 随快照一同传递，使渲染出的页面命名的是它被产出时的节奏，而不是碰巧渲染它的那个进程的节奏。

### The rendering

`render(snapshot, now)` 是纯函数，返回同一次发布的两个面。当 `now - newestSessionAt > staleAfterMs`，或者根本没有折叠到任何会话时，页面以陈旧提示取代全部数字，JSON 带 `stale: true` 且没有行、没有排名。否则页面是一张表，每个公开 scoreboard 行一行：路由、环境、区、隔离级别、证书 executor、组合摘要或 `pending`、留出标志、篡改状态、`resolved`、`parity`，以及每个已认证会话的成本。`resolved` 是以自己的名字出现的证书率，`parity` 是以自己的名字出现的加权通过率，两列绝不合并、绝不跨列排名，也绝不把其中一个渲染成另一个。

成本只与为它定价的摘要一同发布，且只在该行恰好携带一个摘要时发布。这是固定的，不可配置：一个在两张价格表下定价的行陈述的是跨价格表的求和，而一个可以关掉这条规则的部署会把这个求和当作价格发布。两种状态下，页面都会命名它的刷新间隔与折叠时刻。

排名区块为快照携带的每个实验结果渲染一个条目：计划摘要、两条臂路由、裁决，以及配对的 delta。不携带任何结果的快照渲染的是"没有配对实验就不发布排名"这句话，而这正是本分支上每个部署的状态，因为没有任何会话事件携带 `ExperimentResult`——实验服务把结果写入 sink，并把它的臂盖章进运行的 `group`。跑过实验的调用方把结果交给 `snapshot({ experiments })`，快照只保留两条臂路由都出现在公开行中的那些结果，因此关于页面扣留或从未折叠的路由的裁决不会发布任何排名。

### Why not a projection

`ProjectionDefinition` 以单个会话为键，由该会话已提交的事件驱动；`SessionProjectionCache` 每个会话存一条检查点记录。观测台跨全部持久化会话折叠，没有可挂靠的会话，因此两条 seam 都不适用，被缓存的折叠是一个返回快照的服务。Village rollout 第 7 项有两半：本页面，它注明自己的批量刷新间隔；以及实时投影，它在跨会话折叠有了自己的归属之前保持提议状态——那需要一个存储级水位与一条持久快照记录，而不是一个按会话的投影单元。

## Alternatives considered

**由观测台自己从 `SessionFacts` 记录折叠行。** 观测台会通过 `ctx.scorekeeper.facts()` 读取每个会话，在记录层面扣留，再调用导出的 `foldScoreboard`。已拒绝：`foldScoreboard` 需要 pass@k 抽取数，而那是 scorekeeper 已配置的可调项，于是观测台要么重复该配置，要么把部署已经陈述过一次的值写死。行层面的扣留给出同一个划分，因为行键本来就携带被扣留的两个维度。

**把篡改裁决作为四个计数放到行上。** 每个裁决一个计数读起来不错，直到发现 `passed` 与 `failed` 其实就是 `certified` 及其补集，而 `not-instrumented` 就是 `errors`。已拒绝，因为那是对行已携带的列的三次复述；`tampered` 是行唯一无法推出的计数。

**发布跨两个价格表摘要的行成本并同时列出两个摘要。** 已拒绝：列出两个摘要并不能让求和有意义，而比较两个在不同价格表下定价的行的读者，比较的是价格表。一个说不出单一价格的行，不说价格。

**让部署配置成本规则。** 已按"插件中不得写死可调项"规则自身的例外拒绝：这是一条发布不变式，不是随部署而变的选择，而唯一会关掉它的部署，是想要这个数字胜过想要这个数字有意义的部署。

**从最后一次运行的结果推导篡改列。** 已拒绝：`passed` 与 `failed` 能由结果推出，`tampered` 不能，因此推导出的列会把一次被篡改的运行报成失败，而篡改门禁会表现得像已经运行过一样。

**用臂的 group 把实验结果与日志匹配。** 比按路由匹配更强，被拒绝仅仅因为 `ScoreboardRow` 不携带 group：`EnvironmentStats.groups` 是一个计数。为一个页面的一个区块而把 group 名加到每一行上，比这个区块本身的价值更多；按路由匹配已经能拒绝关于页面不发布的路由的裁决。

**每条路由渲染一个混合分数。** 已在 [Village note](2026-09-05-daliesk-village.md) 中拒绝，此处再次拒绝：混合所隐藏的列，正是决定一行是否有意义的那些列。

## Acceptance criteria

- 一个单元测试证明一个 Workshop 区会话与一个留出会话绝不出现在公开行中，并被计入 `withheld`，其会话数与行数都被计数。
- 一个单元测试证明陈旧开关恰好在阈值处切换：`now - newestSessionAt === staleAfterMs` 仍渲染数字，再晚一毫秒则以提示取代全部数字，且 JSON 带 `stale: true` 与零行。
- 一个单元测试证明携带两个价格表摘要的行不发布成本，而恰好携带一个的行把成本与该摘要一同发布。
- 一个单元测试证明会话都没有陈述组合摘要的行渲染 `pending`，会话之间不一致的行同样渲染 `pending`。
- 一个单元测试证明 `resolved` 与 `parity` 是两列且其值绝不合并，且没有 parity 的行渲染"无"而不是它的证书率。
- 一个单元测试证明不带实验结果的快照渲染那句"不发布排名"，而携带一个针对两条已发布路由的裁决的快照渲染该裁决。
- 一个由 Loader 启动的 e2e 通过真实的 `cordis.yml` 在 `workshop` 区运行一个 fleet 计划、在区外运行另一个，取快照、渲染，并断言 workshop 的行不在公开行中而出现在计数里。
- 一个无密钥快照钉住渲染出的 HTML 与 JSON 文档，时间戳被归一化。
- 在两个新事实与三个新行字段之后，scorekeeper 的逐文件覆盖率仍为 100%。

## Risks

- **一个诚实但读不下去的页面。** 排名之前的十一列是发布规则的要求，也是读者不会扫读的东西。缓解手段是排版而不是删减：等宽数字、固定列序，以及没有任何一列可以在不丢掉一条规则的前提下被去掉。
- **没人注意到陈旧的陈旧页面。** 陈旧提示取代数字而不是并排放在数字旁边，正因为一张数字表格上方的横幅会被当成装饰。剩余风险是部署把 `staleAfterMs` 配得比自己的节奏还长，这是任何门禁都抓不到的。
- **被扣留的计数本身就是一次披露。** 被扣留的 Workshop 行数本身就是关于一次客户合作的事实。无法发布该计数的部署就不发布页面；把计数拆出去会变成第二条发布规则和第二种出错方式。
- **按路由而不是按 group 配对的裁决。** 同一对路由在不同计划下的两个实验都会匹配到同一批公开行，因此把同一对路由的多个结果交给快照的调用方会发布多个排名。每个排名上的计划摘要是让它们仍可区分的东西；想要一个排名的调用方就交一个。
- **实时投影仍处于提议状态。** 在它落地之前，页面只与折叠它的进程一样当前，而它命名的刷新间隔是一项关于该进程的声明，页面自身无法核验。
