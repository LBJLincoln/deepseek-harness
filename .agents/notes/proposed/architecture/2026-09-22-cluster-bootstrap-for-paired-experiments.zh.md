# Agent Note: A cluster bootstrap for paired experiments

Status: proposed

[English](2026-09-22-cluster-bootstrap-for-paired-experiments.md) | 中文

## Problem

[实验服务](../../../../packages/improvement/experiments/README.md)报告配对证书率 delta 的总体区间时，只在每个环境内部对配对 delta 做重采样，从不对环境本身重采样。在两次重复下，一个两条配对 delta 相同的环境不给这个区间贡献任何方差。当一个环境在两次重复上都翻转、而两个 arm（实验分支）在其余每个环境上结果一致时，每一次重采样都复现出观测到的 delta，区间没有宽度，无论它所依据的证据有多少。

2026-09-21 的 E7 配对正是这种情况。[`2026-09-21-bench-e7-attempts-5-t5`](../../../../data/proving-ground/2026-09-21-bench-e7-attempts-5-t5/result.json) 在三次尝试的 baseline 上认证了 16 个 cell 中的 12 个，在五次尝试的 candidate 上认证了 16 个中的 14 个：`code:conf-canon` 在 baseline 的两次重复上都失败，在 candidate 的两次重复上都通过认证，而两个 arm 在其余七个环境的两次重复上结果都一致。结果陈述的 delta 为 +0.125，区间为 [0.125, 0.125]，判定为 `promote`，bench 循环的固定规则则在[循环台账](../../../../data/proving-ground/loop/ledger.jsonl)第 7 行写下了 `adopt-candidate`。同一计划更早的两次 E7 配对读数为 +0.0625（16 个中 14 对 15）与 −0.0625（15 对 14），三次合并读数为 48 个中 41 对 43，即 +0.042，低于计划的 `minimumDelta` 0.05。三次尝试的 baseline arm 在这三次配对中分别认证了 16 个中的 14、15 与 12 个，同一路由在三次尝试下，还在台账第 5 行与第 8 行的两次 tier 5 baseline fleet 中认证了 16 个中的 14 与 13 个，因此同一配置的运行间波动跨越三次翻转，而不是一次。

只在环境内部重采样的区间，回答的问题也比判定所问的更窄。bench 抽取的是任务，一次晋升声称 candidate 在这一类任务上更好；一个只存在于八个环境之一的效应，恰恰是环境抽取所携带的不确定性，而环境内部的重采样看不到它。

## Proposal

**总体区间是一个两阶段整群 bootstrap（自助重采样）。** 每次重采样先有放回地抽取持有配对 delta 的环境，抽取的个数与这类环境的个数相同；再在每个被抽中的环境内部，有放回地抽取与它所持有数量相同的配对 delta。这次重采样的统计量是抽出 delta 之和除以其个数，与点估计所用的比值相同，因此一个环境按其配对数量加权，没有配对的环境不作任何贡献。区间是这些重采样统计量在所配置置信水平下的百分位区间。每个环境自己的区间仍然只重采样它自身的配对 delta，所用的生成器与抽取顺序都与之前相同，因此每一个已记录的逐环境区间都原样重放。

**抽取保持确定性。** 总体这一趟的抽取来自一个 mulberry32 生成器，其种子只取计划摘要的 32 位 FNV-1a 哈希，环境按其 id 的码元顺序参与抽取，因此区间与计划列出环境的顺序无关；每个环境自己的那一趟仍使用以 `<digest>:<environmentId>` 为种子的生成器。同一份被冻结的计划在同样的证书之上，在任何进程中都重放出同样的区间。

**结果指名它的统计方法。** 折叠写出的每一份结果中，`ExperimentResult.statistic` 都是 `paired-cluster-bootstrap/1`。没有指名统计方法的已存储结果是由 `paired-bootstrap/0`（即环境内部的方法）读出的，`readStatistic` 按这种方式读取它，并拒绝本包未定义的名字。统计方法不进入摘要：摘要冻结的是计划，并为抽取提供种子，而一次重读是同一份被冻结的计划换一种统计方法。`bench loop` 的台账行以新增字段的形式携带它所读记录的 `statistic`；循环的固定决定规则不变，仪表盘的 Loop 小节在区间旁边显示统计方法，并把该字段出现之前写出的行读作 `paired-bootstrap/0`。

**判定需要最少数量的不一致配对。** 只有两个 arm 在证书上结果不一致的配对重复会移动 delta。`minimumDiscordantPairs` 是一个经过校验的 `Config` 字段，取非负整数，默认值为 2，它被冻结进阈值与计划摘要，因此计划格式从 7 升到 8。不一致配对（discordant pair）少于这个最小值时，无论区间如何，判定都是 `inconclusive`，因为一次证书翻转就会抹掉只依据一处不一致的 delta。结果陈述 `discordantPairs` 与 `verdictBasis`（取值为 `interval`、`no-pairs` 或 `too-few-discordant-pairs`），因此一份已存储的结果会说明它为何是 `inconclusive`。`0` 为有意让持平也晋升的部署关闭这个最小值，例如以负的 `minimumDelta` 做非劣效读数的部署。

**已记录的配对在离线重读，从不改写。** 一份记录的 `result.json` 陈述的是逐环境的比率，而不是哪几次重复通过了认证；当两个 arm 各认证一次时，比率无法区分 `{0, 0}` 与 `{+1, −1}`。因此 [`reread-driver.ts`](../../../../examples/headless-agent/tests/fixtures/proving-ground-bench/reread-driver.ts) 从记录的 `facts.jsonl` 中按 stamp group、环境与重复重建每一次重复的配对结果，并且只有当重建复现出每一个已记录的 cell 时才接受它：该 cell 的配对数、两个 arm 的证书数，以及在记录自身摘要下重新抽取的区间。它在一份记录自身的摘要下读取该记录；对同一计划、同一组 arm 的多份记录，则按环境合并，在由记录名与摘要派生的摘要下读取；读数作为一份折叠写到 `data/proving-ground/folds/` 下，从不覆盖已有文件。每一份 E7 记录都通过了重建检查。

重读之后，2026-09-21 的配对为 `inconclusive`：大约三分之一的整群重采样漏掉了 `code:conf-canon`，这使下界落在零；它的两处不一致配对达到了默认最小值，因此只由区间作出决定。与更早的两次配对合并后，delta 低于计划的最小值，区间包含零。2026-09-19 的第一次配对冻结于计划格式 6 之下，那时 preset 字段尚未进入摘要，因此它的摘要与另外两次不同，而它的 arm、环境、上限与阈值完全相同。

### 2026-09-21 的 `adopt-candidate`

台账第 7 行的 `adopt-candidate` 是 `paired-bootstrap/0` 的产物：在整群 bootstrap 下读取同样的证书，结果为 `inconclusive`，该计划的合并读数也是如此。这行台账保持写出时的原样，因为台账只追加、由机器写出；它的读数没有指名统计方法，读作 `paired-bootstrap/0`。更正后的读数写进[改进日志](../../../../data/proving-ground/improvement-log.md)（其各行由人手写），而不是写进台账。`adopt-candidate` 是一个决定，而不是一次改动，因此没有任何组合采用过五次尝试的 arm，也就没有什么需要回退。

### 预期发生变化的测试

服务测试中，曾对一个只依据一次配对重复的比较给出晋升的用例，现在预期带 `too-few-discordant-pairs` 的 `inconclusive`，因为一处不一致正是这个最小值要为之扣下判定的那种证据；同一个用例也表明，`minimumDiscordantPairs: 1` 会恢复这次晋升。统计测试不再断言单个环境的区间等于总体区间：两趟抽取来自不同的生成器，因此二者只在分布上一致，而不是逐次抽取一致；该测试改为固定总体这一趟只以摘要为种子。两个 arm 相同的比较、默认值与端到端测试都改为陈述五个阈值，experiment-presets 快照记录了新的摘要与字段。循环测试中，为 2026-09-19 的一个计划解析下一个记录名的用例读取的是实时的记录目录，而当天循环的第二份 E7 记录已经占用了它预期的名字，因此它改为针对一个记录不再变化的过往循环之夜进行解析。

## Alternatives considered

**保留环境内部的 bootstrap，并调高 `minimumDelta`。** 零宽度的区间能越过任何低于其点值的最小值，因此调高最小值只是移动了这个人为结果需要越过的门槛；它还会挡住一个稀薄地分布在许多环境上的真实效应。缺陷在于宽度，而不在于门槛。

**每个环境运行更多次重复。** 一个各次重复结果一致的环境，在任何重复次数下都不贡献宽度，而判定所概括的对象是环境；能诚实地收窄区间的是更多的环境，而不是同一批环境的更多次重复。

**对不一致配对做精确检验。** 针对配对二值结果的 McNemar 精确检验只使用不一致配对；当两处不一致配对方向相同时，它的双侧 p 值为 0.5，因此它同样会扣下这次晋升。它没有被选作统计方法，因为判定规则把一个效应量与 `minimumDelta` 相比较，而 p 值给不出效应量；不一致配对的最小值保留了它的洞见：结果一致的配对不携带任何关于差异的信息。

**为每个环境设先验的分层模型。** 贝塔-二项模型在小计数下校准得更好，但它需要先验，而先验会成为与阈值并列的部署可调参数；它还需要一个采样器依赖，或者一种近似，而近似的抽取不再是判定据以重放的、以摘要为种子的重采样。整群 bootstrap 用本包已有的生成器与重放义务修复了这个缺陷。

**只对环境重采样。** 单阶段的整群 bootstrap 把每个环境的观测均值当作固定值，这丢掉了环境内部的重复噪声，例如配对 delta 为 `{−1, +1}` 的 `code:sheet-eval`。第二阶段保留了这两种来源的波动。

**只从 `result.json` 重建配对。** 已记录的比率确定了每个 arm 在每个环境上的证书数，却确定不了哪几次重复通过了认证，因此一个两个 arm 各认证一次的 cell，既可能是两处一致配对，也可能是两处方向相反的不一致配对；`facts.jsonl` 持有每个会话的重复序号与证书，已记录的逐环境区间则用来验证重建。

**把统计方法纳入摘要。** 把统计方法冻结进摘要，会为每一个统计方法版本铸出一个新的实验身份，并给一次对已记录配对的重读一个其会话都不携带的摘要。结果改为指名自己的统计方法；不一致配对的最小值则进入摘要，因为它决定什么可以晋升。

**就地更正记录或台账。** 记录与台账行是改进日志所读的历史，改写其中任何一处都会让先前的每一个读数无法重放。一次重读是记录旁边的一份新折叠。

## Acceptance criteria

- `foldExperiment` 写出的每一份结果都携带 `statistic: 'paired-cluster-bootstrap/1'`、`discordantPairs` 与 `verdictBasis`，其阈值携带 `minimumDiscordantPairs`；schema 拒绝小数或负值并把默认值设为 2，计划摘要在计划格式 8 下冻结它。
- 一个环境在两次重复上都翻转、其余环境结果一致时，读数是下界为零、宽度为正的区间与 `inconclusive`；不一致配对少于最小值时，即使只看区间会晋升，读数也是带 `too-few-discordant-pairs` 的 `inconclusive`；单元测试固定了这两点，并且整群抽取在同一个摘要下、以任何分层顺序都精确重放。
- `readStatistic` 把没有该字段的结果读作 `paired-bootstrap/0`，并拒绝未知的名字；`bench loop` 的台账行携带 `statistic`，而 `decideIteration` 不变。
- 上面两份折叠存在，并且没有任何记录或台账行被改动。

## Risks

**八个环境是很少的整群。** 在寥寥几个环境之上，整群 bootstrap 的重采样分布很粗，而在少量整群上的百分位区间仍然覆盖不足，因此名义上 95% 的区间比之前更宽，但并不恰好是 95%。`minimumDelta` 与 `minimumDiscordantPairs` 仍然是防线。

**判定会变化。** 在 `paired-bootstrap/0` 下晋升的比较，在整群 bootstrap 下可能读作 `inconclusive`，2026-09-21 的配对正是如此；已存储结果的读者在把它与更新的结果比较之前，先检查 `statistic`。

**每个摘要都会改变。** 计划格式 8 把每一份计划冻结到一个新的摘要，因此在格式 7 下冻结计划的调用方会被以 `EXPERIMENT_PLAN_NOT_FROZEN` 拒绝，它的 arm 也会在新的 stamp group 下运行。

**重建信任 facts 导出。** 一份没有 `facts.jsonl` 的记录，或其 facts 与 cell 不一致的记录，无法被重读；驱动器宁可拒绝，也不去猜测。

**合并读数跨越多个 head。** 三次 E7 配对运行在三个仓库 head 上；合并它们的前提是这些 head 之间的 harness 改动没有改变两个 arm 的行为，完全相同的 arm、上限与阈值支持这一前提，但不能证明它。

**默认最小值是一个经验取值。** 两处不一致配对是一次证书翻转无法单独抹掉 delta 的最小数量；运行更多次重复的部署可以调高它。
