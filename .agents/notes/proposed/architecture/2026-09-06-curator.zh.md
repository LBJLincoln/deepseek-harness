# Agent Note: curator——强制脱敏与按条款把守的导出

Status: proposed

[English](2026-09-06-curator.md) | 中文

## Problem

[Village 笔记](2026-09-05-daliesk-village.md)对离开实验室的数据给出两项治理承诺：导出器在没有脱敏配置时拒绝运行；AI Village 数据集——与每一份客户转录一样——只在限定了用途的条款下进入。[四目标笔记](2026-09-05-four-goal-workflows.md)把 Data Curator 花名册行挂在同样这两件事上，把 `ExportManifest` 命名为一次导出必须留下的东西，并把"随包发布的脱敏规则与一个记录规则命中的 curator"放进它的阻塞性推进项；其 W3 阶段 3 行直白地写出了丢弃规则——consent 范围未知的样本会被丢弃，绝不假设。

这两项承诺都没有产出方。[`dsh-trajectories`](../../../../packages/improvement/trajectories/README.md) 直接从折叠写出 `dsh-trajectory/1` 行：它按 `environment/run` stamp 扣留留出会话与区会话并对每一条被扣留者计数，却不做任何脱敏、不读取 `dataUse/terms`、也不留下 manifest，因此它自己的 README 把"无脱敏"列为限制并指向遥测规则作为先例。[`dsh-data-use`](../../../../packages/governance/data-use/README.md) 在会话创建时钉定条款，其 README 直言没有任何东西执行它们；[可归属决定笔记](2026-09-06-attributable-decisions.md)把这项执行推迟给它的推进项 2。与此同时，[竞品基线笔记](2026-09-06-competitive-baselines.md)记录了 Village 数据集的研究许可证在没有书面许可时禁止训练，并断定在扣留可被证明之前没有任何流水线可以摄入它。今天，一次 `ctx.trajectories.export()` 调用就会把一份客户转录、其中的凭据与其仅供评估的样本写进同一个训练文件，而仓库里没有任何东西说这是错的。

## Proposal

一个插件，`packages/governance/` 组中的 `@deepseek-ai/dsh-curator`（`ctx.curator`），包裹导出器而非取代它。它是唯一做脱敏的导出路径、唯一读取被钉定条款的路径、也是唯一留下 manifest 的路径；trajectory 导出器仍是它本来就是的、未经脱敏的原语。

### 脱敏配置，按设计必填

`Config.profiles` 是从配置 id 到 `{ shipped, rules }` 的非空映射。一条规则是 `{ id, pattern, flags?, replacement }`，其中 `pattern` 是 JavaScript 正则表达式源串。每条规则在加载时被编译：无法编译的模式、空 id、同一配置内重复的 id、未知的 `defaultProfile`、没有任何有效规则的配置，以及粘连的 `y` 标志，都是指名配置与规则的加载失败。`shipped: true` 会在前面加上本包拥有的规则集——电子邮件地址、长度不少于二十字符的 `Bearer` 令牌、`sk-` 形式的 API 密钥、点分四段 IPv4 地址，以及 E.164 电话号码——每条都带一个证明命中的 fixture 与一个证明不命中的 fixture，因为没有人看过其失败的规则，就是没有人知道其形状的规则。

`requireProfile: true` 由设计固定，不是 `Config` 字段。不存在任何能绕过脱敏进行导出的配置：当请求没有指名配置且没有配置 `defaultProfile` 时，`export()` 以 `CURATOR_PROFILE_REQUIRED` 拒绝；当它指名了部署方未配置的配置时，以 `CURATOR_PROFILE_UNKNOWN` 拒绝。规则形状取自遥测脱敏这一先例——一个模式与一个替换串，作用于字符串——但机制并不取自它：遥测脱敏是部署方可以不挂载的 waterfall，而这里是导出无法绕过的、经过校验的规则表。

替换通过替换函数施加，因此配置的替换串里的 `$&` 或 `$1` 会被逐字写出，绝不可能把被匹配的文本重新拼回记录。每条规则无论部署方是否写了全局标志都以全局标志编译，因为一条只替换首个命中、留下其余的规则，会报出低估其所留下之物的命中计数。

### 什么会被脱敏，什么永远不会

curator 遍历每条 `dsh-trajectory/1` 记录，对触及的每个字符串做脱敏，只有三类被明确枚举的例外。因此脱敏是安全失败的：记录类型上新增的字段在有人另作决定之前一直被脱敏，而不是在有人注意到之前一直被原样导出。

例外是记录的标识符与其读者的判别式。四棵子树永不脱敏——`environment`（`environment/run` stamp：环境与分组 id、内容摘要、重复次序、区、路由名、isolation）、`steps` 与 `parity`（数字），以及 `provenance`（组件 id、工具名、isolation）。二十个键名在任何深度都不脱敏：`type`、`id`、`format`、`sessionId`、`parentSession`、`agentPreset`、`role`、`sourceKind`、`toolCallId`、`basis`、`phase`、`goalId`、`checkId`、`status`、`isolation`、`executor`、`provider`、`model`、`reasoningEffort`、`attachmentId` 与 `mediaType`；改写其中任何一个都会破坏消费方据以分支的记录，而不会保护记录里的任何东西。三条路径让已注册的工具名保持可读：`tools[].name`、`messages[].content[].name` 与 `messages[].toolCalls[].name`。

其余一切都被脱敏，这正是四目标笔记的字段清单所要求的：渲染后的系统提示（`system`）、每个工具 schema 的 `description` 与参数文本（`tools`）、每条消息的内容块（`messages[].content[]`，并递归穿过 tool-result 的内容，因此文本、推理与嵌套结果都被覆盖）、模型产出的原始参数串（`messages[].content[].arguments` 与 `messages[].toolCalls[].arguments`）、工作目录（`source.cwd`）、目标陈述（`reward.goal.objective`），以及证书里逐检查项的运行证据（`reward.certificate.results[].evidence`）。指令以 `reward.directives` 这个计数进入记录，而非文本；记录里没有可脱敏的指令散文，本笔记如实写明这一点，而不暗示一次并不发生的脱敏。

### 条款闸门

`export({ purpose, ... })` 陈述本次导出服务于哪个 `DataUsePurpose`。在写出任何东西之前，curator 读取每个候选会话的日志，并用 `termsOf(events)` 折叠其条款。最新的 `dataUse/terms` 未列出本次导出用途的会话会被扣留并计入 `withheldByTerms`；完全不携带条款的会话按同一条规则被扣留，这正是四目标笔记的丢弃规则变得可执行——没有条款就没有导出，尤其是没有条款就没有训练导出。被扣留的会话从不交给导出器，因此拒绝发生在做出该决定的操作之内，而不是发生在对已写出行的过滤中。

curator 注入 `trajectories`、`sessionPersistence` 与 `dataUse`。它通过纯折叠 `termsOf(events)` 而非服务读取逐会话的条款，因为 `DataUseService` 没有为持久化会话的事件暴露读取方法——`pin` 与 `defaultTerms` 说的都是活着的 agent。该注入依然是必需的：一个既做策展导出又不钉定条款的组合会扣留它持有的每一个会话，而要求该服务把这种误配置变成加载失败，而不是一个空的导出文件。

同一份条款中的 `residency` 会被复制到每条被导出记录的 `curation` 块上，于是一个 sink 无需再次读取会话日志就能按区域分区。

### curation 块与 manifest

每条被导出的记录获得一个 `curation` 块：`redactionApplied: true`、`redaction: { profile, profileSha256, hits }`（其中 `hits` 按规则 id 统计本条记录的替换次数），以及 `residency`。四目标笔记把它们勾勒为 `redaction_applied`、`redaction_profile_version`、`redaction_rule_hits` 与 `residency_region`；它们以 camelCase 出现在一条 camelCase 记录里，正如 [`dsh-scorekeeper`](../../../../packages/improvement/scorekeeper/README.md) 已经以 camelCase 交付该笔记的 snake_case 字段组。

每次导出写出一份 `ExportManifest`：`version`、`exportedAt`、`purpose`、`profile`、`profileSha256`、`records`、`withheld: { heldOut, districts, terms }`、在整次导出上求和的 `ruleHits`、对写出行按顺序取的 `recordsSha256`，以及 `trajectoryFormat`。`profileSha256` 按顺序摘要该配置的有效规则，于是 manifest 陈述的是哪些规则运行过，而不只是它们被归在哪个名字下；`recordsSha256` 是 sink 所收到字节的摘要，于是任何同时持有文件与 manifest 的人都能互相核对。

导出不是一个会话，因此 manifest 是文件而不是会话事件：其中没有任何东西属于某一个会话的日志，它在最后一行之后写出而不是在某个 turn 期间写出，而一个 `curation/export` 事件将不得不挑一个任意的会话来安放。manifest 是持久产物；返回的报告为同进程内的调用方携带同样的计数以及跳过项。

## Alternatives considered

**在 trajectory 导出器上做一个脱敏 waterfall，如同 `session-telemetry/record`。** 否决：没有挂载任何监听器的 waterfall 会原样放行记录，而这恰恰是本笔记要防止的失败。这里的脱敏必须是运行的前置条件，而不是部署方可以忘记的钩子；遥测 seam 的规则形状值得复用，它的可选性不值得。

**重新实现折叠而不包裹导出器。** curator 本可以自己调用 `foldTrajectory` 并完全跳过导出器。否决：留出与区扣留、跳过记账与 sink 关闭都属于导出器，会被重复实现；而 manifest 的 `withheld` 三元组恰好是导出器自身的报告加上 curator 自己的条款计数。

**对已知文本字段做黑名单脱敏。** 作为错误的默认值而否决：`Trajectory` 上新增的字段会在有人想起它之前一直未经脱敏地导出。标识符与判别式的白名单写一次更长，但在记录类型每次生长时都是安全的。

**施加各会话条款所指名的配置而非本次导出的配置。** 本切片否决：一份 manifest 陈述一个配置，逐会话的配置会让 `profileSha256` 变得无法解读。持有多个客户转录的部署方按配置分别导出一次，而条款里的 `redactionProfile` 指名的正是哪一个配置。

**从 sink 推导 manifest 路径。** 否决：`TrajectorySink` 是一对没有路径的 `write`/`close`，猜测路径就是包边界规则所禁止的隐式默认。请求陈述 `manifestPath`，而无论是否给出该字段，manifest 都在报告中返回。

**在 manifest 之外再加一个 `curation/export` 会话事件。** 否决：一次导出跨越许多会话且不属于其中任何一个，因此该事件将不得不写进任意一个会话或全部会话，两者都不诚实地陈述该事实。

## Acceptance criteria

- 带有无法编译的模式、空的或重复的规则 id、粘连标志、没有任何有效规则，或未知 `defaultProfile` 的配置，在加载时以指名配置与规则的方式失败；每种拒绝都由一个 fixture 证明。
- 每条随包发布的规则都有一个证明命中的 fixture 与一个证明不命中的 fixture，且包含 `$&` 的配置替换串被逐字写出。
- 没有配置的 `export()` 以 `CURATOR_PROFILE_REQUIRED` 拒绝，并且不写出任何东西。
- 一次 `training` 导出扣留条款中不含 `training` 的每一个会话，以及完全没有条款的会话，两者都计入 `withheldByTerms`；同一存储的一次 `evaluation` 导出接纳条款中列出 `evaluation` 的会话。
- 每条被导出的记录携带 `curation.redactionApplied`、配置及其摘要、逐记录的命中计数，以及其条款所指名的 residency；在规则会匹配到它们的配置下，每个永不脱敏的字段都存活下来。
- `recordsSha256` 是 sink 字节按顺序的摘要，且对同样的记录保持稳定；manifest 的 `withheld` 三元组分别记账留出、区与条款扣留。
- 一个由 Loader 启动的 e2e 组合了环境注册、runner、预算策略、持久化、检查点策略、trajectory 导出器、接纳 `delivery` 与 `evaluation` 的数据使用条款，以及带随包规则的 curator；被脚本化的转录携带一个假地址与一个假的 `sk-` 密钥，`training` 导出不写出任何行，`evaluation` 导出写出该记录并计入两条规则命中且两个串都不出现，manifest 的 `recordsSha256` 与磁盘上的文件相符。

## Rollout

1. 本切片：curator、随包发布的规则、条款闸门、curation 块与 manifest。
2. Village 笔记推进项 5 仍需要的信任档案导出，它是同一份 manifest 的第二个消费方。
3. `DatasetManifest`：四目标笔记里带去重、对留出套件去污染，以及对内容哈希取 merkle 根的策展集合；逐记录的 `contentHash`、`dedupeClusterId`、`decontaminationStatus` 与 `split` 字段挂在它上面，而不在本切片。
4. 按组合拒绝未经脱敏的导出：一条村庄规则，拒绝组合了 trajectory 导出器却没有 curator 的区，等到出现需要它的区组合时落地。

## Risks

- **未经脱敏的原语依然可调用。** `ctx.trajectories.export()` 仍是进程内任何插件都能调用的服务，因此 curator 是那条会拒绝的路径，而不是围绕数据的屏障。要封住它需要推进项 4 的组合规则；在此之前 README 写明哪一个调用是安全的那个。
- **规则是正则表达式，而正则表达式会漏。** 没有人为其写过规则的凭据格式会被导出，`redactionApplied: true` 说的是有一个配置运行过，绝不是这条记录是干净的。逐规则的命中计数正是评审者据以判断某个配置是否在起作用的东西。
- **脱敏规则可能损坏数据。** IPv4 规则会改写形似点分四段的版本串，而一条激进的自定义规则能让一条记录不再可用于训练。永不脱敏集合保护读者据以分支的标识符；它不保护文本内部的含义。
- **条款只与钉定一样可靠。** 由配置条款有误的部署方钉定的会话，会按那个错误被接纳或扣留，而 curator 无法把错误的钉定与正确的区分开。它拒绝未钉定这一种情况，那是日志能看见的一种。
- **每个被接纳的会话读两次。** 条款遍历与导出器的折叠各读一次会话，因此大型存储会被读两次。这份代价属于批量导出而非 agent 循环，而另一条路是重复实现导出器。
