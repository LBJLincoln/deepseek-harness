# Agent Note: A generalist code-safety department beside the six specialists

Status: proposed

English | [中文](2026-09-22-code-safety-generalist-department.zh.md)

## Problem

[The three-tier comparison on NodeGoat](../../../../data/code-safety/comparisons/2026-09-22-nodegoat/README.md) scored semgrep, one frontier-model pass with no departments, and the six-department enterprise against the same 18-issue ground truth, at the same revision, with the enterprise and the single pass on the same model (sonnet). The single pass caught 15 of 18 (83%); the six-department enterprise caught 13 of 18 (72%); semgrep caught 4 of 18. Read issue by issue, both approaches miss the same two broken-authentication issues, but the single pass alone catches three the six departments miss entirely — server-side request forgery (`NG-SSRF`, `app/routes/research.js`), regular-expression denial of service (`NG-REDOS`, `app/routes/profile.js`), and log injection (`NG-A1-3`) — while the enterprise alone catches one the single pass misses (`NG-A6-1`, sensitive data at rest).

The comparison's own reading is that a small application fits in one reviewer's context, so a single whole-repository pass gets breadth a six-way subject split cannot: each specialist reads only its own slice, and a defect at the boundary between subjects, or outside all six of them, can fall through every one of the six reads without falling through a seventh that reads everything. The loop already tried the narrow fix once: the injection department's skill gained an SSRF-enumeration directive and the two missing defect classes, and a re-run on the same target, revision, model and composition caught one of the three (`NG-SSRF`) while losing an unrelated one (`NG-A5`) in a department the change never touched — a result the comparison record itself calls inside the program's own run-to-run variation (four recorded NodeGoat runs score 14, 14, 13, 13 of 18), not an established gain. A skill patch to one department treats a named symptom; it does not add the structural breadth the single-pass tier has and the six-department tier does not.

The missing option is a department that gets that same structural breadth — reading the whole application in one pass, across every defect class — while running beside the six specialists rather than instead of them, so the integration's union can carry both the single pass's breadth and the enterprise's per-subject depth, and every one of its findings still passes the same committed examiner the specialists' findings do.

## Proposal

A seventh department, `generalist`, added to the code-safety program fixture as an opt-in beside the six specialists, never in their place:

- **Preset.** [`presets/generalist/agent.cordis.yml`](../../../../examples/headless-agent/tests/fixtures/program-code-safety/presets/generalist/agent.cordis.yml) composes a persona that reads the whole application end to end — every route, every data access path, every configuration file, the client-side code — and reports a defect of any class, under the same finding schema and the same `REPORTING.md` contract as every specialist. It is instructed to load every skill in the knowledge pack rather than the two (`review-method`, `severity-and-evidence`) a specialist loads, since the pack already shares one root across every session (`DSH_CODE_SAFETY_SKILLS` / `customSkillDirs`) and nothing there needed to change.
- **Registry.** [`departments.ts`](../../../../examples/headless-agent/tests/fixtures/program-code-safety/departments.ts) is a new module holding the six specialists' definitions (moved out of `driver.ts` unchanged), the new `GENERALIST_DEPARTMENT` definition, and `resolveDepartments(requested)`: a validated resolution of `DSH_CODE_SAFETY_DEPARTMENTS` (a comma-separated department-key list) that defaults to the six specialists, in their existing order, when the variable is unset, and throws naming the bad value on an empty list, a repeated key, or an unknown key. `driver.ts` calls it once, at the same point it validates its other env-derived inputs, and builds `ProgramSpec.goals` from the result instead of a hardcoded array; every goal gets the same `budget`, `isolation`, `dependsOn` and two-check shape the mapper already gave every specialist, so the generalist is not a special case there.
- **Overlay.** [`overlays/with-generalist.cordis.yml`](../../../../examples/headless-agent/tests/fixtures/program-code-safety/overlays/with-generalist.cordis.yml) is the same real, Claude-Code-routed composition as `overlays/claude-code.cordis.yml`, restated in full rather than layered over it (see Alternatives). Booting it changes nothing about which departments run — that is `driver.ts`'s own resolution from `DSH_CODE_SAFETY_DEPARTMENTS` — so the overlay and the env var are a pair `scripts/code-safety.ts` sets together.
- **CLI.** `scripts/code-safety.ts` gains `--with-generalist` (the six specialists plus `generalist`, booting the new overlay) and `--departments <list>` (an exact set, passed straight to `DSH_CODE_SAFETY_DEPARTMENTS`; `driver.ts` is what validates it), mutually exclusive. Neither flag changes `--keyless`'s composition file, only the department-set env var the scripted route also reads.
- **Concurrency and budget.** `overlays/with-generalist.cordis.yml` keeps `maxConcurrentGoals: 3`: a seventh independent worktree is one more department sharing nothing but the target, not a reason to widen the window. The generalist's goal carries the same `BUDGET` (`maxTotalTokens: 4_000_000`, `maxWallMs: 2_400_000`) every specialist runs under.
- **Keyless coverage.** `code-safety-llm.ts`'s scripted route gains three `generalist` findings, each on a defect class and a file none of the six specialists' scripted findings already cite — OS command injection (`src/admin.js:14`, CWE-78), path traversal (`src/admin.js:28`, CWE-22), and DOM-based XSS (`public/app.js:5`, CWE-79) — so the union genuinely gains breadth rather than restating an existing hit under a new id. `union()` and the scripted `SAFETY-REPORT.md` prose now read the same resolved department set `driver.ts` does, so a run that does not name `generalist` merges and states exactly what it did before this change; a new e2e case runs the program with `DSH_CODE_SAFETY_DEPARTMENTS` naming all seven and asserts the seventh certificate, its two checks, and the merged, examined union; the existing six-department case is asserted unchanged.

## Evaluation

Nothing above is evidence that adding the generalist raises recall — the comparison in `## Problem` motivates trying it, on a different program (six-plus-one departments) than the one it measured (six departments alone or one undivided pass). Reading whether it helps needs a new paired comparison, in the same shape [`compare.mjs`](../../../../data/code-safety/tools/compare.mjs) and [`assemble-comparison.mjs`](../../../../data/code-safety/tools/assemble-comparison.mjs) already produce: the program run twice, once over `overlays/claude-code.cordis.yml` and once over `overlays/with-generalist.cordis.yml`, on the same target, the same revision, the same model, and otherwise the same composition, at least two repetitions of each side, scored against the target's committed ground truth. A single run of the generalist-enabled composition, however good its recall, is exactly the one-run reading the comparison record itself warns is inside the program's own variation; only the paired, repeated reading says whether the seventh department's findings are a real gain, noise, or a wash with what it costs in wall time and tokens.

## Alternatives considered

**Replace the six specialists with one generalist department, mirroring the single-pass tier exactly.** Rejected: the comparison's own reading is that the enterprise's per-subject depth is where it pulls ahead — it surfaces more than double the single pass's findings and catches one issue (`NG-A6-1`) the single pass misses — and that the gap is narrowest on a small application specifically because a single pass can hold the whole thing in context; the target this proof of concept is aimed at has thousands of files, where a single pass cannot, and dropping the specialists would give up the enterprise's whole reason to exist for it.

**Patch each specialist's skill to close the three named gaps, as the loop's first iteration already tried for the injection department.** Rejected as sufficient on its own: the first iteration's own record is one of the three targets caught, one unrelated one lost, and a decision that the effect is not established by one run — a narrow fix to a named symptom, not the structural breadth a whole-application read has and a subject-scoped one does not. The generalist department does not preclude further skill patches to the specialists; the two are complementary, not competing, fixes.

**Widen every specialist's own instruction to read the whole tree, instead of adding a department.** Rejected: it multiplies every specialist's reading and token budget for five subjects it does not own, and blurs what each department is measured on — its own subject, in `findings/<key>.json` — against what its persona actually asks it to read. A dedicated department keeps the measurement and the persona for one reviewer's job aligned with each other, the way every existing department's persona and goal objective already are.

**A cordis.yml plugin config field for the department set, instead of a `driver.ts`-resolved env var.** Considered, because `## Proposal` in the task description offered both. Rejected: `driver.ts` builds `ProgramSpec` in TypeScript entirely outside any plugin's config — no `program` field or other composed plugin owns "which departments this run includes" today — and every other run-varying choice this exact fixture already carries (`DSH_CODE_SAFETY_TARGET`, `_REPORT_REPO`, `_MODEL`, `_SKILLS`) is an env var `driver.ts` or an overlay's `!!js` block reads directly rather than a new plugin's config. Introducing a plugin solely to carry one list would be a heavier, single-purpose seam where the fixture's own established pattern already fits.

**Layer `overlays/with-generalist.cordis.yml` over `overlays/claude-code.cordis.yml` with a nested `cordis-plugin-include`, instead of restating its patches.** Rejected: that plugin's patches override or insert entries by id on the file its own `path` names, with no way to reach into a patch an earlier include already applied — a second-layer patch could only replace the first include's whole `config`, which needs the same full patch list restated anyway, buying nothing over a sibling file that patches the same base directly. [`dsh-agent-presets`](../../../../packages/preset/agent-presets/README.md) accepts the identical cost for the identical reason: its shipped `cordis` and `code` presets are full copies of `standard`, because the layer has "no patch semantics... to express 'standard plus one change'."

## Acceptance criteria

- `pnpm vitest run examples/headless-agent/tests/program-code-safety.e2e.ts` passes both cases: the original six-department run, asserted byte-for-byte unchanged, and a new run with `DSH_CODE_SAFETY_DEPARTMENTS` naming all seven, whose `generalist` member certifies on `generalist-findings` and `generalist-section` and whose three findings are in the merged `findings.json` that the committed examiner's `--report` check passes.
- `resolveDepartments(undefined)` returns the six specialists in their existing order, so every prior recorded run, snapshot and comparison stays comparable against an unmodified default.
- `resolveDepartments` throws, naming the offending value, on an empty department list, a repeated key, or a key no department declares.
- `pnpm run code-safety -- <target> --with-generalist` boots `overlays/with-generalist.cordis.yml` with `DSH_CODE_SAFETY_DEPARTMENTS` set to the six specialists plus `generalist`; `--departments <list>` names an exact set; the two flags are mutually exclusive.
- `pnpm run verify-cordis-config` passes with the new overlay and preset in place.
- A paired comparison — `overlays/claude-code.cordis.yml` against `overlays/with-generalist.cordis.yml`, same target, revision and model, at least two repetitions each, scored by `compare.mjs` and read by `assemble-comparison.mjs` — is what would settle whether the seventh department raises recall; this note is not that reading, and none of the above substitutes for it.

## Risks

- **The cited comparison is one run per tier.** The 15-of-18 single pass and the 13-of-18 enterprise are one measurement each, and the comparison record's own reading of the loop's first iteration treats a one-issue move as inside the program's run-to-run variation once four runs exist. A repeated, paired reading of the generalist addition could show a smaller effect, no effect, or a different set of gained and lost issues than the motivating comparison suggests.
- **A seventh worktree, branch and session per run** costs more wall time at the fixed `maxConcurrentGoals: 3` and more tokens at the fixed per-department budget; this note keeps both caps unchanged rather than widening them to absorb the seventh department, so it competes for the same concurrency window the six specialists already share.
- **The generalist's findings can overlap the specialists' almost entirely on a small or well-covered application**, in which case the visible effect of running it is a longer program for a report the union dedupes back down to what six departments already found. The persona instructs it to spend its reading on what a subject-scoped read would not surface; nothing beyond the model's own judgment enforces that on a real run.
- **The keyless coverage proves the plumbing, not the persona.** The three scripted generalist findings prove the seventh department can certify, merge, and pass the same committed examiner as the six specialists; they do not show that a real Claude Code session reading the generalist persona finds, on a real target, anything a specialist would have missed. Only the paired comparison in `## Evaluation` answers that.
