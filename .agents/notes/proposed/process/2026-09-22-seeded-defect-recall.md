# Agent Note: Seeded-defect recall estimates the review on a target with no ground truth

Status: proposed

English | [中文](2026-09-22-seeded-defect-recall.zh.md)

## Problem

The code-safety program's recall is only measured on the two public targets that carry a documented ground truth: NodeGoat (18 issues) and dvja (14 issues). A client's own application has neither, so today a review of it produces a finding count and a set of severities with nothing to compare them against — the client cannot tell whether 40 findings means the review found most of what is there or missed most of it, because no one has counted what is there. `docs/code-safety-poc.md`'s funded-proof-of-concept scope already names "a seeded ground truth agreed with their security team" as the fix, but nothing produces one: today that would mean a manual negotiation over which real or planted issues count, redone for every engagement.

## Proposal

Seeded-defect (canary) estimation: plant a known number of synthetic defect instances, of the classes the departments' skills already look for, at recorded locations in a full copy of the target; run the review on the copy without telling it; score the fraction of planted locations a released finding lands on, with the same three-line-tolerance match rule `compare.mjs` already uses. The fraction is a recall estimate for those classes on that codebase, with a stated confidence interval — not a claim about the target's real, undiscovered defects.

`data/code-safety/tools/seed-defects.mjs` does the planting, from a **mutation catalogue** at `data/code-safety/tools/seed-catalogue.json`. Each catalogue entry is data: a CWE, a language, a regex (`sitePattern`) that finds a candidate line, optional whole-file `fileRequirePattern`/`fileExcludePattern` and a `fieldHintPattern` for a realistic field name, and a string template (`insertTemplate`) with `{{indent}}`/`{{source}}`/`{{field}}`/`{{line}}`/`{{hex}}` placeholders. The tool is a generic interpreter over that data, not a per-class code path. Eight JavaScript/Express entries ship, one per class the injection, access, and secrets skills document: eval injection (CWE-95), NoSQL `$where` injection (CWE-943), server-side request forgery (CWE-918), log injection (CWE-117), unvalidated redirect (CWE-601), regular-expression denial of service (CWE-1333), reflected XSS via string-built responses (CWE-79), and hardcoded credentials (CWE-798). Seven of the eight share one site pattern — any line referencing `req.query`/`req.body`/`req.params.<field>` — and insert one new line after it that carries that same field into the class's sink (`eval()`, a `$where` filter, `fetch()`, `console.log()`, `res.redirect()`, `new RegExp()`, `res.send()` concatenation); the credential class instead anchors to a file's own `require(...)` line and adds a fallback-secret declaration matching the secrets skill's own `process.env.JWT_SECRET || 'literal'` example. A lightweight per-line scan skips `//` comments, `/* */` bodies, and multi-line template literals so an insertion never lands inside one; every inserted line is then verified with `node --check` immediately, and a site whose file fails to parse afterward is undone and does not count toward N. No two planted sites in one file land within 10 lines of each other. Selection is a seeded Fisher-Yates shuffle of every candidate (fields matching an entry's hint first), so the same seed and target always plant the same set and a different seed reshuffles it; `--max-per-entry` caps how many sites one catalogue entry may contribute, so a class with many candidates does not crowd out the rest on a small target; `--avoid <ground-truth.json>` keeps a planted site away from a target's own already-documented real issues (three-line tolerance, matching `compare.mjs`'s own rule), so a review's hit on a real, pre-existing defect is never mistaken for a hit on a synthetic one. `--dry-run` lists every candidate site, with the seeded selection marked, and touches nothing.

`data/code-safety/tools/seeded-recall.mjs` scores a findings list, or a record directory, against the `seeded.ground-truth.json` a seeding run writes, with `compare.mjs`'s exact match rule, and reports caught/N as a Wilson 95% confidence interval — chosen over a normal-approximation interval because it stays inside [0, 1] and does not collapse to zero width at the small counts one seeding run produces (`k = 0` or `k = n`) — overall and per CWE class.

### The NodeGoat dry run

A seeding run with `--seed 1 --n 12 --avoid data/code-safety/targets/nodegoat.ground-truth.json` against a copy of NodeGoat at the ground truth's own revision (`c5cb68a`) planted all 12 requested sites from 37 eligible candidates (6 rejected for being within 10 lines of another accepted site, 0 rejected by `node --check`), across 11 files, none of them within 3 lines of any of NodeGoat's 18 documented issues. `--avoid` and NodeGoat's small size interacted: excluding the 18 known-issue locations left only one surviving candidate anywhere in the tree for the seven request-flow classes combined (`app/routes/memos.js`'s `req.body.memo`, since NodeGoat's other `req.query`/`req.body` reads all sit within three lines of a documented issue), so 11 of the 12 planted sites are the hardcoded-credential class, which needs no request data flow and has many eligible `require(...)` lines. A single sonnet pass with read-only tools (`Read`, `Grep`, `Glob`; the prompt in `/tmp/…/scratchpad/compare/t1-prompt.txt`, unchanged from the run against the unseeded target, so the review was never told the copy was seeded) against the seeded copy released 50 findings in 265 s and read 12/12 (recall 1.0) with a Wilson 95% interval of [0.758, 1.0]; by class, hardcoded-credential read 11/11 (95% CI [0.741, 1.0]) and log injection read 1/1 (95% CI [0.207, 1.0]) — every planted site was named individually in the model's own vocabulary, with no indication in its output that it recognized the copy as seeded. This is the single-model tier only, run because the full six-department program's subscription was shared with other work that evening; the command for the full reading is recorded in `data/code-safety/README.md`'s seeded-defects section for a later run.

## Alternatives considered

- **Trusting the two public-benchmark readings as a proxy for a client's own recall.** NodeGoat and dvja say nothing about a codebase whose languages, frameworks, and defect distribution differ from either, which is every real client application.
- **A manual, per-engagement seeded ground truth**, as `docs/code-safety-poc.md` already named. It does not scale (redone per engagement), is not reproducible (no seed to rerun), and puts the negotiation before any number exists to negotiate over.
- **An LLM-authored seeding pass** instead of regex templates over a data catalogue. It could vary planted defects more than eight fixed templates, but its output would not be exactly reproducible under a seed, and it would need its own verification step to guarantee syntactic validity and realistic placement — the same problems this proposal solves, reintroduced one level up.
- **Scoring seeded recall inside the release gate.** A gate that plants and scores synthetic defects on every run would make the release criterion partly about this tool's own synthetic patterns rather than verified, real findings; seeded recall stays a separate, optional estimation step, the same relationship `recall.mjs` already has to the gate.

## Acceptance criteria

- `seed-defects.mjs` never modifies the original target (verified: `git status` on `/root/targets/NodeGoat` is empty after every run in this note); every planted defect's file independently passes `node --check`; no two planted defects in one file land within 10 lines of each other; the same seed and target plant the same set on a second run.
- `seeded-recall.mjs` reproduces `compare.mjs`'s match rule exactly and reports a Wilson 95% interval, overall and per class.
- A dry run against NodeGoat plants N = 12 and reports the caught/12 reading above; the full six-department program's own reading is run once the subscription is not shared with other work.
- Java support is out of scope for this note: NodeGoat's and dvja's Java frameworks (Struts 2, Spring) need a distinct site pattern and a distinct syntax check (no `node --check` equivalent), which was not cheap to get right in this pass.

## Risks

- A seeded-recall number is recall on the **seeded classes at the seeded sites**, not the base rate of real, undiscovered defects in the target; a target certainly holds defects outside the eight modeled classes, and this estimate says nothing about those. `data/code-safety/README.md`'s seeded-defects section states this alongside every reading.
- A planted defect the seeder made obvious — a comment naming the vulnerability, a variable named for it, a value resembling a documented placeholder a review's own skill would filter as a known non-finding (an `AKIA...EXAMPLE`-style key, a literal `devsecret`) — would inflate the number without saying anything about the review's real ability. The catalogue avoids this by mirroring patterns already documented in a department skill or already present as a real defect in a public target, carrying no comment or defect-naming identifier, and using a seeded pseudo-random hex string for the one class (hardcoded credentials) whose value could otherwise resemble a known placeholder.
- On a small, extensively-studied target like NodeGoat, `--avoid` can leave only one class with real capacity, so a small N reads mostly that class; a customer's much larger codebase will not have this constraint bind the same way, but a small pilot target might, and the per-class breakdown in `seeded-recall.mjs`'s output is how a reader would notice.
