# Agent Note: The code-safety misses on NodeGoat, diagnosed from the session logs and closed at their owner

Status: proposed

English | [中文](2026-09-27-code-safety-misses-diagnosis.zh.md)

## Problem

[The three-tier comparison](../../../../data/code-safety/comparisons/2026-09-22-nodegoat/README.md) reads the six-department code-safety program at 13 of 18 known NodeGoat issues against one plain single-model pass at 15 of 18, and the loop's two iterations moved that reading without settling it: iteration 1 widened the injection skill (gained `NG-SSRF`, lost `NG-A5`), iteration 2 added a generalist department and read no gain across an interleaved pair. `comparison.json` names the gaps: the single pass alone caught `NG-A1-3` (log injection), `NG-SSRF` and `NG-REDOS`; both tiers miss `NG-A2-2a` (account enumeration) and `NG-A2-2b` (password policy); `NG-A5` (security headers) is caught in four of the six enterprise runs and lost in two. Each iteration chose a mechanism before reading why the department that owned the file did not file the finding, so a change could land beside the cause rather than on it: in a skill when the department's own instruction was the authority it followed, in a new department when the owning one had already opened the file.

This note reads the six enterprise records — [`2026-09-21-nodegoat-3`](../../../../data/code-safety/2026-09-21-nodegoat-3/manifest.json), [`2026-09-22-nodegoat-4-improved`](../../../../data/code-safety/2026-09-22-nodegoat-4-improved/manifest.json), [`-5-generalist-a`](../../../../data/code-safety/2026-09-22-nodegoat-5-generalist-a/manifest.json), [`-6-base-a`](../../../../data/code-safety/2026-09-22-nodegoat-6-base-a/manifest.json), [`-7-generalist-b`](../../../../data/code-safety/2026-09-22-nodegoat-7-generalist-b/manifest.json), [`-8-base-b`](../../../../data/code-safety/2026-09-22-nodegoat-8-base-b/manifest.json) — for each miss: which department opened the file, what it wrote about the line, whether the examiner refused a finding, and whether a budget or a tool stopped it; then it changes the smallest thing that owns each cause. Nothing here is a rerun: the pair that would read the effect is written out in `## Verification` for the operator, because the route was busy while this was written.

## Proposal

Change the owner of each cause and nothing else, in the places the diagnosis names; every skill change names defect classes and code patterns, never a target's file, route or line.

- **Injection department scope** ([`departments.ts`](../../../../examples/headless-agent/tests/fixtures/program-code-safety/departments.ts) goal instruction and [`presets/injection/agent.cordis.yml`](../../../../examples/headless-agent/tests/fixtures/program-code-safety/presets/injection/agent.cordis.yml) persona): the sink list gains server-side HTTP clients taking a request-built URL, log calls writing a request value unencoded, and regular-expression tests with nested or overlapping quantifiers, and the persona states that a log line and a validator's pattern are this department's sinks — because the run-3 report cites "that department's assigned sink list" as the reason SSRF went unfiled and the run-5 injection department, having loaded the skill that already carried log injection, still judged the login log line another department's concern.
- **Injection skill** ([`data/knowledge/code-safety/injection/SKILL.md`](../../../../data/knowledge/code-safety/injection/SKILL.md)): the log-injection and ReDoS sections each gain an enumeration directive of the form the SSRF section already has (list every call site a request value reaches, then judge each) — because SSRF went from 0 of 1 to 5 of 5 runs after its enumeration directive, while ReDoS, with a recognition paragraph and no directive, was filed in 2 of 6 runs by a department that had the file open in all 6.
- **Access skill and scope** ([`data/knowledge/code-safety/access/SKILL.md`](../../../../data/knowledge/code-safety/access/SKILL.md), [`presets/access/agent.cordis.yml`](../../../../examples/headless-agent/tests/fixtures/program-code-safety/presets/access/agent.cordis.yml), the access goal instruction): two new checklist entries, account enumeration through authentication responses that differ by whether the account exists (CWE-204, CWE-203) and the password-policy acceptance rule a signup or change handler applies (CWE-521), each with the line to cite — because the access department opened the login and signup handlers in all six runs and its skill, persona and instruction held neither class.
- **Platform persona** ([`presets/platform/agent.cordis.yml`](../../../../examples/headless-agent/tests/fixtures/program-code-safety/presets/platform/agent.cordis.yml)): when the code carries the disabled control as commented-out code or a false option, the finding cites that line; only otherwise the line where the protection would be mounted — because the platform department filed the missing-headers defect in all six runs and in two of them cited the first live middleware line the old rule pointed it to, outside the window any reader of the defect would look at.
- **The two READMEs that state department and skill scope** ([the fixture's](../../../../examples/headless-agent/tests/fixtures/program-code-safety/README.md), [the pack's](../../../../data/knowledge/code-safety/README.md)) name the added classes in their tables, with their Chinese counterparts re-recorded.

The goal instruction is part of the frozen spec, so a run with these changes carries a new program id; the recorded runs keep `program-e570066f…` and `program-b0d17883…`, and records stay comparable by target, revision and ground truth, not by id.

## Alternatives considered

**Another department, or the generalist again.** Rejected: every missed issue's file was opened by its owning department in every run, and the generalist read `session.js` in both of its runs without filing either authentication issue; breadth is not what these misses lack, and the generalist pair already recorded that a seventh reader adds no recall on this target.

**Put the new classes only in the skills, as iteration 1 did.** Rejected as the sole change: the run-3 report names the department's "assigned sink list" — the goal instruction and persona — as the reason SSRF went unfiled, and the run-5 injection department had loaded the skill that carried log injection and still deferred the line to another department. The instruction and persona are what a department reads as its remit; the skill is what it reads as its craft. Both change here, each in one sentence.

**Give the data department log injection, since it already greps the log calls.** Rejected: the failure mode on record is a department leaving the class to another, and two owners invite exactly that in both directions. The integration deduplicates overlapping findings, but ownership has to be unambiguous for the sink list to be followed; the injection persona now says so in as many words.

**Widen the scorer's window or the ground truth's `alsoAt` so `server.js:68` counts for `NG-A5`.** Rejected: the scorer is not the product. A finding whose snippet shows a favicon middleware while its evidence talks about a commented-out block six lines earlier is a worse finding than one whose snippet shows the disabled control; the citation rule improves the evidence and the recall reading follows.

**Loosen the examiner.** Not applicable: the examiner refused nothing in any of the six runs, so no true finding was lost to verification; the examiner stays as it is.

**Run the pair inside this task.** Not done: the route was busy with another run, and one run of either arm is the single-run reading the comparison record itself warns is inside the program's 12-to-15 band; the pair is written out instead.

## Risks

- **A longer sink list dilutes attention.** The injection persona's sink-first list grows by three classes and the access checklist by two; a reader that spreads the same reading over more sinks could thin its core findings. The pair's no-loss criterion is what detects that, and it is the reason the base arm runs twice rather than being read from the six existing records.
- **Cross-run contamination.** The records show departments reading earlier runs' findings from `.code-safety/`; a rerun that leaves those directories in place lets each arm read the other's findings and blurs the pair. The procedure moves them away first; a department that still reaches another run's files is a reason to discard that run, not to read it.
- **Fitting the target.** The two never-caught issues are the classic tutorial items of this target, and the new access entries describe exactly their classes. The entries are written as classes and patterns with the line to cite, and the example pattern in the skill is not the target's; the check that they generalize is the same one every skill has — a second target with its own ground truth, or [seeded-defect recall](2026-09-22-seeded-defect-recall.md) on a codebase without one.
- **A moved citation moves other readings.** The platform rule now prefers a disabled control's own line; on a target whose ground truth pins a missing-control issue to the live mount point, the same rule moves the citation the other way. The rule states the preference and its fallback, so a reader of either target can follow the finding to the code.
- **The program id changes.** The goal instruction is part of the frozen spec; the recorded runs keep their ids, the deck's recorded programs are unchanged, and no test pins the id, but a reader comparing a new record with an old one by id alone will find none.
