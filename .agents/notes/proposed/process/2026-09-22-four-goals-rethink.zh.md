# Agent Note: 四个目标作为可测量的主张意味着什么，以及它们共同的短缺

Status: proposed

[English](2026-09-22-four-goals-rethink.md) | 中文

## Problem

[2026-09-19 的目标笔记](2026-09-19-objectives-step-back.md)陈述了四个目标各自所处的位置。2026-09-22，四次只读审计把 `c0efe64a3` 处的代码树逐包、逐记录地对照每个目标做了映射，发现那些位置被高估了，而仪器比其文档所述更弱。本笔记取代那份笔记的位置陈述与工作顺序；它不取代[四个目标工作流](../architecture/2026-09-05-four-goal-workflows.md)，后者仍是目标设计。

审计确立的事实，每一条都标明其在代码树中的位置：

- **被测量的 harness 不是发布的 harness。**记录在案的每个 harness 循环单元都运行在一个八工具构建（`bash`、`read`、`write`、`edit`、三个 job 工具、`skill`）与两句话的人设之下（[基准台 `cordis.yml`](../../../../examples/headless-agent/tests/fixtures/proving-ground-bench/cordis.yml)）；发布的编码插件（compaction、grep 与 glob、编辑器、todo、subagents、workflows、plan 模式、LSP、Code Mode、重复调用提醒）没有一个对编码有被测量过的效应。1,157 个盖章单元中有 1,137 个通过操作者的 Claude Code 登录运行在一家供应商的模型上；原生 DeepSeek 适配器的基准台单元为零；harness 路由以 `effort: medium` 运行而产品循环未设置，因此"harness 与产品循环持平"的读数带有混杂。没有任何东西适配模型：没有按模型的提示词、工具面、编辑格式或文本工具调用回退，而记录在案的唯一一次开放权重失败（一个从未写过文件的模型）被归为"不是 harness 该修的"——这恰恰是目标 1 所关心的情形。
- **仪器会假晋升。**[`dsh-experiments`](../../../../packages/improvement/experiments/README.md) 中的配对 bootstrap 在每个环境内部重采样配对结果，却从不重采样环境本身；在两次重复下，一个结果一致的环境不贡献任何方差。循环有史以来写下的唯一一次 `adopt-candidate`（[账本第 7 行](../../../../data/proving-ground/loop/ledger.jsonl)，2026-09-21，E7 五次尝试对三次）是 16 之 12 对 16 之 14，区间为 `[0.125, 0.125]`：一个环境两次重复都翻转，其余每个单元完全相同，区间因此坍缩成一个点。把三对 E7 合并起来读是 48 之 41 对 48 之 43，+0.042，低于计划的 `minimumDelta`。此前唯一一次有利于某个 harness 机制的 `reject`（E3，三次尝试对一次，2026-09-08 的 −0.375）没有复现（09-19 与 09-21 均为 −0.0625），而同一配置在十二次记录在案的舰队中得分从 16 之 12 到 16 之 15 不等，所以文档所写的"一次翻转"噪声底被低估了。09-19 笔记中的"尝试次数有效（+0.375）"已被取代。
- **企业是一种投影。**[`data/enterprise/roster.json`](../../../../data/enterprise/README.md) 中的 147 个席位指向两个单元测试用的桩预设，以及没有任何记录会话用过的路由（`deepseek-official`、`codex`）；把 feed 的映射逻辑在每个会话文件上重放，只点亮 16 个席位，并把 541 个会话送到一个兜底席位。部门们造出的唯一一件软件（[csv-tools](../../../../data/proving-ground/2026-09-19-csv-tools-program/manifest.json)，447 行，51 个测试，部门串行）从未被提交；没有任何程序有审阅者；每个发布签名都由驱动在工作开始前写在一个占位摘要之上；`ci.yml` 在这个分支上从未运行过，分支也没有 pull request。在代码安全对比上，一次模型通过找到 18 个已知问题中的 15 个，而六部门程序找到 13 个（[记录](../../../../data/code-safety/comparisons/2026-09-22-nodegoat/README.md)），循环针对这一差距的第一次迭代是每边各一次运行，落在程序自身 13 到 14 的波动范围之内。
- **语料是 22 条轨迹，且未经整理。**1,044 条已提交的轨迹行中，22 条带有允许训练的条款（全部为第 2 层、六个环境、四个未读过许可证的免费模型）；0 条带有 `curation` 块，因为两个基准台驱动都调用原始导出器，而三份文档却说导出经过了 curator 门控；99 条奖励为 0 的轨迹中有 71 条是预算突破，训练者无法把它们与失败区分开；发布的脱敏规则漏掉了 PEM、AWS、GitHub 与 Slack 材料，两条记录把一个目标的私钥体原样提交了（已在 `d277281c9` 中脱敏，且记录器现在在摘要之前先脱敏）。

四个目标之下压着同一种短缺：**可验证的任务**。四十四个手工编写的 JavaScript 命令行程序，第 5 层以下被每个模型饱和、第 5 层被最大的模型饱和；十六个单元读不出 0.19 以下的效应；32 个可训练环境在组大小 8 下每个 epoch 只给出 256 次 rollout，比已发表的 RLVR 运行低一到两个数量级；也没有任何东西可供读者放到一个公开数字旁边。三周里造出的每件仪器——fleet、experiments、scorekeeper、curator、程序账本、shifts、observatory、读屏障——都在等任务。第二种短缺是路由：一家供应商、一个登录、种子被该路由丢弃。

## Proposal

把每个目标重述为一个由某件仪器裁决的主张，并把任务供给放在首位。

### 目标 1——让任何模型成为最好的 agentic 编码者的 harness

**主张。**对固定的模型，发布的组合在一个公开套件和一个没有任何模型见过的私有套件上，以每单位成本认证的任务数超过模型供应商自己的脚手架与一个最小参考循环，且对至少三个模型家族成立。

**仪器。**三个套件，各为环境注册表中的一个 `bench` 种类：Aider polyglot 基准（六种语言的 225 道 Exercism 练习，钉在修订版 `7e0611e7`，同一批任务在 aider 脚手架下有公开排行榜，本机已有 Python、Go、Rust 与 C++ 的工具链）；由基准台自身参考程序合成的补全族（私有、未受污染、数百个任务）；以及在磁盘允许时，Docker 下的 SWE-bench Verified 子集，本机能运行它。被测量的组合是发布的那个，而不是八工具的裁剪版，且每个臂都声明其 effort 与种子处理方式。

**机制。**读数表明 harness 的价值在于验证密度——验证器循环、封印、守得住的上限——而不是呈现给模型的知识。因此要测试的机制是那些提高每 token 验证量的机制：携带验证器通道差异的指令、验证前的自我审阅级、带验证器筛选的 best-of-n，以及按模型的适配（对原生调用失败的模型提供文本工具调用回退与编辑格式）。每一项都以由修正后的统计量确定 n 的冻结配对，在一个能区分的套件上运行。

### 目标 2——通过 harness 进行的 agentic 软件创造

**主张。**企业交付的软件，其验收由实现者读不到的检查来认证，并有账本记明哪个 agent 做了什么；仓库自身的变更就是这样产生的。

**机制。**每次程序运行的交付物与账本一起提交进记录，使一次构建以代码而非仅以工具调用参数的形式存在。一个审阅者部门对照规格阅读集成差异，返回经 schema 校验的裁决（W2 第 9 阶段），由集成门消费；发布签名在证书之后记录，签署者不由驱动杜撰。接下来的 harness 切片由程序在仓库自身的门禁下产出，部门记录归档到 `data/` 之下，于是记录在案的组织就是账本，而非一份定义花名册；花名册只显示有记录会话占据过的席位。对代码安全产品而言：在六个专家部门之旁增设一个全仓库通才部门，因为在小型应用上广度胜过专精，并以带重复的配对而非单次运行来测试；对没有基准真值的客户代码，则通过在副本中植入审查不知情的已知缺陷实例来估计召回率。

### 目标 3——以 RLVR 训练的开放权重模型

**主张。**一个约 120B 的开放权重模型，配合这个 harness 后在保留任务上的认证数超过其基座，以证书奖励、通过 GRPO 在数千个已准入环境的提示集上训练。

**机制。**[配方](../architecture/2026-09-19-rlvr-recipe-and-base-model.md)仍然成立；它的输入尚不存在。环境先来自上面的工厂，再来自仓库派生的任务（一旦运行器能持有隐藏测试文件，本仓库自身的 712 个 spec 文件与 1,362 个带 JSDoc 规格的导出函数），再来自 Docker 下许可宽松的公开仓库。Rollout 来自开放权重路由：免费层以每天约一千个请求填充语料，付费密钥是倍增器，条款按路由钉定。curator 运行在导出路径上，记录携带停止原因，于是截断被掩蔽而非计为 0。基座模型表格漏掉了一个候选：NVIDIA Nemotron 3 Super 120B-A12B（BF16 开放权重、已发布的后训练数据、与推荐模型同一档次的 agentic 结果、今天在路由上免费、许可证仍待阅读）；决定在它与 Qwen3.5-122B-A10B 之间重新打开。算力仍在外部；配方对 16 到 64 张 H200 上每个 epoch 一到四小时的估计成立。

### 目标 4——自我改进循环

**主张。**每次迭代都由对记录在案的会话记录的诊断提出，以统计量可靠、n 与效应匹配的冻结配对测试，按规则决定，通过组合应用，并在一份账本中可读。

**机制。**先修统计量：对环境及其配对进行重采样的聚类 bootstrap、不一致配对守卫、跨复现的合并，以及在每个结果与账本行上命名的统计量版本。然后是缺失的阶段，每个都是一个在记录日志上工作、输出经 schema 校验的部门：诊断（漏检类别与证据序号，代码安全对比中手工的差距清单即其原型）、提案（候选覆盖或技能及其计划，运行前先散列）、应用（`adopt-candidate` 通过清单把覆盖写进组合并在门禁下打开一次变更；同一计划的下一对配对将其回退）。队列不再重跑合并读数已经定论的计划；它排入诊断指名的配对。从一个目标的漏检中做出的知识编辑，要先在另一个目标上读到结果才算数。

### 工作顺序

1. 统计量、导出路径上的 curator 与停止原因、带首次记录运行的 polyglot 基准台、补全任务工厂——四项在 2026-09-22 均已在进行中。
2. 改进日志缺失的行与 09-21 晋升的修正读数；每条记录的脱敏（已在 `d277281c9` 完成）。
3. 程序的已提交交付物与审阅者部门；代码安全通才配对；植入缺陷的召回估计。
4. 仓库派生的环境（运行器中的隐藏测试文件）、Docker 下的 SWE-bench Verified 子集、诊断与提案部门。
5. 基座模型的重新决定，以及开放权重路由上一支舰队的首次训练用途导出。

需要操作者提供：一条付费的开放权重路由（OpenRouter 上 Qwen3.5-122B-A10B 输入与输出每百万 token 为 $0.26 与 $2.08；Nemotron 3 Super 为 $0.08 与 $0.45；否则免费层每天一千个请求）、关于训练算力的决定，以及对 Nemotron 许可证的阅读。

## Alternatives considered

- **继续建造仪器。**否决：fleet、experiments、scorekeeper、curator、program、shifts 与 observatory 都已存在；它们产出的每个读数都受限于 44 个任务与一条路由。
- **手工编写更多任务。**否决：那 44 个花了两周外加一次审计；工厂与公开套件一天就能给出数百个，而公开套件还给出任何内部任务都给不了的可比性。
- **只采用 SWE-bench Verified。**推迟到第 4 步：每个模型都见过它，其 Docker 镜像在全尺寸下装不进本机的磁盘配额，且它只测量 Python 仓库编辑；它是对另外两个套件的补充而非替代。
- **在记录在案的证据上宣称 harness 处于最先进水平。**一如既往地否决：在证书上它与一家供应商的产品循环持平，唯一一次有利于 harness 的冻结裁决没有复现。
- **丢弃 147 席位的花名册。**否决：这些定义是真实的；修正在于只点亮有记录会话占据过的席位，并停止把从未用过的路由呈现为企业的路由。

## Acceptance criteria

- `dsh-experiments` 在每个结果上命名其统计量；09-21 的 E7 配对在其下重读后不再是 `promote`；有测试覆盖零方差情形。
- `data/proving-ground/` 下有一条 polyglot 基准台记录，含操作者路由上按语言的认证计数，旁边是同一模型在排行榜上的数字及其日期。
- 一个由 `admit.mjs` 准入、至少一百个子任务的补全任务族，通过覆盖注册到基准台组合之下。
- 两个基准台驱动都通过 curator 导出；此后做出的记录在每条导出行上都带有 `curation` 块；轨迹记录携带 `stopReason`，数据集构建器掩蔽非 `completed` 的行。
- 改进日志载有 09-21 的三行及修正读数，其排程段落描述的是实际存在的 Routine。
- 一条程序记录，其交付物与账本一起提交，其发布签名晚于其证书。

## Risks

- 订阅是一个登录，由夜间队列、polyglot 运行与代码安全配对共用；速率限制与容器重启会切断运行，部分记录路径保留已跑完的部分。
- 公开套件在每个模型的训练数据之中；配对读数经得起这一点，绝对数字经不起，凡引用公开数字之处本笔记都会说明。
- 8 个环境上的聚类 bootstrap 区间很宽；诚实的后果是在套件扩大之前裁决更少，而不是区间更窄。
- Nemotron 许可证可能不是配方所要求意义上的开放权重许可证；决定等待其文本。
