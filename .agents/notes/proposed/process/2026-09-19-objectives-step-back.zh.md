# Agent Note：四个目标各自处于何处、各被什么阻塞，以及工作的顺序

Status: proposed

[English](2026-09-19-objectives-step-back.md) | 中文

## Problem

本项目有四个目标：一个让任何模型成为它所能成为的最好的 agentic coder 的 harness；通过这个 harness 进行的 agentic 软件创造；一个在 harness 经认证运行上以 RLVR 训练的约 120B 开放权重模型；以及一个 harness 依据证据改进自身的循环。两周的构建产出了这套仪器（一个带 validator 持有用例的 40 环境 bench、密封的 cell、带 bootstrap 裁决的冻结配对实验、带尝试阶梯与预算份额的 runner、program 工作流、trajectory 导出器与数据集构建器、条款门控、一个仪表板），以及 32 份已记录的运行、920 个 cell 与 844 份证书（[data/proving-ground](../../../../data/proving-ground/README.md)）。没有人写下的是：每个目标离"部分完成"究竟还有多远、哪些事实阻塞着它、余下的工作应按什么顺序进行。没有这些，精力会不断流向离手最近的东西。

## Proposal

从记录中陈述每个目标的现状，点名阻塞项，并按下面的顺序推进工作。

### 目标 1：面向任何模型的最好的 harness

现状：仪器已存在，且只在第 5 层有区分力；harness 尚未展示出相对产品自身循环的证书优势，而 32 份记录中的每一份都通过操作者的 Claude Code 登录运行同一家提供商的模型。[结果笔记](../architecture/2026-09-08-hypothesis-program-results.md)中的配对读数是：在第 3 层与第 5 层，harness 循环在证书上与产品循环持平（0 与 −0.0625，都在一次翻转的噪声底线之内），同时在 16 个密封配对中的 15 个更快，计费 token 便宜 3.4 倍；最大模型认证了每一个密封的第 5 层 cell；尝试次数有关（三次对一次，+0.375）；知识包、手艺技能、模型级联与丢弃对话记录都不增加证书，而廉价一级有界的级联（E6）以两倍成本挽回了无界级联丢掉的证书。第 5 层以下的 bench 被每个模型饱和，第 5 层被最大模型饱和。

阻塞项：单一提供商；被最大模型饱和的最高层；十六个配对下一到两次翻转的噪声底线。

下一步：密钥一到就让 bench 在第二个模型家族上运行（下文的开放权重叠加层）；增加一个最大模型不饱和的层级（带仓库与规格的多文件任务、validator 持有的隐藏用例、与第 5 层相同的准入与公平性审计）；对在第 5 层对中等模型有明确效应假设的机制逐一以冻结配对测试（E7，五次尝试对三次，正在运行；之后是验证前的自审一级，以及携带 validator 通道差异的指令）；每个实验跑两个种子，使一个读数有三十二个配对。

### 目标 2：通过 harness 进行的 agentic 软件创造

现状：program 工作流（工作树中的部门、集成、已提交的验证器、不提交即拒绝）真实运行过一次，产出了一份评估文档，从未产出过软件。

下一步：今天准备、E7 之后在路由上运行的 `csv-tools` program（三个部门、一份规格、一个 `node:test` 验证器）；随后是一个在本仓库自身门禁下为本仓库构建插件的 program，那才是这个目标真正所指的自用场景。

### 目标 3：以 RLVR 训练的开放权重模型

现状：流水线已存在并作为演练运行过：[v1 数据集折叠](../../../../data/proving-ground/datasets/2026-09-18-proving-ground-v1/README.md)中有 `dsh-trajectory/1` 格式的 750 条 trajectory，其中 521 条在 harness 路由上，奖励来自证书与一致性。它们没有一条可以训练 Daliesk 模型：全部运行在操作者的 Claude Code 登录上，而[数据使用条款](../../../../packages/governance/data-use/README.md)只把钉有允许训练之条款的会话纳入训练语料，而只有开放权重模型上的路由能携带这样的条款。因此真正要紧的语料是空的，而且本仓库没有挂接任何训练算力。

阻塞项，按顺序：一个开放权重路由的密钥（[`dsh-llm-deepseek`](../../../../packages/llm/llm-deepseek/README.md) 的 `DEEPSEEK_API_KEY`，或通过 [`dsh-llm-pi-ai`](../../../../packages/llm/llm-pi-ai/README.md) 的网关密钥）；仍未决定的基座模型；RLVR 运行本身的算力。

下一步，无密钥时：`with-deepseek` 与网关叠加层及其计划，使密钥到达后一个环境变量之内 bench 就能在开放模型上运行，而语料只从这些运行中填充；把训练配方写成一份 proposed 笔记（经认证的 trajectory 作为 SFT 预热，validator 作为同一批环境上的 RLVR 奖励，留出环境作为唯一报告的数字）。有密钥时：先跑第 2 层 fleet，再跑对中等产品模型的第 3 层冻结配对，像其他每次运行一样记录。

### 目标 4：自我改进循环

现状：每一块都已存在并运行过（冻结配对、裁决规则、组合清单、program 工作流），但每一次迭代都由人提出、通过 `pnpm run bench` 手动启动、通过编辑组合来应用。这些迭代只有横跨一份笔记、三十二份记录与十份折叠才能被看清。

下一步：`data/proving-ground/` 下的改进日志，作为每一次迭代及其裁决与决定的账本（今天）；然后是 harness 内部的提议步骤（一个部门阅读账本与 bench 的错过，写出候选叠加层与计划）；通过班次驱动的定时启动；以及通过组合清单而非手工编辑来晋升。

### 工作顺序

今天：记录 E7；开放权重叠加层、计划与无密钥时的拒绝；改进日志；运行并记录 `csv-tools` program；更新仪表板与本笔记。接下来：第 5 层之上的层级；作为冻结配对的自审一级；提议步骤。需要操作者提供：环境中的一个开放权重路由密钥、关于训练算力的决定，以及基座模型。

## Alternatives considered

- 继续在这一家提供商上跑实验直到出现效应。否决：最高层被最大模型饱和，且该提供商的任何 trajectory 都不能训练模型，所以这些运行既回答不了目标 1 也回答不了目标 3。
- 先构建下一个 bench 层级，再做开放权重路由。推迟：这个层级在第二个模型家族运行起来之后才最重要，而路由只差一个变量，层级却要数天的编写与审计。
- 现在就宣称 harness 是最先进的。否决：按已记录的证据，它在一家提供商上、在证书上与产品循环持平，并且更便宜；那是一个成本结果，不是一个能力结果。

## Acceptance criteria

- `data/proving-ground/` 下有一次在开放权重路由上、条款允许训练的运行记录，且语料折叠至少计入一条被准入的 trajectory。
- `csv-tools` program 被其验证器认证并记录为一份 program 记录。
- 改进日志载有 E7 的裁决与决定。
- 下一个 bench 层级通过公平性审计准入，并在其上完成一组冻结配对。

## Risks

- 共享订阅的速率限制与容器重启（2026-09-18 有两次）可能截断一次运行；部分记录路径会保住已运行的部分。
- 十六配对的读数容易被过度解读；笔记中的噪声底线规则依然有效。
- 把提供商记录的 trajectory 混入训练的数据集会违反条款；curator 会扣留它们，而折叠的 manifest 点名每一份来源记录，读者可以核对。
