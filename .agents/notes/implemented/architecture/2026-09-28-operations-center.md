# Agent Note: The Operations Center: one live snapshot of every agent's work

Status: implemented

English | [中文](2026-09-28-operations-center.zh.md)

## Problem

The enterprise's work runs in a dozen places on one machine: cycles started by the scheduler, shifts and intakes in their scratch directories, departments and reviewers in harness session logs and Claude Code transcripts, function gates and CI judges, the Proving Ground bench, and the operator's own background agents. Each writes its own record, and nothing read them together. The operator could not see at a glance what was working, what needed attention and why, or how much the enterprise delivered; a client demonstration had nothing live to show; and the public deck on GitHub Pages cannot reach the machine, which accepts no inbound connections.

## Decision

**One collector, one document.** [`scripts/enterprise-ops.ts`](../../../../scripts/enterprise-ops.ts) (`pnpm run enterprise:ops`) folds every source into one `OpsSnapshot`, whose fields are typed once in the deck's [`contract.ts`](../../../../apps/command-deck/deck/contract.ts); the host type-check program includes that file, so the collector and the deck read one schema. [`scripts/enterprise-ops-sources.ts`](../../../../scripts/enterprise-ops-sources.ts) holds one parser per source: cycle log step lines, the scheduler's log, the branch history's `chore(enterprise): <cycle>` commits, harness `session.jsonl` logs, Claude Code transcripts read incrementally from a byte offset, Branch CI runs and jobs from the GitHub REST API, `/proc/meminfo`, `statfs` and the `/proc` process table. The snapshot holds the agents working now (kind, seat and division when recorded, newest tool call or step, elapsed and idle time, tokens where the source reports usage), the ranked attention queue, the organisation's day (seats by division, the queue, cycles, hourly throughput, shipped commits with the Branch CI verdict that covers each), every seat for the scene, every agent run of the last 24 hours, and the last ten minutes of activity frames.

**An unreadable source is unknown, never guessed.** Every source is listed with `ok` or `unknown` and a reason; every figure counted from an unknown source is `null`, and the view prints `unknown` in its place. Liveness is read, not assumed: a shift is live while the pid in `shift.lock` is, a cycle while its process runs and its log has no closing line, and a running agent is `stuck` after twenty minutes without an event. An agent is not running once its transcript ends with its final report (a streamed transcript records that report as a text row with no stop reason, so a text row with no tool call or user row after it ends the turn), and a shift's or intake's sessions are read from its `.sessions` directory alone, because the rest of its scratch run is a clone of the branch whose committed records are history. The collector caches each transcript's fold between runs, and a finished transcript never grows again, so the state file carries `OPS_STATE_FORMAT` and a state of another format is discarded and every source read again from its start. A running cycle step takes the newest event of the shift, intake or gates it started, because the cycle log is silent while they work. Every published line passes through the transcripts' shared credential redaction ([`secret-patterns.mjs`](../../../../data/transcripts/tools/secret-patterns.mjs)), masks e-mail addresses, removes this module's wider credential shapes and cuts home and temporary paths to their last segment. The finished snapshot then passes through [`deck/host-paths.ts`](../../../../apps/command-deck/deck/host-paths.ts), which replaces every remaining absolute path of the machine with a placeholder naming what the directory was, so no path of the producing machine reaches the relay, the committed fixture or the screen.

**The attention queue ranks by severity, then recency.** Red Branch CI names its failing jobs; a failed or interrupted cycle step (from the cycle log, or from the committed cycle record once the log is gone), a stale or stopped scheduler (no cycle in 2.5 hours), a stuck agent, a shift whose committed record shows it halted at a usage limit or shipping nothing since the last shift that shipped, a shift abandoned without a record (its scratch run held by no process and silent thirty minutes), a transcript capture or operations loop that is down or late, disk and memory pressure, halted and rejected tickets and the owner's open requests each carry evidence links (a GitHub commit, run, job, ledger line, shift record or cycle record; the record's name alone, a cycle by its id, when nothing public exists) and a next action. A condition with no recorded time ranks as current.

**Every figure is dated, and every loop has a heartbeat.** Each source carries `asOf`, the moment its facts describe: the collection for what is read live, the checkout's newest fetch of the branch (`FETCH_HEAD`) for the ledger, the queue and the records, the roster's own `generatedAt`, and the cached Branch CI read; every tile and panel prints the age of the sources it counts from. The snapshot's `heartbeats` name the cycle scheduler, the transcript capture and the operations loop as `alive`, `late`, `down` or `unknown`, from the process table and each loop's newest run (the newest cycle start; the newest push the capture's log records, else the newest `chore(transcripts): live capture` commit; the loop's state file). The cycle timeline, the shift board and the shipped tickets follow in [their own note](2026-09-29-ops-cycles-and-shift-board.md). The snapshot's schema is 2, and a deck refuses any other.

**Transport reuses the feed contract.** [`scripts/harness-feed.ts`](../../../../scripts/harness-feed.ts) serves `GET /ops` and streams the activity frames on `GET /ops/events` in the run stream's frame format. The relay's feed function serves the same two paths from the rows `ingest` stores under `/ops` and the run id `ops`. [`scripts/enterprise-ops-live.sh`](../../../../scripts/enterprise-ops-live.sh) runs the collector with `--push` every `OPS_INTERVAL_SECONDS` (15) from its own checkout, fast-forwards that checkout every five minutes, holds a `flock` so one loop runs, and keeps the collector's incremental state in `/tmp`. The cycle's `enterprise:publish` step also writes `public/fixtures/ops.json`, so the Pages deck carries a snapshot no older than the last cycle.

**The deck says which mode it is in.** [`deck/ops.ts`](../../../../apps/command-deck/deck/ops.ts) reads the feed's `/ops`: younger than six producer intervals (at least 90 seconds) is `live`; otherwise the view shows the newest snapshot it could read, the feed's or the bundled one, as `recent` with its age and a replay notice; with neither it is `offline`. Live frames play one interval and five seconds behind the machine, at their recorded spacing; a recent snapshot's frames replay on a loop. The [Operations view](../../../../apps/command-deck/README.md#the-operations-view) (`/ops`, key `5`) puts the glance tiles on top, the scene in the middle, the swimlanes under it and the attention queue beside it. Its seat counts, the tile and the divisions, read the deck's roster, the one the header counts from and stamps, so the header and the view never disagree; the snapshot's own reading of the roster stands in until the deck has read one. The scene mounts behind the deck's shared `WebGLGate`, which checks for WebGL 2 before it mounts the scene, holds a scene that throws, or whose WebGL context the browser takes back, in an error boundary, and honours `?flat`; in each case this view hands it the same floor drawn as one SVG, and the gate says why, so a laptop without a GPU or a remote desktop still gets a readable view ([the gate's note](2026-09-29-command-deck-room-grade.md)).

## Alternatives considered

**Run the feed server and the existing pusher.** The pusher mirrors `/roster`, `/runs` and every run's event stream; the operations snapshot is one document the collector already writes, so pushing it directly from the loop needs no local server, and the feed server serves the same collector for a local deck.

**Stream everything over Server-Sent Events.** The relay can only forward what the machine pushed, and the machine pushes once an interval, so a stream through the relay is no fresher than the snapshot. The stream exists because a local feed can be faster, and because it lets the scene play each frame in order; the snapshot alone carries every figure.

**Read the enterprise cycle's own checkout.** It holds the ledger lines the functions step appends before its push, but it belongs to the scheduler and a reader there risks racing its pulls. The loop's own checkout, fast-forwarded every five minutes, sees everything the branch holds.

**Count cycles from their logs alone.** A container reset erases the logs; the branch history's cycle commits and the committed cycle records survive it, so the collector counts cycles from all three and marks a cycle known only from history `unknown` in the timeline.

## Consequences

The operator has one page that answers what is working, what is wrong and what to do next, and the client sees the same numbers drawn as a scene. Every number is traceable to a source the page names. The price is a second copy of machine state on a public relay: the snapshot publishes agent labels and tool descriptions, redacted but readable, and the operator's agents' task names. The relay's feed function serves reads only, so nothing a viewer sends starts work on the machine. The relay's token lives outside the repository and is erased by every container reset, so rotating it is a standing step of starting the loop ([runbook](../../../../apps/command-deck/mirror/README.md#rotating-the-token)).
