# Agent Note: The client briefing: every figure computed from the record, with its source

Status: implemented

English | [中文](2026-09-28-client-briefing.zh.md)

## Problem

The operator presents the Daliesk enterprise to executives of a client — its chief information, information-security and financial officers — and nothing in the repository was written for that audience. The Command Deck's four views are stages built for a demonstration: they show the enterprise working but state no proposition, no control a security officer can check, and no cost. The facts such an audience needs are on the branch, in the roster, the ledger, the shift, intake and cycle records, the Proving Ground's frozen pairs, the code-safety records and their ground truths, the live transcript capture, and GitHub's Branch CI runs, but they are spread over a dozen READMEs and Agent Notes written for contributors, several of them carrying claims a later record qualified. A hand-written deck would restate those numbers once and go stale by the next cycle, and an audit of an early draft found the claims such a document drifts into: that unattended cycles ship work (none had), that shipped work was verified by CI (neither shipped commit had a run of its own, and the run that contained them failed), that a client's code never leaves the review machine (the departments send it to Anthropic's model API under the operator's login, and the transcripts are published), that a person signs the releases (the engine writes the sign-offs), and recall stated without its matching rule or its denominators.

## Decision

**One builder computes every figure, and the page only formats.** [`scripts/enterprise-briefing.ts`](../../../../scripts/enterprise-briefing.ts) (`pnpm run enterprise:briefing`) reads the committed inputs, and the Branch CI runs of the branch and the repository's visibility from GitHub's REST API, and writes [`apps/command-deck/public/fixtures/briefing.json`](../../../../apps/command-deck/public/fixtures/briefing.json). Each figure is `{ value, source: { paths, urls?, computation } }` or `{ value: null, unknown, source }`: the paths or pages it was read from and one sentence saying how. Seats and divisions come from the roster; tickets by status, tokens and seconds from the ledger; shifts from their records; frozen pairs from each record's `result.json`, with a re-read fold's reading attached where one exists; recall from each code-safety record's findings against its target's ground truth by the rule `compare.mjs` applies, a finding within three lines of an issue's lines or of an `alsoAt` location, and the three-tier comparison recomputed the same way; the governance figures from the records themselves (sessions pinning `dataUse/terms`; the approvals a shift or intake record holds, either `signoff/recorded` events in its session logs or the `decisions` its `result.json` states, each with the principal's id and declared kind; a reviewer's `tool/call` events; the review record of [review independence](2026-09-29-enterprise-review-independence.md), every review with the reviewer its ledger line names and the route and model its log's request was sent with). The input sets it read are listed with their SHA-256. The deck's `/briefing` route imports the file at build time and renders it.

**The pilot is set out unit by unit.** A unit is one run of the cycle script, named on the branch by a cycle commit's subject, a ledger function line, a cycle record under `data/enterprise/cycles/`, or a cycle log the live capture holds, or one shift record outside every cycle. Per unit the builder states who started it and on what evidence: the starter a cycle record states, which the cycle script records as scheduler when `scripts/enterprise-scheduler.sh` is its parent process and operator otherwise; for a cycle whose record states none, the scheduler, when the captured scheduler log reports running the cycle or announced the slot the cycle is the first to start in; the operator, for a cycle that started before `scripts/enterprise-scheduler.sh` reached the branch and for any shift outside a cycle; unknown otherwise. It then counts the tickets the unit's shift records name, the ledger lines of those shifts by status with the checks that failed, the named tickets no line records, and the lines' tokens; a unit that ran a shift with no record on the branch, or whose steps nothing states, has attempted and lost counts of unknown. The captured logs are read from the live capture's gzip chunks; a step time an older cycle script logged as a time of day is placed after the previous step. The page's first section and the summary report shipped tickets by starter, so the record says which work the operator started and which the scheduler did.

**CI verdicts name what each run tested.** Branch CI runs on the tip of each push. For each shipped commit the builder reads the newest run on exactly that commit, the containing run (the earliest run whose head contains it, `git merge-base --is-ancestor`, the push that carried it) with its jobs, the run on the shift's base commit, and the first successful run containing the commit, and splits the containing run's failed gates — parsed from each failed job's log by the functions runner's `parseJobLog` — into those the base run already failed and those the push introduced. The page labels the two readings "Exact commit" and "Containing run" and does not call shipped work verified. A run list that cannot be read leaves every CI figure unknown with the reason; one shipment whose runs cannot be read leaves that shipment alone unknown.

**Data handling is stated as it is.** The governance section opens with a data-flow diagram: the branch cloned onto the review machine; every department, reviewer and intake request going to Anthropic's model API under the operator's Claude Code login, file contents included; the shift records' session logs committed with each shift; the live capture pushing the operator's and the departments' transcripts every five minutes to the repository, whose visibility the builder reads from GitHub. Under it the page lists what an engagement needs before a client's code is read: an Anthropic API organisation under a data processing agreement with zero data retention, a private repository for the records, and data-use terms pinned on every session. The sign-off row reads both forms the records hold: the sign-off events the engine wrote into the older shift and intake records, milliseconds apart as the program opened, under a principal labelled with the kind `human`, and the decisions newer records state under the engine's machine principal; it states that no person signs a change before it is pushed.

**Unknown is a value, never an estimate.** A figure whose input is missing is written as unknown with its reason, and the page prints `unknown`. The currency cost of a ticket is unknown by construction: the shifts run on a flat-rate subscription route and no record carries a price.

**A claims register gates the page.** [`scripts/enterprise-briefing-claims.ts`](../../../../scripts/enterprise-briefing-claims.ts) renders the page with React's server renderer in a child process ([`apps/command-deck/scripts/render-briefing.ts`](../../../../apps/command-deck/scripts/render-briefing.ts) under tsx with `apps/command-deck/tsconfig.render.json`, which compiles the deck's JSX to the automatic runtime), reads it with jsdom, and splits every paragraph, list item, table row and KPI into sentences, each with the notes it cites, else its paragraph's, else the heading's above it. The builder refuses to write the register, and exits 1, when the page's text, notes and hover cards included, contains "unattended cycles ship", "CI-verified", "never leaves" or "(human)" in any case, or when a sentence states a number with no note; otherwise it writes [`apps/command-deck/public/fixtures/briefing-claims.md`](../../../../apps/command-deck/public/fixtures/briefing-claims.md): every sentence with its section and notes, then every note with its computation and what it read. The register sits beside `briefing.json`, so the cycle commits the two together, and [`scripts/enterprise-briefing-claims.spec.ts`](../../../../scripts/enterprise-briefing-claims.spec.ts) fails in Branch CI when the committed register is not the rendering of the committed page.

**The page is a document inside the deck.** `/briefing` is a Server Component over the imported file with three client parts: the theme toggle, the print button and a key guard that holds back the deck's stage keys while the briefing is open. Its stylesheet, [`components/briefing/briefing.css`](../../../../apps/command-deck/components/briefing/briefing.css), is scoped under `.bf`; the rules that hide the deck's header and footer and let the page scroll apply through `:has([data-briefing])`, so no shared shell file changes. Eight sections — where the pilot stands, the operating model, the pilot record, measured quality, data handling with governance and audit, economics, limits and risks, the roadmap with a proposed engagement — each cite their figures in reading order and end with numbered source notes, folded on screen and printed open; a label shows its note on hover or focus. Charts are HTML and CSS on one scale each, directly labelled, with colours validated for both themes. The print stylesheet lays out A4 or Letter (`@page { size: auto }`), starts each section on a new page, prints page numbers in the margin boxes and the source notes under each section, and forces the light tokens.

**The publish step runs the builder.** `pnpm run enterprise:publish` runs `enterprise:briefing` last, so the cycle regenerates the briefing and its register without a change to `scripts/enterprise-cycle.sh`, and the cycle's commit of `apps/command-deck/public/fixtures` carries both. The default run writes nothing outside that directory. `--summary` renders the one-page executive summary pair, `docs/client/daliesk-executive-summary.md` and its Chinese side, from the same briefing ([`scripts/enterprise-briefing-summary.ts`](../../../../scripts/enterprise-briefing-summary.ts)) and `--check-summary` compares the committed pair with that rendering. The summary and the claims modules import nothing from the builder at run time, because the builder loads them while its own top-level evaluation is pending.

**English only on the page.** The deck has no locale layer (`<html lang="en">`); the French executive summary belongs to the code-safety report the program writes for its target, which the page cites. The repository's own bilingual rule applies to the summary, which is rendered in English and Chinese from one briefing.

## Alternatives considered

**Figures typed into the page.** Fastest to write and wrong within a cycle: the seat, ticket, cycle and CI figures change every two hours, and a number without its computation cannot be audited. Rejected for the builder.

**The page computes from the raw fixtures at runtime.** The deck already ships `roster.json` and `enterprise.json`, but the benchmark, code-safety, session-log, captured-log and CI figures are not in any fixture, and computing them in the browser would ship 400 MB of records and the GitHub API reads to every viewer. The builder runs where the records are.

**Who started a cycle from its start time alone.** The scheduler starts cycles at 13 minutes past every even UTC hour, so the minute would suggest the starter, but a hand-started cycle can fall on that minute and a scheduled one waits for a running cycle. The builder reads the starter the cycle record states, else the scheduler's own log and the scripts' history, and says unknown when none covers a cycle.

**Parsing the account of lost work into counts.** `data/transcripts/LOSSES.md` names the tickets the reset interrupted, from the operator session's log. It is prose written for people; the pilot table leaves those counts unknown and cites the account.

**Cache CI verdicts from the previous build when the API fails.** A completed run's conclusion does not change, so a cache would be sound, but it would make the output depend on the previous output and hide an unreadable API behind stale data. Unknown with the reason is the honest state, and the next cycle reads it again.

**Rendering the register from the Next.js static export.** It reads exactly what ships, but needs a full deck build, which neither the cycle nor the unit tests run. The server renderer produces the same markup for the page's body in seconds.

**A route group with its own root layout for `/briefing`.** It would escape the shell cleanly but moves every other route into a group, rewriting files other work on the deck is changing. The scoped `:has()` rules reach the same result from the briefing's own files.

**A French edition of the page.** The client may read French, and the code-safety report already leads in French. The deck localizes nothing; adding a locale layer for one route would be the deck's first and belongs with the deck's other views.

**Generating the executive summary on every publish.** It would keep the summary current, but the cycle commits only `data/enterprise` and the deck's fixtures, so a regenerated summary would leave the cycle's checkout dirty and stop the next cycle. The summary is a dated snapshot, regenerated with `--summary` when it is sent.

## Consequences

The briefing states the enterprise's weaknesses with the same prominence as its strengths because they come out of the same computation: which units shipped and who started them, what each CI run tested, where the data goes, who signs, which sessions pin terms, which work runs outside the sandbox, and how concentrated the model routes are. When the record changes, the page, the register and the pilot table change at the next cycle, and a sentence that the new data would leave without a source, or a forbidden phrase, stops the publish step instead of shipping.

The builder reads every session log of the committed records, about 400 MB, and the captured cycle logs in a few seconds, and renders the page once in a child process. The briefing file changes with every Branch CI run, so the cycle's deck commit changes it every cycle, with the register.

The prose around the figures is templated from the data where the data can change: the units, the shipped tickets, the CI verdicts, the sign-off principal and kind, the repository's visibility and the counts. A statement tied to one event — the translation-pairing failure the first shipped ticket introduced, the shift a container reset erased — is cited to the record that states it and stays true of that event. The statements about what an engagement needs are requirements, not records, and the register lists them without a note.

## Verification

- `pnpm exec vitest run scripts/enterprise-briefing.spec.ts` computes every figure family on fixture data: occupancy by division, ticket status from the newest line, shift durations, the pilot's units with their starters (a recorded starter, a captured scheduler slot, a scheduler run line, a cycle before the scheduler existed, shifts outside every cycle, a recorded cycle that ran no shift) and their attempted, shipped, failed, lost and token counts, arm labels, certificates per arm and the re-read fold, recall within three lines with `alsoAt`, the three tiers, pinned terms, sign-off events and recorded decisions with the principal's kind across shift and intake records, reviewer tool calls, the exact-commit, containing, base and first-green CI runs with introduced and pre-existing gates, the repository's visibility, the unknown handling for an unreadable API and for one shipment, the absent inputs, byte-identical serialization, the digest grouping, and the summary pair's matching structure with none of the forbidden phrases; it also recomputes the committed comparison's scores from the committed findings and reassembles the committed scheduler log.
- `pnpm exec vitest run scripts/enterprise-briefing-claims.spec.ts` reads sentences, their notes and the notes they inherit from a synthetic page, refuses a forbidden phrase inside a hover card and an uncited number, and renders the committed page to its committed register with no problem.
- `DECK_STATIC=1 NEXT_PUBLIC_BASE_PATH=/deepseek-harness pnpm --dir apps/command-deck run build` exports `/briefing`; Playwright over headless Chromium captured it at 1440×900 and 390×844 with no horizontal overflow and no page error, and printed it to PDF on A4 and Letter.
- `pnpm run typecheck`, `pnpm run lint`, `pnpm run knip` and `pnpm run doc-sync` cover the builder, the page, the READMEs, the summary pair and this note.
