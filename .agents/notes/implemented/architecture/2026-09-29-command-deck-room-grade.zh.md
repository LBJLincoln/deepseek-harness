# Agent Note: 指挥台在没有 WebGL 的浏览器中依然可用、无需键盘即可演示，并用人能读懂的名字称呼运行

Status: implemented

[English](2026-09-29-command-deck-room-grade.md) | 中文

## Problem

指挥台通过一个公开链接向客户展示。它的每个视图都用 three.js 绘制舞台，而 three r169 只创建 WebGL 2 上下文。公司笔记本、远程桌面会话和加固过的浏览器常常根本不提供 WebGL。在这样的机器上，`WebGLRenderer` 会在画布的 layout effect 中抛出异常，指挥台里没有任何地方接住它，Next.js 便用它不带品牌的 “Application error” 页面替换整页，页头和面板一并消失。场景内部的任何运行时错误也会导致同样的结果，因为 react-three-fiber 会把每个场景错误重新抛进 React 树。客户在一台受限的笔记本上打开链接，看到的是一张死页面。

指挥台在演示它的会议室里也不合格。它最浅的灰色对比度约为 4:1，许多文字只有 9 到 11 px，经投影仪一放就模糊不清；页头超出笔记本屏幕；严重程度只用颜色表示；发现表和记录里的行只能用鼠标打开。每个演示序列都要用按键启动，在平板上或讲台旁的演示者无法启动或操控它。相机按 1600×900 的舞台取景，在笔记本上近乎正方形的舞台或竖握的手机上会裁掉图、流水线和城市，而轨道控制还会吞掉每一次滑动，页面无法越过舞台滚动。场景上的标签相互重叠，也压在视图标题上。标题打印的是运行的目录名，例如 `2026-09-19-nodegoat-2`；事件流一行一条地列出数百次工具调用，并把证书打印成原始 JSON；已发布花名册中有两个分部没有调色板颜色，画成了同一种灰；已发布的 fixture 还带着记录它们的机器上的绝对路径。

## Decision

**每个舞台都挂载在同一道门之后。** `components/three/WebGLGate.tsx` 导出 `WebGLGate`，每个视图都用它包裹自己动态导入的舞台。在第一次客户端渲染时，这道门向一块临时画布请求一个 `webgl2` 上下文，随即释放它，并在本次页面加载内记住结果。拿不到上下文时，场景及其要加载的 three.js 代码块都不会挂载：舞台显示该视图在 `public/posters/<view>.jpg` 中的静帧（按 `NEXT_PUBLIC_BASE_PATH` 解析），并附一行说明：面板保有完整记录。面板、页头和每个标签页照常工作，因为舞台之外没有任何东西依赖画布。

**这道门也是舞台的错误边界。** 类组件 `SceneBoundary` 把舞台挂载之后抛出的任何错误限制在舞台之内：视图显示同一张静帧、错误信息，以及一个重新挂载场景的按钮。`Stage` 把丢失的 WebGL 上下文当作这样的错误抛出，因为浏览器收回上下文后画布会一直是黑的，three.js 不会自行恢复；监听器会忽略 react-three-fiber 在正常卸载半秒后强制造成的那次丢失。

**舞台之外的错误保留外壳。** 视图抛出异常时，`app/error.tsx` 在根布局之内用指挥台自己的错误页（`components/shell/DeckError.tsx`）替换该视图，页头、导航和页脚都保留。外壳本身抛出异常时，`app/global-error.tsx` 在它自己的页头下显示同一个错误页，页头带有指向每个视图的普通链接。

**静帧是真实场景的截图。** 每一张都只截取舞台，从静态导出以 1600×900 在已提交的 fixture 上捕获，并隐藏了叠加的文案，因此视图自己的标题不会出现两次。它们是每张不到 100 KB 的 JPEG 文件，因为场景的胶片颗粒和辉光会让同一帧的 PNG 大上许多倍。

**每个视图共用一种机制。** [运营视图](2026-09-28-operations-center.md)上线时自带探测、错误边界和上下文监听，围绕一张画成平面 SVG 的大厅；它们已并入这道门。门接受一张静帧（`poster`），或视图用自己的数据画出的图（`flat`），`/ops` 传入它的平面大厅。运营视图引入的地址参数 `?flat` 现在要求每个舞台都显示其替身，演示者可以在有 WebGL 的机器上预演回退。

**演示无需键盘。** 页头的 Present 菜单（`components/shell/PresentMenu.tsx`）启动冷开场、导览巡游、聚焦和发现巡览，`?present=open|tour|focus` 则在读到花名册后从链接启动其中之一。巡览运行时，`components/shell/TourControls.tsx` 显示当前位置，并提供上一个、下一个和结束；发现巡览的位置与视图巡览的位置一起存在指挥台的 store 中，所以控制栏、方向键和视图推进的是同一个巡览。轻触永远不会结束巡览，点击演示控件也不会。

**在会议室后排也能看清。** 文字不小于 12 px，大写标签为 11 px，`--ink-3` 为 `#8494b8`，在面板上的对比度为 6.3:1。宽度低于 1100 px 时页头折行。每个严重程度都在颜色旁以文字标出，每一行可点击的行都能获得焦点，并在按 Enter 或空格时打开（`components/shell/activate.ts`），同时显示 `:focus-visible` 焦点框。

**在触屏上，舞台让页面保持可滚动。** 在粗指针设备上，每个舞台的轨道控制处于关闭状态，舞台的外层元素取 `touch-action: pan-y`，因此滑动会滚动页面，轻点仍然选中；舞台的 **Explore 3D** 按钮（`components/three/explore.ts`）把手势交给轨道控制，直到观看者要回页面滚动或离开该视图。

**相机按舞台的宽高比取景。** `components/three/framing.ts` 计算在给定宽高比下相机要站多远才能容纳主体，每个相机装置都把设计好的距离乘以该距离与 `DESIGN_ASPECT`（镜头构图时所用的 1600×900 舞台）下距离之比。更宽的舞台保持原设计的镜头；更窄的舞台则让相机后退。

**标签彼此避让。** `components/enterprise/labels.ts` 为每个舞台提供一个 `LabelField`：每帧清空标签已占的矩形，每 500 ms 测量一次视图指定的舞台文案（标题、提示和卡片）。每个标签在附近几个位置中取第一个空闲的，否则取重叠最少的，并保持该位置直到另一个位置明显更好，因此标签不会闪动。手机上隐藏城市的街区名，因为在那个宽度下它们无法并排放下。

**用人能读懂的名字称呼运行。** `deck/display-name.ts` 根据已知审查主题表和运行类型，把运行的目录名和时间变成 `OWASP NodeGoat · security review · 19 Sep 2026 · 20 min`，实验的分组写在括号里；标题、标题卡、运行选择器和记录卡片都使用它，id 保留在页脚中。审查目标以其检出目录的名称称呼，工作流视图把程序的根会话称为 `Program`，而不是用它的摘要。事件流把每一段连续的工具调用和步骤折叠为一行，列出其中最常见的调用，**Show every step** 则逐条列出；feed 把证书所在行组合为 `certificate · 3 of 3 checks pass`（`scripts/harness-feed.ts` 中的 `certificateLine`），指挥台把记录收在一个展开项后面。

**代码安全数字附带其条件。** 依据[面向客户的陈述](../process/2026-09-29-code-safety-client-claims.md)，Benchmark 面板和简报说明每个对比层只运行了一次，把企业的发现称为行级验证（line-verified）并给出定义，把落在任何已记录问题之外的发现计为未分诊的候选，按实测给出重跑的重合度，并把使用诊断检查清单时读到的召回标为样本内；代码安全面板和简报的数据处理段落通过 `deck/repository.ts` 链接[数据处理页面](../../../../docs/client/data-handling.md)。

**分部颜色以已发布的花名册为准。** `deck/palette.ts` 中的 `DIVISION_COLOR` 恰好以花名册中的分部为键；某个分部没有颜色、两个分部共用一种颜色，或调色板键入了花名册已不再定义的分部时，`tests/palette.spec.ts` 都会失败。

**不发布任何主机路径。** `deck/host-paths.ts` 把记录机器上的绝对路径改写为占位符（`<repo>`、`<targets>`、`<scratchpad>`、`<tmp>`、`<home>`）。feed 的折叠把它应用于所转发的每个工具结果、指令和证书；`scripts/snapshot-fixtures.ts` 把它应用于写出的每份载荷；运营收集器把它应用于自己的快照；指挥台把它应用于读到的任何快照。已发布的 fixture 中出现主机路径时，`tests/fixtures.spec.ts` 会失败。

## Alternatives considered

**为每个场景做一个 2D 渲染。** 用 canvas-2D 或 SVG 版本的图、流水线、城市和工作流，可以在没有 WebGL 时保持视图可交互，代价是每个视图多一个必须与第一个保持同步的渲染器。面板已经保有场景展示的每一项事实，所以一张静帧加上面板就能以很小的代价满足需要。

**让 `app/error.tsx` 接住场景故障。** 没有门的边界时，抛出异常的场景会到达路由的错误边界，它替换整个视图，面板也随之消失。把故障限制在舞台之内能让记录保持可读，而 `app/error.tsx` 仍是舞台之外故障的兜底。

**在服务端探测 WebGL，或在探测返回之前先渲染静帧。** 服务端无法知道观看者的浏览器；先画静帧则会让它在每个随后挂载的场景下闪现一下。探测只需一帧，这一帧里门什么也不画。

**PNG 静帧。** 场景带有胶片颗粒和辉光，PNG 对此压缩得很差；四张舞台尺寸的 PNG 静帧要占好几兆字节，而需要它们的恰恰是受限的机器。

**为标签使用布局求解器。** 力导向或全局布局能把标签排得更紧凑，但每帧都有开销，并且任何一个标签移动时其他标签也会跟着动。每个标签只在几个固定位置中选择，并优先保留当前位置，能让标签保持静止，这在投影屏幕上更重要。

**在记录中重命名运行，或手工清理 fixture。** 记录和 fixture 由机器写出，并在每次快照时被重写；直接施加在文件上的命名或清理会在下一次快照时丢失。名字是记录的一种呈现，属于指挥台；清理则放在文本首次被读取的地方，因此之后的每次快照都是干净的。

## Consequences

公开链接在任何浏览器中都能打开一个可用的指挥台：没有 WebGL 时，每个视图是其场景的一张静帧，旁边是完全可用的面板；场景故障只让场景本身停下。静帧展示的是已提交 fixture 的静止画面，而不是正在跟随的运行，也不响应点击；舞台上的说明指出面板才是记录。场景的外观改变时必须重新捕获静帧，否则它们会展示一个比线上更旧的指挥台。

演示者可以在平板或讲台旁操作指挥台，客户也可以在手机上跟随。新审查的目标在 `deck/display-name.ts` 认识其主题之前，按首字母大写的目录名显示。花名册新增的分部在获得颜色之前会让 `tests/palette.spec.ts` 失败；只有 `deck/host-paths.ts` 不认识其根目录的新一类主机路径才会进入 fixture，而 `tests/fixtures.spec.ts` 会报告它。
