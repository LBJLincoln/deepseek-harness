# Agent Note: 指挥台在没有 WebGL 的浏览器中和场景抛出异常时依然可用

Status: implemented

[English](2026-09-29-command-deck-room-grade.md) | 中文

## Problem

指挥台通过一个公开链接向客户展示。它的每个视图都用 three.js 绘制舞台，而 three r169 只创建 WebGL 2 上下文。公司笔记本、远程桌面会话和加固过的浏览器常常根本不提供 WebGL。在这样的机器上，`WebGLRenderer` 会在画布的 layout effect 中抛出异常，指挥台里没有任何地方接住它，Next.js 便用它不带品牌的 “Application error” 页面替换整页，页头和面板一并消失。场景内部的任何运行时错误也会导致同样的结果，因为 react-three-fiber 会把每个场景错误重新抛进 React 树。客户在一台受限的笔记本上打开链接，看到的是一张死页面。

## Decision

**每个舞台都挂载在同一道门之后。** `components/three/WebGLGate.tsx` 导出 `WebGLGate`，每个视图都用它包裹自己动态导入的舞台。在第一次客户端渲染时，这道门向一块临时画布请求一个 `webgl2` 上下文，随即释放它，并在本次页面加载内记住结果。拿不到上下文时，场景及其要加载的 three.js 代码块都不会挂载：舞台显示该视图在 `public/posters/<view>.jpg` 中的静帧（按 `NEXT_PUBLIC_BASE_PATH` 解析），并附一行说明：面板保有完整记录。面板、页头和每个标签页照常工作，因为舞台之外没有任何东西依赖画布。

**这道门也是舞台的错误边界。** 类组件 `SceneBoundary` 把舞台挂载之后抛出的任何错误限制在舞台之内：视图显示同一张静帧、错误信息，以及一个重新挂载场景的按钮。`Stage` 把丢失的 WebGL 上下文当作这样的错误抛出，因为浏览器收回上下文后画布会一直是黑的，three.js 不会自行恢复；监听器会忽略 react-three-fiber 在正常卸载半秒后强制造成的那次丢失。

**舞台之外的错误保留外壳。** 视图抛出异常时，`app/error.tsx` 在根布局之内用指挥台自己的错误页（`components/shell/DeckError.tsx`）替换该视图，页头、导航和页脚都保留。外壳本身抛出异常时，`app/global-error.tsx` 在它自己的页头下显示同一个错误页，页头带有指向每个视图的普通链接。

**静帧是真实场景的截图。** 每一张都只截取舞台，从静态导出以 1600×900 在已提交的 fixture 上捕获，并隐藏了叠加的文案，因此视图自己的标题不会出现两次。它们是每张不到 100 KB 的 JPEG 文件，因为场景的胶片颗粒和辉光会让同一帧的 PNG 大上许多倍。

**每个视图共用一种机制。** [运营视图](2026-09-28-operations-center.md)上线时自带探测、错误边界和上下文监听，围绕一张画成平面 SVG 的大厅；它们已并入这道门。门接受一张静帧（`poster`），或视图用自己的数据画出的图（`flat`），`/ops` 传入它的平面大厅。运营视图引入的地址参数 `?flat` 现在要求每个舞台都显示其替身，演示者可以在有 WebGL 的机器上预演回退。

## Alternatives considered

**为每个场景做一个 2D 渲染。** 用 canvas-2D 或 SVG 版本的图、流水线、城市和工作流，可以在没有 WebGL 时保持视图可交互，代价是每个视图多一个必须与第一个保持同步的渲染器。面板已经保有场景展示的每一项事实，所以一张静帧加上面板就能以很小的代价满足需要。

**让 `app/error.tsx` 接住场景故障。** 没有门的边界时，抛出异常的场景会到达路由的错误边界，它替换整个视图，面板也随之消失。把故障限制在舞台之内能让记录保持可读，而 `app/error.tsx` 仍是舞台之外故障的兜底。

**在服务端探测 WebGL，或在探测返回之前先渲染静帧。** 服务端无法知道观看者的浏览器；先画静帧则会让它在每个随后挂载的场景下闪现一下。探测只需一帧，这一帧里门什么也不画。

**PNG 静帧。** 场景带有胶片颗粒和辉光，PNG 对此压缩得很差；四张舞台尺寸的 PNG 静帧要占好几兆字节，而需要它们的恰恰是受限的机器。

## Consequences

公开链接在任何浏览器中都能打开一个可用的指挥台：没有 WebGL 时，每个视图是其场景的一张静帧，旁边是完全可用的面板；场景故障只让场景本身停下。静帧展示的是已提交 fixture 的静止画面，而不是正在跟随的运行，也不响应点击；舞台上的说明指出面板才是记录。场景的外观改变时必须重新捕获静帧，否则它们会展示一个比线上更旧的指挥台。
