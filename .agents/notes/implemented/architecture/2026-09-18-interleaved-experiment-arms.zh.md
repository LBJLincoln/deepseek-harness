# Agent Note：交错运行的实验 arm

Status: implemented

[English](2026-09-18-interleaved-experiment-arms.md) | 中文

## Problem

一场实验先把 baseline arm 整个跑完，再跑 candidate arm，形式是在相同环境与相同重复索引上的两次 `ctx.fleet.run` 调用。随后的配对消除了环境方差，因为一次重复只有在两个 arm 都报告它时才进入统计，但它消除不了两次调用之间发生变化的东西：在一份共享订阅上，排队情况、可用容量，以及一条模型路由背后的构建版本，都会在一天之内移动，而每一次这样的移动都会整个落在后跑的那个 arm 上。2026-09-08 记录在 `data/proving-ground/` 之下的每一场实验，其两个 arm 相隔 30 到 80 分钟运行，因此那些 delta 每一个都带着一个未被度量的「arm 与小时」项，而[结果说明](../../proposed/architecture/2026-09-08-hypothesis-program-results.md)把消除它的那一片工作排进了队列。

## Decision

`FleetService.runPaired(first, second)` 把两份计划作为一个批次运行，并按给出计划的顺序为每份计划返回一份报告。它对每份计划做与 `run` 完全相同的校验；当两份计划选出的环境不同或要求的重复次数不同时，以 `FLEET_INVALID_PLAN` 拒绝这一配对；并以环境为主序、其次重复序号、再次计划来排列 cell，因此两份计划在同一个环境、同一个重复序号上的 cell 彼此相邻，且两份计划共用同一个已配置的 `maxConcurrent` 池。两个入口都先准备一份计划，为每个 cell 填入一个结果槽位，并从同一条记录上折叠出报告，因此每份报告——它的 group、按它自己的计划顺序排列的 cell、它的排行榜、它的 spend——以及它的 `fleet/cell` 事件、它的路由熔断器与它的 token 上限，都与该计划自己的 `run` 产出的一致。`ExperimentService.run` 像以前一样构造两个 arm 的计划，并发起一次 `runPaired` 调用，因此摘要、两个 arm 的 stamp group、折叠、`ExperimentResult` 以及每一份已存储结果的格式都不变，不同的只是一个 cell 在什么时候运行。

## Alternatives considered

- **在实验服务里交替两个 arm，每个 cell 发起一次 fleet 调用。** 拒绝：group、台账的 token 上限与路由熔断器、赋予 cell 其重复序号的枚举，以及工作区保留策略，全都是按计划生效的，因此逐 cell 的计划会把它们每一个都重新开始，两个 arm 也会失去结果所陈述的按 arm 的账目。
- **把两个 arm 作为一份在 `models` 中指名两条路由的 fleet 计划运行。** 拒绝：一份计划携带一个 group、一个 implementer 与一条阶梯，而两个 arm 各自携带自己的这三者，并且正是靠各自的 group 在会话日志中被找到；那一份报告还会把两个 arm 折叠进一块排行榜与一份 spend，而这不是折叠所读取的东西。
- **在两个 arm 之间随机排列 cell 顺序。** 拒绝：随机顺序只在期望意义上消除该混杂，并且同一个被冻结摘要的两次运行会排出不同的顺序，而成对的顺序是精确的、确定的，也是该设计本就假定的最紧配对。
- **保持顺序不变，在折叠中对小时做校正。** 拒绝：折叠会需要一个没有任何东西在度量的提供方漂移模型，而更便宜的修法是不再制造这一项。

## Consequences

一个 arm 不再与它运行所处的那个小时混杂在一起：批次开始与结束之间提供方一侧的变化如今落在两个 arm 身上，配对 delta 度量的是 arm 本身。一次配对运行在途的 cell 不比单次运行更多，因为两份计划共用同一个池；两份计划彼此不匹配的配对会在任一计划运行任何 cell 之前被拒绝，因此一场实验绝不会因不匹配而只花掉一半。`run` 对它的另一个调用方——每个时段运行一份计划的班次驱动器——保持不变。指名多条路由的计划，其 cell 按配对顺序而非以路由为主序启动，这正是配对所换取的代价；报告仍按计划顺序列出它们。

## Testing

fleet 包的测试覆盖两份计划 cell 的成对顺序、每份报告与同一份桩脚本上两次独立 `run` 调用产出的结果深度相等、不匹配的配对在任何 cell 运行之前被拒绝、跨两份计划的单一有界池且一对中的两个 cell 同时在途，以及按计划生效的路由熔断器与 token 上限。experiments 包的测试断言每场实验一次配对调用，且结果与分别构造的两份桩报告折叠所得相等。无密钥的 experiment e2e 在 `maxConcurrent: 2` 下通过一份真实组合运行两个 arm。
