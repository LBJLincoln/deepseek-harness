# Agent Note: A route limit halts the run instead of failing its cells

Status: implemented

English | [中文](2026-09-27-route-limit-halts-the-run.zh.md)

## Problem

At 17:47 UTC on 2026-09-27 the subscription behind the `claude-code` route reached its session limit while the polyglot fleet `polyglot-all-sonnet` was running. From then on every model call on the route returned the product's notice, and the route logged each one as a step failure under `TRANSPORT`: `llm-claude-code: the query failed: success api_error stop_sequence You've hit your session limit · resets 8:20pm (UTC)` — 1,746 such `assistant/chunk` finishes across the run, each retried twice by the default policy because `TRANSPORT` is retryable. The runner then did what it does after any turn: it validated the untouched workspace, recorded a failed `verification/run`, issued a directive, and delivered the next attempt to the same wall, three times per cell. The fleet's route breaker counts consecutive cells whose run threw, and none threw — every cell came back as a report with `certified: false` — so the fleet kept scheduling: 97 of 116 cells were recorded as failed certificates and 19 certified. A paired experiment (14 of 48 cells done) and a code-safety program run were cut the same way. A usage limit is a state of the route — nothing on it can succeed until the window resets — and a record that counts it as a task outcome is false: the leaderboard rows, the scoreboard rates, the trajectory rewards, and the experiment verdict all read the wall as the model's failure.

## Decision

The refusal is classified once, at the seam, and every layer above stops on the code rather than on the text.

**The seam's `QUOTA` covers a usage window and carries its reset.** `QUOTA_EXCEEDED_CODE` in [`packages/llm/llm/src/error.ts`](../../../../packages/llm/llm/src/error.ts) already named exhausted quota, balance, credits, budget, and usage limits, and `isQuotaExceededError` already read `usage limit reached` wording from other providers, so the product's notice family joins that classifier (`You've hit your … limit`, `You've reached your … limit`, `out of usage credits`, `team's shared budget`) instead of a second code with the same contract. The contract now states what a scheduler may rely on: the route serves nothing until the provider's own state changes, so the first `QUOTA` on a route stops the route; and `providerRetryAfterMs` carries the delay until the stated reset. `quotaResetDelayMs(detail, now)` reads a reset stated as a UTC clock time (`resets 8:20pm (UTC)`, minutes optional, 24-hour accepted) as the next such instant after `now`; a notice in another zone, or with no clock, yields no delay. `quotaRetryAfter(detail, now, resetsAtSeconds?)` turns a provider-stated reset instant in unix seconds, else that clock time, into the `providerRetryAfterMs` option — empty when neither is still ahead of `now` — so both Claude Code packages spread one seam helper into their failure instead of each computing the delay. `QUOTA` stays outside the default retryable set, so a refused step fails once instead of after two pointless retries.

**The Claude Code route reads the structured signal first and the notice last.** [`resultFailure`](../../../../packages/llm/llm-claude-code/src/response.ts) takes the query's last `rate_limit_event`: one with `status: 'rejected'` is the refusal, and its `resetsAt` (unix seconds, per the CLI's own schema) is the reset. Without one, a result whose text is the notice is the refusal, and the reset comes from the clock time. The recorded logs prove only the second signal: the route kept `result` and `assistant` messages and dropped every other message, and the message it logged joins `subtype`, `terminal_reason`, `stop_reason`, and `result` — `success api_error stop_sequence <notice>` — so `api_error_status` and the rate-limit event are handled from the pinned SDK's declared types and could not be confirmed from the run. Both signals are therefore read, the event outranking the text because it is the product's own statement rather than its rendering. `api_error_status` is carried as the failure's `status` on every success-marked-failure result; a 429 with neither signal is `RATE_LIMIT`, which the policy repeats, rather than `TRANSPORT`. A refusal the SDK raises by throwing is classified from its rendered chain the same way. [`dsh-subagent-claude-code`](../../../../packages/subagent/subagent-claude-code/src/run.ts) applies the same two signals to the child CLI's result and throws the seam's `LlmError('QUOTA')`, and [`settleRunResult`](../../../../packages/subagent/subagent/src/out-of-process.ts) carries an `LlmError`'s facts, or any `HarnessError`'s code and message, as the new `SubagentResult.failure`, so a delegated attempt's outcome states its code the way a route turn's `turn/end` does. The two Claude Code packages may not depend on each other, so the shared wording lives in the seam and each package keeps only its own SDK reading.

**The runner ends the run on the code.** After each delivered turn of a route attempt — work and self-review alike — [`EnvironmentRunner`](../../../../packages/improvement/environment-runner/src/index.ts) reads the `turn/end` that turn ended with; after each delegated child it reads `result.failure`. A `QUOTA` failure appends one `environment/route-limit { attempt, provider, model, failure, resetsAt? }`, with `resetsAt` the failure's delay measured from the turn's end or the child's settlement, flushes the session, and throws `EnvironmentRouteLimitError` under `ENVIRONMENT_RUN_ROUTE_LIMIT`, carrying the route, the attempt, the failure, and the reset. The cut attempt is never validated; the runs recorded before it stay. Any other turn failure is validated as before. The delegation record gains `failure` for every coded child failure.

**The fleet walls the route on the first such cell.** [`FleetService`](../../../../packages/improvement/fleet/src/index.ts) keeps a `RouteWalls` registry per run beside the breaker and the ceiling: the first `EnvironmentRouteLimitError` a cell throws walls its route, and every later cell on it is refused unstarted as `FLEET_ROUTE_LIMIT_REACHED`, checked before the ceiling and the breaker, whatever `routeBreaker` is configured to. The report names every walled route once under `routeLimits: { provider, model, code, message, resetsAt? }`. A paired run shares one registry between its two plans and refuses every later cell of either plan once any route is walled, because a pair with a refused side measures nothing. Trip-on-first is fixed rather than configured: a limit states that nothing on the route can succeed until the reset, which no threshold improves on.

**The folds exclude the cut cell everywhere.** The experiment fold unions both reports' `routeLimits` onto `ExperimentResult.routeLimits`; the cut and refused cells are already unpaired errors, so the delta, interval, and verdict read the pairs that completed. The trajectory reward is `null` on the new `route-limit` basis whenever the log carries the event, so the cell is neither a `0` nor a `1`. The scorekeeper's outcome group carries `routeLimit`, and the scoreboard counts such a session under `errors` whatever runs it recorded, outside parity and every pass@k batch; the observatory publishes that column unchanged. The bench drivers exit non-zero once the report or the result names a route limit, printing each route and its reset to stderr after writing `status.json`, and `bench loop` reads that status back into the ledger reason (`describeRouteLimits`) instead of recording an exit code alone.

Nothing waits for the reset. The reset instant is recorded on the event, the runner error, the fleet report, the experiment result, the facts, and the ledger reason; resuming the refused cells is a later plan's `cells` after that instant.

## Alternatives considered

**A new `USAGE_LIMIT` code beside `QUOTA` and `RATE_LIMIT`.** It would separate "wait for the window" from "top up the balance", but the seam already classified `usage limit reached` as `QUOTA`, no consumer acts differently on the two, and both stop a route the same way; the difference the run level needs — when the route serves again — is the delay the failure now carries. A third code would have split one scheduler rule across two codes.

**Reusing `RATE_LIMIT` with the reset as `providerRetryAfterMs`.** The retry plugin already declines a provider delay past `maxDelayMs`, so the step would have failed fast; but `RATE_LIMIT` promises the policy that a repeat may succeed within seconds, and a fleet that stopped a route on `RATE_LIMIT` would stop it on every 429 the policy gave up on. `QUOTA` is the code whose contract is "nothing on the route until the state changes".

**Letting the breaker count uncertified reports.** The evidence was 97 failed certificates, so counting reports with `certified: false` toward `consecutiveErrors` would have tripped the breaker — and would trip it on every hard environment a model fails three times in a row. A wall and a hard task must stay distinguishable in the record, which only the route's own code does.

**Deriving the cut from `turn/end` in the folds, without a new session event.** The scorekeeper and the trajectory fold could search the log for a `QUOTA` turn end, but the runner is the one deciding to end the run on it; a later runner policy that retried after the reset would leave the same `turn/end` in a log whose cell was measured to the end. The event states the decision once, where it is made, and the folds read it as they read `budget/breach`.

**Stopping only the walled route in a paired run.** The partner arm's remaining cells would run to completion and pair with nothing, spending a budget on measurements the verdict cannot use; the experiment semantics make the pair the unit, so the wall stops the pair. A single-plan run keeps its other routes running, because their rows stay valid.

**Waiting for the reset and resuming.** The reset is known in most cases and a sleep-until would let an unattended run finish; it was left out because it falls out of nothing simple — a fleet holding cells for hours changes what `maxConcurrent`, the token ceiling, and the shift driver mean, and the polyglot bench already resumes a partly run plan by naming `cells`.

## Consequences

A run that hits a usage limit now ends its cells as errors and its command non-zero: the leaderboard, the scoreboard, the trajectory export, and an experiment's verdict no longer count the wall as the model's failure, and the record — the cell error, the `fleet/cell` event, `routeLimits`, the session's `environment/route-limit`, the facts' `routeLimit`, and the loop ledger's reason — names the route and, when the product stated it, the instant the limit lifts. Every fleet report and experiment result gains a `routeLimits` field, every facts record may gain `routeLimit`, `SubagentResult` and `environment/delegation` gain `failure`, the trajectory reward gains the `route-limit` basis, and the session-event vocabulary gains `environment/route-limit`, so a build older than this one refuses a log that carries it. A `QUOTA` step is no longer retried by the default policy, which every keyed route already relied on. The reset read from a notice is only as good as the notice: a product that states its reset in a zone other than UTC, or without a clock time, records the refusal without a reset. The route also classifies a 429 without a notice as `RATE_LIMIT`, so a keyed installation's transient 429 now reaches the policy under the same code the DeepSeek adapter uses.
