# Agent Note: The enterprise roster is generated from real sources; the feed computes liveness, never invents it

Status: implemented

English | [中文](2026-09-19-enterprise-roster-and-harness-feed.zh.md)

## Problem

A customer proof of concept needs to present a large, structured "enterprise" of agents — divisions, departments, specializations — without pretending the harness runs 147 concurrent agents today. Two failure modes were both live risks: a hand-authored roster JSON that drifts from the repository the moment a package is renamed or removed, and a status field that reports "active" for seats nothing is actually running. Either one turns a proof of concept into a fabrication the first time someone checks it against the repository.

## Decision

**The roster is generated, not authored, and every entry cites a real, checked path.** `scripts/enterprise-roster.ts` composes exactly 147 agents as role x division x specialization, where each division's slice is built from one enumerable, real pool: `packages/core`, `packages/llm`, and `packages/subagent` leaf directories for `harness-core`; recorded bench scenarios under `examples/headless-agent/tests/*snapshots*` for `proving-ground`; `scripts/verify-*.ts` for `verification`; the CI gate ids in `scripts/run-gates.ts` for `judging`; `.agents/notes/implemented/<class>` directories plus the token-meter package for `curation-data`; ten package group READMEs for `program-departments`; six department-grounding packages crossed with six language specializations for `code-safety`; `.agents/skills/<id>` directories for `knowledge`; eight process-standard files for `governance`; and six telemetry/query sources for `observatory`. A `cite()` helper resolves every hardcoded relative path against `existsSync` before the generator emits it, so a renamed or deleted source fails the generator immediately, naming the missing path, rather than shipping a roster entry nothing backs.

**`generatedAt` is the tree's last commit timestamp, not the wall clock.** Reading `git log -1 --format=%cI` instead of `Date.now()` is what makes `buildRoster()` produce byte-identical JSON on repeated runs against the same commit — a real idempotency property, not merely a stable field count. A tree with no git history falls back to a fixed epoch rather than breaking the guarantee.

**The generated file's `status` is always `"defined"` and `counts.active` is always `0`.** This module describes what the repository defines; it has no session data and must not guess. `scripts/harness-feed.ts` is the only place liveness is computed: its `GET /roster` handler reads the committed roster, then maps each agent to a live session (best-effort, by preset id and role/department keywords present in the session's stamped `request/header` and `tool/call` data) to decide `active` (a matching session is open), `certified` (that session logged a `verification/certificate`-shaped event before ending) or `failed` (it ended without one), and only then are the counts recomputed. The committed file and the served response are never the same object; the served response is derived and discarded per request.

**Code-safety specializations name a target, not an implemented scanner.** This repository is TypeScript/JavaScript and has no Java, Go, PHP, or mobile static-analysis tooling, so every one of the 36 department x specialization reviewer seats cites its department's real grounding package (`dsh-credentials`, `dsh-shell`, `dsh-fs`, `dsh-storage`, the license-verification script, `dsh-sandbox`) regardless of which language the seat names; the specialization records what the seat is *for*, and `data/enterprise/README.md` states this plainly so a reader does not mistake "defined" for "implemented."

**The event fold in `harness-feed.ts` is written against the real session-event vocabulary, not the aspirational one.** `packages/core/session` defines `turn/start`, `turn/end`, `step/start`, `step/end`, `tool/call`, `tool/result`, `assistant/message`, and `agent/inbox/spliced`; there is no `agent/step`, `subagent/*`, `program/delegation`, `program/integration`, or `verification/certificate` event type in this tree today. The fold maps the real types (`turn/*` and `step/*` to `step`; `tool/call`/`tool/result` to `tool`, or to `delegation` when the tool name is one of the subagent tools; `agent/inbox/spliced` to `directive`) and additionally recognizes the aspirational prefixes (`verification/certificate` to `certificate`, `program/integration` to `merge`, a `finding`-prefixed type to `finding`, a denial-shaped tool failure to `refusal`) so that when the parallel proving-ground and code-safety programs start emitting those events, the fold requires no change. An event type the fold does not recognize is dropped from the stream, never a crash and never a placeholder record.

## Consequences

- `pnpm run roster` regenerates `data/enterprise/roster.json` deterministically; a diff in that file after a clean regeneration means a cited source moved, and the generator's own error names which one.
- `pnpm run feed` serves `GET /roster`, `GET /runs`, `GET /runs/:id/events` (SSE), `GET /safety/:id`, and `POST /safety` on port 4711 (`--port` to override) or against a `--fixtures <dir>` directory for the front end's own tests; it discovers `.proving-ground/runs/*`, `data/proving-ground/*/sessions/*.jsonl`, and `.code-safety/*` at request time and tolerates all three being absent, which they are in a fresh checkout — these are runtime output directories, not repository fixtures.
- `POST /safety` returns 501 until the parallel code-safety workstream lands `pnpm run code-safety`; the feed checks for that script in `package.json` on every request rather than caching its absence, so the 501 clears the moment the script is added with no feed change required.
- The honesty rule this note exists to enforce: 147 is always the defined count; the active count is whatever `GET /roster` computes from real session directories at the moment of the request, including zero.

## Alternatives considered

- **Hand-authoring `roster.json` once and committing it as static data** — the first package rename or removal would silently strand entries pointing at nothing, with no mechanism to notice. Generation with a checked `cite()` turns that into a build failure instead of a silent lie.
- **Wall-clock `generatedAt`** — makes every regeneration a diff even when nothing sourced from the tree changed, which defeats the point of an idempotency check.
- **Reusing the fictional event names (`agent/step`, `program/integration`) as the fold's primary keys** — would make the fold's happy path untestable against any session log this repository can currently produce. Folding the real vocabulary first, with the aspirational names as additional recognized prefixes, keeps the keyless test suite exercising real behavior while staying forward-compatible.
- **Treating a missing `.proving-ground/`, `data/proving-ground/`, or `.code-safety/` as an error** — these are runtime directories the parallel workstreams populate on a real machine; a fresh checkout or CI runner without them is the common case, not a misconfiguration.
