# Agent Note: The bench on OpenRouter's free open-weight models

Status: implemented

English | [中文](2026-09-19-bench-on-openrouter-free-models.zh.md)

## Problem

[The open-weight route note](2026-09-19-bench-on-an-open-weight-route.md) left the bench one key away from a run on anything other than the operator's Claude Code subscription, and left the RLVR corpus empty: every record under `data/proving-ground/` was produced under terms that admit evaluation only. The operator supplied that key — an OpenRouter account whose free tier serves a rotating set of open-weight models at no charge, under one account-wide limit of twenty requests a minute and one thousand requests a day. Two things had to be true before a plan could run on it and one before its transcripts could count.

The composition had to name the route without a code change and survive the limits. pi-ai ships `openrouter` in its installed catalog, so [`dsh-llm-pi-ai`](../../../../packages/llm/llm-pi-ai/README.md) inherits the endpoint and the `openai-completions` protocol for a route of that name and lets the profile replace the model list; but the free ids change from week to week, the catalog knows only some of them, and a cell that hits the per-minute limit fails its model request with the adapter's default two retries a few hundred milliseconds apart, which is the wrong shape for a limit measured in minutes. A fleet that runs cells two at a time on a shared limit also needs a bound on how many cells it will burn when the provider stops answering.

The transcripts had to carry terms that admit training. The base composition pins `agreementId: proving-ground-bench` with `purposes: [evaluation]`, and the curator withholds a session whose terms do not name the purpose an export asks for; a run under those terms would be one more evaluation-only record however open the model's weights are.

## Decision

`examples/headless-agent/tests/fixtures/proving-ground-bench/overlays/with-openrouter.cordis.yml` is the base plus four patches. It inserts one `llm-pi-ai` entry with a single route, `openrouter`, whose `apiKeyEnv` is `OPENROUTER_API_KEY` and whose `models` list names eight free ids with the context and output sizes OpenRouter published for them on 2026-09-19 (`deepseek/deepseek-v4-flash-0731:free`, `nvidia/nemotron-3-super-120b-a12b:free`, `nvidia/nemotron-3-ultra-550b-a55b:free`, `qwen/qwen3.8-27b:free`, `google/gemma-4-31b-it:free`, `poolside/laguna-s-2.1:free`, `nex-agi/nex-n2.5-pro:free`, `thinkingmachines/inkling:free`; every one of them advertises tool calling, which the harness loop requires). Its retry policy is the adapter's `normal` mode with eight retries and a backoff from three to thirty seconds, so a request refused at the per-minute limit waits it out instead of failing the attempt. The fleet patch runs two cells at a time with a route breaker of four consecutive error cells: a cell makes one request per step and a step on a reasoning model takes tens of seconds, so two cells stay far below twenty requests a minute, and a provider that stops answering costs at most four cells. The data-use patch pins `agreementId: proving-ground-openrouter-free` with `purposes: [training, evaluation]`, the base's client, residency, retention, and redaction profile unchanged; the terms govern this repository's use of the session log, and whether a given model's licence admits its outputs as training data is decided per model when a dataset is built, not by the composition. The three village-rule entries are restated as in every overlay.

The key is a reference and the launching shell is the whole credential plane: the drivers call `boot()` directly, so the repository's `.env` is not read, and the variable is exported in the shell that runs `pnpm run bench`. Keyless, `pnpm run bench -- fleet h1-fleet-openrouter-smoke-t2 --overlay with-openrouter` exits before any cell with `MISSING_CREDENTIAL: llm-pi-ai: no credential for provider route "openrouter"; its profile resolves OPENROUTER_API_KEY, which is not set …`, through the preflight the previous note added. The credential scanners in `data/transcripts/tools/collect-claude-code-session.mjs` and `data/proving-ground/tools/build-dataset.mjs` gained an `openrouter-key` pattern for the `sk-or-v1-` prefix, which the OpenAI-style pattern does not match because of the hyphen after `or`; a transcript or trajectory carrying such a key is refused before it is written.

Five plans name the route, all in district `bench-openrouter`: `h1-fleet-openrouter-smoke-t2` (one model over two named tier-2 environments, once, to calibrate the request count per cell before the allowance is committed), `h2-openrouter-free-t2` (the DeepSeek flash model, the 120B-class Nemotron, and the 27B Qwen over the six non-held-out tier-2 environments, once each), `h2-openrouter-agentic-t2` (three models built for agentic coding over the same six), `h1-fleet-openrouter-deepseek-t2` (the DeepSeek model alone, after the reasoning fix), and `h1-fleet-openrouter-nex-smoke-t2` (two cells on the model that certified first, the loop's first queue). After the first records the route also sets `compat.requiresThinkingAsText: true`, so a prior step's reasoning is replayed inside `content` ([its note](../architecture/2026-09-19-reasoning-replayed-as-text-through-gateways.md)).

## What the runs showed

Five records and one ledger line, all of 2026-09-19 ([the README](../../../../data/proving-ground/README.md) holds each):

- **The route works end to end.** Tool calls, reasoning, usage, the attempt ladder, the caps, the read barrier, the census, the export: every cell on the free tier produced the same session log a subscription cell does, and the loop's first iteration recorded one of them without a hand on it.
- **The first launches certified nothing, for three different reasons.** The DeepSeek flash model looped on reads for forty steps because the gateway drops the `reasoning` field it plans in ([the fix](../architecture/2026-09-19-reasoning-replayed-as-text-through-gateways.md)); the Nemotron 120B model lost every attempt to an upstream overload the adapter did not retry, now classified `SERVER`; the Qwen model's upstream shared pool returned 429 through every retry.
- **With the two harness defects fixed, the agentic fleet certified 16 of 18** on the six non-held-out tier-2 environments: Nex N2.5 Pro 6 of 6 and poolside Laguna S 2.1 6 of 6 at the first attempt but one, Nemotron 3 Super 120B 4 of 6, missing csv-codec and glob-match after three attempts each. The middle product model certified the same six environments 12 of 12 in a third of the steps in the h1 record; the free models reach the tier, slower. The DeepSeek model, rerun with reasoning replayed as text, kept its plan between steps and still ended attempts without a write in three cells before its rerun was stopped: the transport defect is fixed, and what remains is the model's handling of this tool surface.
- **The corpus exists and is small.** The sessions carry terms that admit training; the first `--purpose training` dataset ([`2026-09-19-openrouter-free-v1`](../../../../data/proving-ground/datasets/2026-09-19-openrouter-free-v1/README.md)) holds 22 trajectories, 18 certified and 4 measured failures, on four free models over six tier-2 tasks, after the two records exported before the `terms` field were re-exported by the current fold. Licences, read on the Hugging Face hub on the day: DeepSeek V4 Flash is MIT, Qwen3.8-27B is Apache-2.0, Nemotron 3 Super is under NVIDIA's own open-model licence; the Nex and poolside licences were not read and gate their trajectories at admission.
- **The allowance shaped the day.** 834 of the 1,000 daily requests were spent by 12:20 UTC across five fleets; a cell makes one request per step and a reasoning model's step is a minute long, so a tier-2 fleet of eighteen cells is an eighty-minute, three-hundred-request run.

## Alternatives considered

- **Declare the route by hand, as `with-openai-gateway` does.** Rejected: pi-ai's installed `openrouter` entry already carries the endpoint, the protocol, and the `openrouter` reasoning-dispatch format its URL implies, and a hand-declared route would restate them and drift when pi-ai updates. The overlay states only what the catalog cannot know: which free ids exist today and how large they are.
- **Run one cell at a time.** Considered and measured: the first cell made one request per step at roughly three a minute, so a serial fleet used a seventh of the per-minute limit and took ten minutes a cell. Two cells halve the wall time and stay under a third of the limit; more would run into the per-minute limit on fast models and turn the backoff into the pace of the run.
- **Keep the base's evaluation-only terms and decide about training later.** Rejected: a pin may narrow terms and never widen them, so a session created for evaluation cannot become training data afterwards; the decision has to be in the composition before the first cell. The overlay makes it, under its own agreement id, so the two corpora stay distinguishable by the terms each session carries.
- **List every free model.** Rejected: twenty-two ids were free on the day, two of them without tool calling, several of them variants of one family; a route serves exactly the models it lists, so the list is the eight a plan might name. Adding one is one entry with its sizes.
- **Throttle in the fleet.** Rejected: the fleet has no notion of requests, only of cells, and the limit is per request. The route's retry policy is where a rate limit belongs, and the breaker covers the failure the retry cannot.

## Consequences

- The bench runs on an open-weight route for real, on a free allowance, with one flag and one environment variable, and refuses loudly without the variable.
- The route's model list is a snapshot: OpenRouter's free set changes, and a plan naming an id the provider withdrew fails at the first request of the first cell with the provider's own error, not before. The preflight checks the key, not the catalog.
- A fleet on this overlay spends a shared daily allowance, so two plans launched the same day compete for it; the plans' cell counts are sized for one day and a rerun, and a plan that exhausts the allowance mid-run produces cells that fail every attempt on a rate-limit refusal rather than an error, which the breaker does not stop.
- Sessions on this route are the first in the repository whose terms admit training. They are admissible into a dataset only under a purpose filter that reads those terms, and the model's licence still has to be checked per model at admission.
