# Agent Note: The development branch runs the repository gates on hosted runners

Status: implemented

English | [中文](2026-09-27-branch-ci-on-hosted-runners.zh.md)

## Problem

The upstream workflow `.github/workflows/ci.yml` runs on pushes to `master` and on pull requests only, on the enterprise runner label `dsh-ubuntu-24-04-16core`, which this fork does not have. The development branch `claude/coding-agent-harness-u9l4gt` therefore carried 488 commits past `master` (47f943859) without one CI verdict. The local pre-push discipline ([dsh-pre-push-checks](../../../skills/dsh-pre-push-checks/SKILL.md)) runs focused checks by design, so drift that crosses packages was invisible: the first branch runs found a stale `docs/module-graph.md`, two knip findings, a rotten bubblewrap pin (`0.9.0-1ubuntu0.2` had left `noble-updates`), a plan-listing test pinned to a count, real-product spend assertions that hold only on the enterprise host, three uncovered locations (the pwsh executor's read-barrier probe and the in-process driver's `model` branch), a duplicate `tool-pwsh` loader entry in the pwsh terminal lane, 28 session fixtures committed in the unpacked layout, two loader-composition expectations recorded before the `model` capability landed, and a translation-prompt snapshot recorded before its gold-pair documents changed.

## Decision

`.github/workflows/branch-ci.yml` runs the same three gate groups the enterprise lanes run (`check:ci:static`, `check:ci:coverage`, `check:ci:consumers`) on hosted `ubuntu-latest` runners on every push of the development branch and on manual dispatch. Worker counts are sized for the runners' four cores: the static job runs two gates at a time; the coverage job runs one gate at a time with three vitest workers; the consumers job runs one gate at a time because the browser suites time out when a second gate's build shares the cores, and it caps oxlint at two threads and publint at two concurrent packages and skips the Node-compatibility typecheck. One concurrency group per ref lets a started run finish and keeps only the newest push waiting behind it: the enterprise cycle pushes several times an hour, and a group that cancelled the run in progress left no commit with a verdict. The static job checks out full history because the archive gate reads the trusted base from the checkout. Telemetry is disabled for every job. `scripts/prepare-ci-bubblewrap.sh` pins the bubblewrap package to the version `noble-updates` currently serves (`0.9.0-1ubuntu0.3`) with its SHA-256, so the sandbox lanes stay reproducible and a future pin rot fails the install step by name instead of silently changing the sandbox under test.

The workflow grants no permission by default and each job `contents: read` only. Every third-party action in `branch-ci.yml`, `deck-pages.yml` and `docs-pages.yml` is pinned to a full commit SHA with the release that tag resolved to named beside it (`actions/checkout` v6.1.0, `pnpm/action-setup` v4.3.0, `actions/setup-node` v6.5.0, `actions/cache` v4.3.0, `actions/configure-pages` v6.0.0, `actions/upload-pages-artifact` v5.0.0, `actions/deploy-pages` v5.0.1), so a moved tag cannot change what a lane runs; an update edits the SHA and its comment together. The repository's Pages site is published from the development branch only: the `deck-pages.yml` job runs for that ref alone, so a manual dispatch from another branch publishes nothing, and it alone holds `contents: write`, with a checkout that keeps no token for the build to read; `docs-pages.yml` deploys only in the upstream repository, so a push of this fork's `master` cannot replace the deck.

A pending run that a newer push replaces ends `cancelled` without a verdict, so a commit's verdict is its own run's when that run rendered one, else the first later completed run whose head contains the commit: `scripts/enterprise-report.ts` labels that answer `later` and names the superseded runs, the Judging functions record it with the head in `target.via`, and `pnpm run enterprise:verdicts` lists every shipped commit's verdict with its basis.

## Alternatives considered

**Add branch triggers to the enterprise `ci.yml`.** Rejected: its runner label does not exist for the fork and its lane shape assumes sixteen cores.

**A self-hosted runner in the development container.** Rejected: the container is ephemeral and reclaimed between sessions; a verdict must not depend on it.

**Keep relying on the local pre-push checks.** Rejected by the evidence under Problem: the discipline is right for a push and wrong as the only gate, and the branch had accumulated exactly the cross-cutting drift it cannot see.

**Install bubblewrap unpinned.** Rejected: an unpinned install makes the sandbox lane's binary drift with the mirror; the pin is the reproducibility, and its maintenance cost is visible at the failing step.

**Keep actions on their major tags.** Rejected: a tag moves when its owner releases, so the lanes would run code no commit of this repository names; the SHA is the version that ran.

**Attribute a superseded commit to the branch's newest verdict.** Rejected: the newest run's head need not contain the commit, so its verdict need not cover the commit's changes; the ledger holds such a line, a verdict on `d2cc487f7` recorded for `3ed95172e5`, a commit the branch does not contain.

## Consequences

Every push of the development branch gets a verdict on hosted runners; the branch's first green run is the first CI evidence for the work since `master`. The pwsh sandbox spec's read-barrier probe tests run only where `pwsh` is installed, which the hosted runners are, so the coverage gate holds on CI and on a developer host with PowerShell. The bubblewrap pin will rot with the next `noble-updates` release and the install step names it. Of the two web e2e timeouts on the fourth run, `workspace-management` (a hover poll) was load: it passed on the fifth run with the consumers job at one gate at a time. `agent-preset-selection` was not: the judge and validator presets added on 2026-09-06 had no English display names, so the English preset menu listed them in Chinese and every assertion after the menu golden failed in cascade; the fifth run showed it plainly. The development container cannot run the web e2e lanes at all: the repository's Playwright wants headless-shell r1228 and the container ships r1194, so those lanes' verdict is CI's alone. It ships no `pwsh` either, so the `pwsh-tool-turn` ACP scenario and the pwsh executor suites run there only with a PowerShell release tarball on `PATH`; the hosted runners have it.

## Verification

Runs one to four on the branch each found the defects listed under Problem, and each was fixed in the commit that followed. The fifth run found two more: the pwsh probe test expected the bash spec's `read-only` default where its own composition resolves `workspace-write` (fixed in `038e8f019`), and the preset-name defect above (fixed with English names for both presets and the two web goldens re-recorded against the built app). Locally before that commit: `npx tsc --noEmit -p tsconfig.host.json` passes; oxlint passes on the changed packages; `pnpm run verify-module-graph` reports the graph up to date; the in-process driver's tests hold its source at 100% coverage; both loader-composition tests pass against the built `lib/` (`DSH_EXAMPLE_MODE=lib`); the translation-prompt snapshot was re-recorded from the current gold pairs and passes; `pnpm run migrate:packed-session-fixtures` rewrote the 28 fixtures and the layout snapshot passes; the ACP scenario `subagent-continuable-inheritance`, which timed out in a local run of the whole consumers group under load, passes alone.

Runs five and nine to thirteen failed the consumers job on one pin the fifth run's account left out: `examples/acp-agent/tests/snapshots/pwsh-tool-turn/tool-schemas.expected.json` is compared only where `pwsh` is installed, and the `task_*`→`job_*` rename (`a2d0f7f41`) had edited it by hand instead of re-recording it, so four background-job descriptions kept the old noun and `pwsh` stayed ahead of the `job_*` tools the header lists by name; `DSH_SNAPSHOT=refresh` with PowerShell 7.5.4 on `PATH` re-recorded it, and the full keyless snapshot suite passes with the scenario running. Run thirteen also failed the coverage job in the shifts spec `refuses a slot that lands on a running shift of the same district`: at its millisecond cadence every refused slot published a session of its own — several directory and file syncs each — for as long as the run was held open, and under the lane's two forked workers neither the running slot's `shift/start` nor the poll's listing settled inside `vi.waitFor`'s one-second default (on an idle host the second poll alone took 218 ms and 82 refusals landed within 350 ms); the spec drives refusals at 25 ms and waits for the overlap refusal itself, as its spend-window sibling does since `c8abb2080`.

Runs 23 to 48 failed on five causes. The coverage job of run 23 failed the fleet spec `stops both plans of a paired run once either plan's route is refused at its limit`: pair 1's two cells slept 1 ms each and the spec expected the walled cell to settle first, so when its partner finished first the fleet correctly started the next cell before the wall rose; the stub now makes the overlap explicit, the walled cell refusing once its partner has started and the partner completing once the fleet has announced the walled cell (`85d47f7ac`). The coverage job of run 27 failed `removes an ordinary managed tree after 'uncaught-exception'` after waiting 30 s for the host fixture's `ready` file: the managed tree wrote its process ids with `writeFile`, which creates the file empty first, and the host parsed the file as soon as it existed, died on the empty read before writing `ready`, and removed the tree on exit; a standalone reproduction of that poll read an empty file in 18 of 300 runs at the host's 10 ms interval, and none once the ids were written to a side file and renamed into place, which the fixture now does (`f1e5cb672`). The consumers jobs of runs 23 to 25 and 48 failed the translation-prompt snapshot, which embeds five live bilingual pairs: `30c607f15` and `5b1f5e66c` changed two of them without re-recording it, and `8a4f37301` and `f2fba8fa0` re-recorded it; T-0023 removes the dependency. The consumers jobs of runs 35 and 48 failed the duplication gate on the per-division seat tally that `29161bc0e` copied from the publisher into the report, now the one function `divisionSeats` in `scripts/enterprise-roster.ts` (`e83784055`); run 48's lint failure on the secret-patterns spec was fixed in `1db0cb562`. The static jobs of runs 35 and 48 failed knip because `cd535f57e` added the deck's operations reader `apps/command-deck/deck/ops.ts`, which no view imports yet, and with it the only uses of `FIXTURE_BASE` and `feedUrl` in `feed.ts`. Locally, `npx tsc --noEmit -p tsconfig.host.json` passes, the fleet and process-exit specs pass, the enterprise functions, ledger, report, publish and verdicts specs pass, `pnpm run duplication` finds no clone, and the three edited workflows parse with their permissions and job conditions as stated above.
