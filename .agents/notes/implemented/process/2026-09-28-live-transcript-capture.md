# Agent Note: Every live transcript reaches the branch within five minutes

Status: implemented

English | [中文](2026-09-28-live-transcript-capture.zh.md)

## Problem

The container that runs the operator's session, its subagents, and the enterprise's cycles is reset without notice, and a reset keeps only what the pushed branch holds. The transcripts were kept by a snapshot of the whole session tree ([`collect-claude-code-session.mjs`](../../../../data/transcripts/tools/collect-claude-code-session.mjs)) that rewrote a 200 MB raw tree per run, refused any credential shape it was not told about, and ran from an hourly Routine that was disabled on 2026-09-19. The last snapshot was taken at 2026-09-23T00:28Z. The reset at 2026-09-28T22:07Z therefore erased five days of the orchestrator log, every subagent transcript of those days, and the department sessions of a shift in progress; [LOSSES.md](../../../../data/transcripts/LOSSES.md) states what was lost and what survived. The enterprise's other logs (shift `.sessions`, the intake's scratch, the cycle and scheduler logs, the nightly bench log) live in `/tmp` or `/home/user` and are committed, when at all, only after their run finishes.

## Decision

[`capture-live.mjs`](../../../../data/transcripts/tools/capture-live.mjs) appends, per run, only the bytes each source gained since the last run, as immutable gzip chunks under `data/transcripts/live/`, and writes one immutable manifest per run under `live/runs/<date>/`. The chunk holds whole lines; its manifest entry names the source path, epoch, sequence number, byte and line range, the SHA-256 of the stored bytes and of the raw source prefix the chunk ends, its redactions, and the capture time. The state is folded from the committed manifests, so a fresh clone resumes where the last pushed run stopped, and a file whose first captured bytes no longer hash to the recorded prefix begins its next epoch at byte 0 instead of being overwritten. Chunk directories are sharded by the date of the file's first capture and the capture date, so no git tree the loop touches grows without bound, and paths stay under 140 characters.

The credential and personal-data patterns live in [`secret-patterns.mjs`](../../../../data/transcripts/tools/secret-patterns.mjs), which the collector, the live capture, the dataset tool, the intake admission ([`enterprise-intake-admission.ts`](../../../../scripts/enterprise-intake-admission.ts)), the bench preflight ([`preflight.mjs`](../../../../data/proving-ground/tools/preflight.mjs)) and the code-safety recorder ([`record-run.mjs`](../../../../data/code-safety/tools/record-run.mjs)) import, so every tool that publishes transcripts or agent text masks the same shapes. Each pattern has a `kind`: `credential`, or `personal` for `email`, because the harness's context reminders carry the operator's account e-mail into every Claude Code session the capture reads. The live capture masks every match as `[REDACTED-<PATTERN>]` and counts it per pattern instead of refusing, since refusing a chunk loses the transcript it holds; the digests the collected builds accepted stay verbatim, because each pattern still matches the same characters for them; a PEM block in a plain-text log is masked line by line, including across a chunk boundary through the manifest's `pemOpen`; an e-mail match never starts after a backslash or inside a `\uXXXX` escape, so a masked JSONL line stays parseable; and the masked chunk is scanned again, a surviving match stopping the run before its manifest is written.

[`scripts/transcripts-capture.sh`](../../../../scripts/transcripts-capture.sh) runs the capture every `TRANSCRIPTS_CAPTURE_MINUTES` (default 5) from a dedicated linked worktree, with the enterprise scheduler's structure: a one-function body, a `flock` single instance, exit 2 for a bad interval, 4 for a held lock, 5 for the main checkout or tracked changes. It commits `data/transcripts/live/` alone and pushes by fetch, `git pull --rebase` and push with 2, 4, 8 and 16 second retries. The commit and the push pass `--no-verify`, following the [shift engine](../architecture/2026-09-28-enterprise-shift-engine.md): its data commits are machine-written and certified elsewhere, and the pre-push hook's three-minute workspace typecheck would take most of each interval. Branch CI ignores a push that changes only transcript data (the live chunks, the raw trees, and the derived datasets); the tools and the Markdown pairs under `data/transcripts/` still start it. The Pages workflow already runs only for `apps/command-deck/**`, its own file, and the lockfile. [`transcripts-to-dataset.mjs`](../../../../data/transcripts/tools/transcripts-to-dataset.mjs) reads a session from the live chunks with `--session`, reading a line an earlier epoch already held once.

## Alternatives considered

- **Re-enable the hourly collector Routine.** It fires into the operator's session, which a reset suspends, rewrites the whole raw tree each hour, and refuses a new credential shape until a person reviews it; any of the three loses transcripts.
- **Commit the source files themselves on every run.** A growing 200 MB log committed every five minutes stores a new full blob each time; appended chunks store only the new bytes.
- **One manifest file for the whole capture.** Rewriting it every run grows the history quadratically with the number of chunks; one immutable manifest per run does not.
- **Refuse a chunk with an unhandled credential shape, as the collector does.** Refusal is right for a reviewed archive and wrong for a capture whose only job is to keep the bytes before a reset; masking with a count keeps the transcript and the secret out of the branch.
- **Keep a copy of the patterns in each tool.** The copies drifted: the intake admission's said the collector did not export its list, the bench preflight's lacked the private-key and bearer shapes, and none knew personal data.
- **Detect phone numbers.** Over the 588 MiB of the 2026-09-06 raw tree and the live chunks, the international and North American phone shapes matched a Twitter-snowflake epoch constant, number tables and line-number lists, and no phone number; masking them would cut ids and counts out of the record for no measured gain.
- **Mask only the operator's address.** It would put the address into the repository it must stay out of, and leave every other address.
- **Let the pre-push hook run.** It typechecks the whole workspace for about three minutes and needs an installed checkout, which a data-only worktree does not have.

## Consequences

A reset now loses at most one interval of any source the capture names. The branch gains one commit per interval while any session writes, with no CI run, and the repository grows by the compressed size of everything the sessions write: the first two loop rounds took 7.3 and 5.0 MiB of source while a workflow of subagents ran. The chunks are redacted copies, so their SHA-256 values describe the stored bytes, and the raw prefix hashes only detect a rewritten source. The loop's own log and Claude Code's `ccr-tip.json` pointer are excluded, because either would add a chunk to every run. A source outside the default list needs `--source`, and a source that rewrites itself in place begins a new epoch each time, so the ceilings bound what one run can add. The chunks of the runs before the capture of 2026-09-29T00:18:02Z, the collected raw trees, and the session logs of earlier code-safety and proving-ground records hold the operator's e-mail verbatim; the [transcripts README](../../../../data/transcripts/README.md#what-the-data-is-and-is-not) names the transcript trees, and purging the address from the public history is the operator's decision. The loop restarts only when someone starts it; after a reset its command is in the [transcripts README](../../../../data/transcripts/README.md#live-capture).

## Verification

`scripts/transcripts-capture-live.spec.ts` covers incremental whole-line chunks and a settled trailing line, a new epoch that leaves the old chunk bytes unchanged, masking and counting with an accepted placeholder and a PEM block split across two runs, resuming from a copied `live/` tree, the per-file ceiling, and the dataset tool reading the live chunks; `scripts/collect-redaction.spec.ts` covers the collector's refusal of an e-mail address and `--redact email`; `scripts/secret-patterns.spec.ts` covers every pattern, a key and an address after a JSON-escaped `\n`, an address in a JSON string, in a doubly encoded one and behind `\u003c`, a PEM body, an AWS secret next to an already masked key id, an accepted placeholder, and leaves a git SHA, a UUID, a base64 image fragment, package pins and short-prefix identifiers alone. The loop's first round with the `email` pattern, capture `609d922cc` at 2026-09-29T00:18:02Z, masked 43 addresses. A smoke run of the loop against a local bare remote pushed two captures one minute apart with the trailers, and refused the main checkout with exit 5. The first live epoch was committed in `541b9f1b5` at 22:54Z (30 chunks from 30 files, 21.0 MiB of source, 7.2 MiB stored), and the loop, started from `.claude/worktrees/transcripts-capture`, pushed its first two captures as `7d505222b` at 23:03:09Z and `9d893dee7` at 23:08:08Z; a re-scan of every stored chunk found no unaccepted credential shape.
