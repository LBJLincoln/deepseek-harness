# Agent Note: The improvement log as the loop's ledger

Status: implemented

[English](2026-09-19-improvement-log-as-the-loop-ledger.md) | 中文

## Problem

本仓库四个目标之一，是一个靠证据自我改进的 harness：提出一项改动，把它作为一个冻结配对实验在 Proving Ground 基准上跑起来，读取裁决，然后保留或拒绝这项改动。这其中的每一个部件都已存在，这个循环也已经闭合了十九次，但没有任何一个文件承载这个循环。读数存放在[结果笔记](../../proposed/architecture/2026-09-08-hypothesis-program-results.md)里，是按"驳倒了什么"而非按"决定了什么"来组织的；运行存放在 `data/proving-ground/` 下的三十二个记录目录与十二个折叠中，每一份在那个 README 里都有自己的一段；裁决又一次以卡片的形式出现在仪表板上。这三者都没有说明每个裁决换来了什么决定、因此挪动了哪些默认设置，以及还有什么仍靠人手完成，于是想要判断这个 harness 是否真的靠证据自我改进的读者，只能从三个各为别的目的而建的视图里去重建这个循环。

## Decision

[`data/proving-ground/improvement-log.md`](../../../../data/proving-ground/improvement-log.md) 连同它的中文对应文件就是这份台账：每次改进迭代一行，按迭代运行的顺序排列，共六列——日期、被提出的改动及它检验的机制、检验它的实验或记录（在存在的情况下链接记录目录的 manifest 与折叠文件）、按笔记与折叠自身所述的配对读数、为 harness 所做的决定及其理由与代价，以及默认设置中挪动了什么。十九行覆盖第 3 与第 5 层的 E2/H1、E1 的四次模型档位比较、四次尝试上限读数、E4、H4、E5 的三次读数、E6，以及正在运行的 E7。

表格上方有一段按代码实际执行的方式陈述晋级规则：计划在任何单元运行之前就被摘要冻结，两臂会解析出不同上限的计划会被拒绝，而 `promote` 要求自举区间的下界超过计划的 `minimumDelta`。成本被如实陈述——它列在裁决旁边、由读者权衡，并不属于这条规则——因为[实验包 README](../../../../packages/improvement/experiments/README.md#statistics-and-verdict) 让裁决只是区间的函数。表格下方的"这个循环仍然缺什么"一节点明了还不自动的四个部分：提案由 harness 之外的人撰写、运行由人手经 `pnpm run bench` 启动、被保留的改动靠编辑组合来落地，以及至今每一次运行都在同一家供应商的模型上。

这份台账从读者已经站着的地方被链接：[`data/proving-ground/README.md`](../../../../data/proving-ground/README.md) 的 Layout 代码块与工具段落、[`data/README.md`](../../../../data/README.md) 的 proving-ground 条目、根 README 的 Proving Ground 一节，以及仪表板自身的注记——后者由 `data/proving-ground/tools/build-dashboard.mjs` 构建进已提交的页面。

直接位于 `data/proving-ground/` 中的手写文档属于双语配对语料，这由 [`scripts/translation-pairing.ts`](../../../../scripts/translation-pairing.ts) 中的 `isTranslationScopeFile` 判定。该模式止于第一段路径：该目录之下的一切都是记录的运行、折叠或数据集，它们在运行之后从不编辑，也从不翻译。

## Alternatives considered

- **从记录与折叠生成这份台账。**拒绝：六列中有三列并不存在于任何工具读取的文件里。一份记录陈述它的臂、证书与花费；磁盘上没有任何东西陈述这些臂是为检验什么改动而选的、harness 事后决定了什么、哪个默认设置挪动了，而两行读数互相矛盾的迭代需要的是一句话而不是一个字段。生成器只会产出仪表板已经展示的那两列，并把台账真正的主题留给一份手工维护的附属文件，那不过是同一个文件加上更差的来源说明。
- **改把这些行放进结果笔记。**拒绝：那份笔记是一个读取本次程序发现的提案，按驳倒／支持／未决来组织，并以它所要求的切片收尾。按时间排序的决定台账是另一份文档、面向另一类读者，把它折进去会让那份笔记成为两种互不相容排序的唯一归宿。台账转而为每个读数引用那份笔记。
- **给仪表板加一列决定。**拒绝：仪表板只由记录与折叠折叠而成，这正是它能在任意提交上从数据重建的原因。决定及其理由二者皆非，把它们放进去就等于把手写文字塞进一个生成的页面，而这个页面是 pull request 无法逐行审阅的 HTML。
- **让这份台账只有英文。**拒绝：它是关于本仓库自身运作的文档，就摆在一个已配对的 README 旁边，而配对约定不接受任何按文件逐条放行的清单。把范围判定扩到该目录的手写文档，比加一条排除项更小，也让这个配对继续受门禁约束。

## Consequences

- 这个循环可以作为一个循环来读：十九行说明提出了什么、由什么检验、返回了什么、做了什么，而表格下方的四个缺口说明还有什么要由人来提供。表中每个数字都可回溯到它所出自的记录、折叠或笔记，没有任何一行陈述三者之外的数字。
- 这份台账靠人手维护，因此一次运行了却没有换来一行的迭代，会让这个循环自身的记录不完整。让它保持诚实的规则，与记录 README 已有的那条相同：先记录一次运行，再添一行。
- `verify-translation-pairing` 现在会发现 `data/proving-ground/*.md`，因此该目录中今后任何手写文档都必须作为完整配对合入。它之下的记录目录、折叠与数据集仍在语料之外。
- 晋级规则现在有了唯一的陈述之处，并与执行它的代码对齐。这份台账直言：至今没有任何冻结配对晋级过一项 harness 改动，而唯一拥有晋级级别读数的那个 harness 机制，其读数来自一次离线折叠，且冻结重跑并未复现它。
