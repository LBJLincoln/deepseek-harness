# GitHub sweep, 1 June to 7 September 2026

Source: repository pages, raw files, release pages, vendor changelogs and developer search. Every number below carries its URL. Where a figure exists only in a secondary roundup I say so; where a project publishes a claim it cannot substantiate I say that too.

---

## 1. The tool bridge moved under us: MCP 2026-07-28

The single most consequential change in the window for `packages/mcp` is the [MCP 2026-07-28 revision](https://modelcontextprotocol.io/specification/2026-07-28/changelog), the largest since MCP launched. The protocol is now stateless: the `initialize` handshake and `Mcp-Session-Id` are gone, protocol version and client capabilities ride in per-request `_meta`, a mandatory `server/discover` RPC replaces the handshake, every result carries `resultType`, and list results carry `ttlMs`/`cacheScope`. Streamable HTTP POSTs must carry `Mcp-Method`/`Mcp-Name` headers that servers validate against the body. MRTR (multi round-trip requests) replaces server-initiated `sampling/createMessage`, `elicitation/create` and `roots/list`; sampling, roots and MCP logging are deprecated on a twelve-month window; tool schemas loosen to full JSON Schema 2020-12.

The migration pattern the ecosystem settled on is **dual-era, not cutover**. [OpenObserve's implementation](https://github.com/openobserve/openobserve/issues/13527) serves 2026-07-28 for requests carrying modern `_meta` and 2025-11-25 for anything that calls `initialize`, byte-for-byte unchanged. [Agentgateway shipped v1.4 on 27 July](https://agentgateway.dev/blog/2026-08-03-new-mcp-spec-revision/), one day before the spec. A [Kaneo design note dated 9 August](https://github.com/usekaneo/kaneo/blob/main/apps/docs/core/integrations/mcp-stateless.mdx) makes the point that matters for us: treating a sessionful 2025-06-18 exchange as "stateless" because its POSTs use separate TCP connections does not implement the contract. Notably, [as of a mid-window tracker](https://github.com/stumason/coolify-mcp/issues/337), no major client had shipped the revision — Anthropic's connector docs still capped at 2025-11-25 — so servers are ahead of clients.

For us this is mostly good news. Statelessness pushes cross-call state into explicit server-minted handles passed as tool arguments, which is closer to our session log than MCP sessions ever were. The work is real but bounded: a `server/discover` responder, `resultType` and cache fields on our outbound tool lists, and a decision about MRTR before elicitation's deprecation window closes.

## 2. Vendor harnesses: convergence, and one shutdown

Claude Code continued near-daily releases to [2.1.263](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md), with `bashOutputMaxChars`/`taskOutputMaxChars` raising inline output limits to 128K, `--append-subagent-system-prompt-file` for large subagent prompts, and `/skill-doctor` reporting unused skills and their context cost. The 2.1.180+ range is where the convergence with our seams is visible: `SendMessage`/`ListAgents` for cross-session agent communication, agent definitions carrying `model:`/`permissionMode:`, `PreModelSwitch`/`PostModelSwitch` hooks that can block or annotate, network sandboxing with domain allowlisting, worktree isolation, and `/goal` for background task monitoring. Codex CLI shipped [0.153.0 through 0.153.4 on 3-4 September](https://github.com/openai/codex/releases) with plugin-marketplace management, app-server reconnection and MCP tool approvals scoped to app accounts; 0.147.0 earlier in the window brought portable Agent Plugins across local, personal, workspace and remote sources plus an opt-in 2026-07-28 MCP implementation.

The window's hard lesson is Google's. [Google announced](https://developers.googleblog.com/an-important-update-transitioning-gemini-cli-to-antigravity-cli/) that on **18 June 2026** Gemini CLI and the Code Assist IDE extensions stop serving requests for Pro, Ultra and free individual tiers, which move to Antigravity CLI (`agy`), a closed-source Go binary. Enterprise licences and paid API keys continue. Secondary reporting describes the retired repository as Apache-2.0 with roughly 104k stars and about 6,000 external contributors. An open-source harness with a vendor behind it stopped serving requests on a date — that is the argument for model-agnosticism, made better than we could make it ourselves.

[OpenHands shipped roughly ten releases](https://github.com/All-Hands-AI/OpenHands/releases) between 30 July and 27 August, moving toward a managed product: automation run phases, an automations catalog, LLM pre-flight validation that rejects misconfigured profiles before a run, per-run cost tracking, a "ready-for-dev" issue readiness gate, and MCP enable/disable with disabled skills excluded from agent context. The pre-flight validation is the piece worth stealing: a fleet cell with a misconfigured route should fail at plan freeze, not mid-shift.

On the closed side, [Amp had a dense July](https://ampcode.com/news): agent-to-agent spawning and file exchange (17th), subscriptions (18th), the Puck meta-agent and Slack (20th), **self-scheduling agents that "set their own schedules, wake themselves up, and keep working" (21st)**, Multiplayer (22nd), and **event-driven Orbs that react to CI failures, Linear issues, monitor alerts or any HTTP request (23rd)**, then Global Plugins and Skills (11 August). That is a commercial always-on product shipped three months before we have one. A [secondary catalogue](https://github.com/bradagi/awesome-cli-coding-agents) puts Factory Droid top of Terminal-Bench with headless CI mode, and Cursor CLI's Cloud Handoff (`&` prefix moves a live session to a cloud agent) as the cleanest answer to leaving a long task running.

## 3. The field, ranked, and the upstream we forked

A [star-ranked survey pulled from the GitHub API on 29 August](https://pinggy.io/blog/best_open_source_cli_coding_agents/) gives the shape of the open field: OpenCode ~202k (MIT), **DeepSeek Harness ~203k (MIT)**, Codex CLI ~119k (Apache-2.0), Pi ~98k, OpenHands ~85k, Cline ~67k, Goose ~54k (now under the Linux Foundation), Aider ~48k with no commits since May 2026, then CodeWhale, Continue, Reasonix, Crush, Qwen Code, Kilo Code and Grok Build. All licence and star figures there are from one secondary source. The structural point is that model labs stopped outsourcing the terminal.

[The upstream itself](https://github.com/deepseek-ai/deepseek-harness) confirms MIT, developer-preview status and roughly 214.7k stars over about 15,210 commits when read on 7 September. Two consequences for Daliesk: our fork carries `improvement/`, `verification/`, `components/` and `governance/` groups upstream does not, so merge cost is a standing line item; and the harness alone is not the moat, because a 214k-star MIT version of it exists.

Three open-weight coding flagships landed inside the window, all from [one secondary roundup](https://pinggy.io/blog/best_open_source_self_hosted_llms_for_coding/) and none independently verified here: Qwen3.8-Max weights published 14 August under Apache-2.0 (reported 67.7 SWE-Bench Pro, 86.6 Terminal-Bench 2.1, text-only, 262K context); GLM-5.3 announced 14 August with weights held two weeks for a safety review and published 29 August under a bespoke licence; DeepSeek V4-Flash GA on 31 July and V4-Pro build 0813 on 13 August at 1.6T total / 49B active, with the API moving to peak/off-peak pricing on 16 August. A bespoke per-model licence and time-of-day pricing are both things our curator terms and budget policy do not currently model.

## 4. RL infrastructure and environment hubs

Prime Intellect had the strongest window. [Scaling Agentic RL (22 July)](https://www.primeintellect.ai/blog/scaling-agentic-rl) unified 23 tasksets behind one API — about 198,000 SWE tasks across 20+ languages, 28,600 terminal, 137,600 search, ~365,000 total — each loading from a typed config, provisioning a sandbox from the task image, and scoring with the taskset's own logic. Their validation is the part to copy: no-op must fail, gold patch must pass with 10x retries for flakiness, duplicates removed (Scale-SWE 20,181 to 17,202; Multi-SWE 4,703 to 2,232). They are also candid in a way benchmark vendors rarely are: because "the agent shares a sandbox with the grading machinery, a policy under RL pressure will eventually find whatever seam is left", withholding grading material is "mitigation, not a guarantee", and isolated grading sandboxes are still roadmap. They separately name the false-negative class — PR-mined tests assert implementation details, so a differently-correct fix is punished and gold-patch validation is blind to it by construction.

[Multi-Agent Systems in PRIME-RL (7 August)](https://www.primeintellect.ai/blog/multi-agent-systems) released multi-agent support in verifiers 0.3.0 and prime-rl 0.8.0 on two abstractions: `Agent.run(task, *, runtime) -> Trace` and `Env.run(task, agents) -> None`, which expresses agentic judging, self-play and user simulation as ordinary environments with programmable credit assignment, Hierarchical GRPO and Role-Conditioned Advantage Estimation. The [verifiers v1 vocabulary](https://github.com/primeintellect-ai/verifiers/blob/main/docs/v1/overview.md) is the thing to align with: a *Harness* is "the program the model is run in, e.g. Claude Code, Codex or mini-swe-agent"; an *Agent* is harness x model x runtime policy; a *Trace* records the message graph, rewards, metrics, errors and one `ModelCall` per provider exchange; a *Toolset* is installed as MCP servers into harnesses that support them. Our fleet cell is their Agent triple under a different name.

[Prime Agent](https://github.com/PrimeIntellect-ai/prime-agent) is the closest public thing to our goal 4 and it is MIT with 20.1k stars: a persistent Python REPL plus durable harness state that the agent refines itself via `/refine`, subagents spawned programmatically through `rlm(...)`, a background daemon and an autonomous mode under budgets. Releases run v0.7.2 (11 August) to v0.9.3 (6 September). Its refinements are unversioned free text with no certificate and no paired experiment — which is precisely the gap we exist to fill, so it should be measured against, not copied.

[SkyRL](https://github.com/novasky-ai/skyrl) consolidated into one library with `skyrl-tx` as a Tinker API backend beside `skyrl-agent` and `skyrl-gym`; [verl](https://github.com/verl-project/verl) announced uni-agent in May with a gateway for 1,000+ concurrent stateful sessions and a continuous-token mechanism preserving token continuity across assistant output and tool feedback. That last detail matters to our exporter: if tool results are re-tokenised as text, boundary handling differs per model family. [TRL v1.0](https://huggingface.co/blog/trl-v1) (31 March, before the window) remains the low-infrastructure baseline and its own ecosystem table rates PRIME-RL's agent support as "tied to Prime Intellect's Environments Hub" — the coupling we should avoid inheriting.

The standing training environments are unchanged but still the reference: [SWE-Gym](https://huggingface.co/SWE-Gym) with 2,438 tasks from 11 repos and 491 released trajectories, where fine-tuning on under 500 sampled trajectories reported +14 points absolute on SWE-Bench Verified with a 32B model, and [SWE-smith](https://github.com/swe-bench/swe-smith) at 128 repos and ~50k instances. That ratio is the encouraging number for goal 3: a few hundred certified trajectories is one district's output.

## 5. Evaluation: the integrity crisis is now the story

On **8 July 2026** OpenAI published [Separating signal from noise in coding evaluations](https://openai.com/index/separating-signal-from-noise-coding-evaluations/), reporting that roughly 30% of SWE-Bench Pro's 731 public tasks are broken and **retracting its own February recommendation** to adopt it as a leading coding evaluation. The method is worth imitating: a data-quality pipeline flagged 286 tasks, then Codex-based investigator agents with repository access and five human engineers reviewed the flagged subset independently. Causes were hidden requirements, contradictory instructions, over-strict tests and incomplete grading. Secondary summaries give ~27% AI-flagged and ~34% human-flagged and note the leaderboard moving 23% to 80% in eight months. [SWE-Bench ProMax](https://arxiv.org/html/2608.09802v1) followed in August with 170 instances, explicitly motivated by flawed tests in Verified.

The Terminal-Bench team shipped [Terminal-Bench Challenges on 18 June](https://www.tbench.ai/news/terminal-bench-challenges): three long-horizon single-task benchmarks (Rust compiler speedup, sub-25kb inference-engine codegolf, WASM/WebGL renderer) with solution scopes of 10,000-500,000 lines and days per task, graded on task-specific correctness and performance. Twelve-hour agent runs produced marginal compiler progress and ~96.4% WebGL 1.0 / 20.5% WebGL 2.0 coverage — nobody is finishing these. [Harbor-Index](https://harbor-index.org/) followed on 6 July, and [Harbor](https://github.com/harbor-framework/harbor) (Apache-2.0, ~5k stars) is now the interoperability layer: arbitrary agents against Terminal-Bench 2.x, SWE-Bench and Aider Polyglot, across Docker, Daytona, Modal and other sandbox providers, with parallel experiments and rollout generation for RL. Published adapter lists include `dsh`. Harbor's installed-agent contract — install into a fresh container, run headless, post-run parse of tokens and USD cost — is a contract our fleet should both speak and demand of itself.

## 6. Multi-agent orchestration and always-on operation

The always-on category now has a real public baseline. [AI Village](https://theaidigest.org/village) has run over 15 agents every weekday since **1 April 2025**, eight hours a day 09:00-17:00 PT, at an order of $10k per month, with every action public and the [full dataset on Hugging Face](https://aivillageblog.substack.com/p/how-the-ai-village-works). Its memory design is the anti-pattern for us: agents consolidate every 40 actions and, when context fills, are prompted to rewrite memory shorter while keeping what they can. That is lossy and unauditable — the exact failure our "model-visible means logged" rule forbids.

[ruflo](https://github.com/ruvnet/ruflo) (MIT, 71.2k stars, formerly claude-flow) is the loudest peer and is analysed in `ruflo-comparison.md`. The most useful artefact it produced in the window is its own honest audit: its [dream-cycle ledger](https://github.com/ruvnet/ruflo/blob/main/docs/dream-cycle/LEDGER.md) records that 80 nightly research issues from 25 May to 13 August produced **4 shipped (5%), 1 rejected, 75 never touched**, and that after v2 tightened the loop, every night from 24 August to 5 September produced an evaluated ACCEPT whose pull request was still unmerged at the head commit. On 5 September the loop found its own CLI benchmark suite reporting every number, including a "V2 vs V3 Speedup: 5.00x", from `setTimeout()` calls with no code between them. Two of its policies are worth adopting outright: [ADR-169](https://github.com/ruvnet/ruflo/blob/main/v3/docs/adr/ADR-169-benchmark-reporting-integrity-standard.md), a binding five-rule standard for every published benchmark number, and its [signed per-OS witness manifests](https://github.com/ruvnet/ruflo/blob/main/verification/README.md) with Ed25519 attestation and a `witness-verify` CI job that blocks publish.

Elsewhere the pattern is containerised fleets with unverifiable operating claims. [Trinity](https://github.com/abilityai/trinity) advertises 1M+ agent runs per week, 99.94% scheduler uptime and "0 unaudited tool calls in production" — none substantiable from the repository, though the framing is one we could actually substantiate from the session log. Worktree-per-agent is now table stakes: [Kilo Code](https://kilo.ai/kilo-code/vs/cline) documents Code/Plan/Debug/Ask modes delegating to Explore/General/custom subagents with an Agent Manager across git worktrees.

## What Daliesk should do

1. **Ship a dual-era MCP server before Q4.** Goal 1, seam `packages/mcp`. Serve 2026-07-28 (`server/discover`, `resultType`, `ttlMs`/`cacheScope`) alongside 2025-11-25, and route elicitation through MRTR. Clients lag servers, so we gain compatibility without losing any.
2. **Adopt Prime Intellect's environment validation ritual in `ctx.environments`.** Goal 3/4. No-op must fail, gold check must pass with retries, record the drop count. Today we admit an environment on the author's word; after this we admit it on evidence, and the drop count belongs on the scoreboard.
3. **Publish and own a Harbor adapter for `dsh`.** Goal 4, seam `ctx.environmentRuns`. External leaderboards then run our harness unmodified, and Harbor's post-run token/USD contract becomes a recorded outcome of every fleet cell.
4. **Align `dsh-trajectory/1` with the verifiers `Trace`.** Goal 3, seam `ctx.trajectories`. One `ModelCall` record per provider exchange with model, sampling, finish reason, usage, timing and error, plus token boundaries per call so verl-class continuous-token training does not degrade. Rename our fleet cell to harness x model x runtime while we are there.
5. **Make reward provenance explicit, ruflo ADR-171 style.** Goal 3, seam `ctx.trajectories` + `ctx.judge`. A certificate-decided reward is ground truth; a judge verdict is a labelled second tier; nothing else may be blended into one number. We already have both mechanisms and no label.
6. **Put ADR-169's five reporting rules into the observatory's render path.** Goal 4, seam `ctx.observatory` + `ctx.scorekeeper`. An unlabelled metric, an undisclosed best-of-N or an aggregate hiding no-work passes should be unpublishable by construction, not by discipline.
7. **Add event-driven wake to shifts, as a logged event.** Goal 4, seam `ctx.shifts`. Amp shipped this on 23 July. Our version appends a wake event to the shift's ledger session before any cell is planned, so an externally triggered shift stays as reproducible as a cadenced one.
8. **Adopt signed, per-platform attestation for the composition manifest.** Goal 2/4, seam `packages/components` + `packages/bundle`. Ruflo's Ed25519 witness with a publish-blocking CI job is better than anything we ship for released artefacts and costs one dependency. Keep our executable checks; add their signature.
9. **Model licence and time-of-day pricing in the curator and budget policy.** Goal 1/3, seams `governance/` + `packages/guard`. A bespoke model licence (GLM-5.3) must be able to refuse a client purpose, and peak/off-peak API pricing makes a spend window a function of wall-clock time. Both are new in this window and neither is represented.
10. **Run one Terminal-Bench Challenge through `ctx.programs` as an external validity check.** Goal 2, seam `ctx.programs` + `ctx.completionStandards`. It is the only public benchmark shaped like a client deliverable, and the published results (nobody finishing) set the honest claim for a sales deck: certified partial progress with a certificate on the merged head, not completion.
