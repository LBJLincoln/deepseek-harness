### TOPAS: Workflow-Aware Prefix-State Scheduling for Multi-Agent LLM Serving

- Date 2026-08-26 · kind paper · role input · evidence primary · goals 1, 4 · seams budget-policy, fleet, shifts, subagent, workflow
- URL: <https://arxiv.org/abs/2608.25523>
- Summary: USTC and HFUT formalise the tradeoff between keeping an agent's long system-prompt KV cache resident and having memory left to batch concurrent requests. Diagnostic: serving same-agent requests together roughly doubles the mean running batch (9.3-11.5 against 4.7-5.0) and alternating between two agent prefixes takes 1.8-1.9x the makespan for identical work. Locality-first (longest prefix match) and progress-first (SRPT) policies each fail in complementary ways. TOPAS scores post-decision states that jointly choose which prefixes stay resident and which requests are admitted, trading expected reduction in each task's longest remaining service path against near-term prefix reuse, minus prefix-movement and preemption costs, with task-level aging to prevent starvation. Implemented on SGLang: mean/p99 job completion time down up to 39.8%/49.4% on synthetic DAGs, 9.8% mean on MetaGPT-SOP, 22.0%/26.6% on MetaGPT-TL. Scheduler overhead 1.9 ms per decision, 0.31% of wall time.
- Adopt: Adopt the scheduling insight for fleets and shifts: when many districts run concurrently against one serving pool, grouping same-preset work is worth more than fine-grained fairness, and interleaving distinct system prompts is directly costly. Relevant only when Daliesk serves its own weights; irrelevant against a third-party API. Test the grouped-versus-alternating diagnostic on the fleet before building a scheduler.
- Tags: kv-cache, multi-agent-serving, prefix-caching, scheduling, sglang

### Harness the Memory: A Holistic Evaluation of Memory Substrates in Memory Agents

- Date 2026-08-15 · kind paper · role input · evidence primary · goals 1 · seams compaction, context, session-log, skill, subagent
- URL: <https://arxiv.org/abs/2608.15008>
- Summary: UIC, UW, McGill, MBZUAI and UCLA isolate the memory substrate as the sole variable across 11 methods in seven families (flat dense/sparse index, text records, structural notes and graphs, hierarchical trees, refinement, parametric weights, activation/KV mechanisms), three backbones and four benchmarks, instrumented with 26 performance and efficiency metrics. Landscape analysis of 52 published memory systems: 62% of benchmark usage is LoCoMo plus LongMemEval, only 21% report any efficiency metric, 81% use GPT-family backbones alone. Findings: the optimal substrate reverses between regimes - dual-level graphs lead dialogue QA (LoCoMo judge 0.719 on Gemma-4) but are Pareto-dominated on agentic tasks, while refinement substrates lead embodied planning (distilled strategies 32.1% ALFWorld task success against 22.4% no-memory on Qwen3-32B-AWQ); retrieval depth helps QA and hurts agentic decisions, with an attention probe showing why; graph substrates can cost 10-100x more per query.
- Adopt: Adopt the design rule - trade read breadth for write depth - and the conclusion that memory must be a routed capability seam with several providers, not one implementation. Adopt their efficiency metric set (write tokens, write calls, management tokens, compression ratio) since almost nobody reports them. ### SlotGuard: Stop Oversharing Private Local Context in LLM Agent Transcripts

- Date 2026-07-19 · kind framework · role input · evidence primary · goals 3 · seams credentials, curator, hooks, session-log, trajectory-export
- URL: <https://arxiv.org/abs/2607.17147>
- Summary: UIUC place a local boundary between the agent runtime and the model provider, distinguishing two orthogonal leakage surfaces: structural bindings (paths, workspace roots, hostnames, branches, emails, sensitive entity names) and secret values (API keys, tokens, DB credentials).
