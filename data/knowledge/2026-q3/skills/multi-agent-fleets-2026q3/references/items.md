### Prime Intellect prime-agent

- Date 2026-09-06 · kind repo · role threat · evidence primary · goals 1, 3, 4 · seams code-runtime (Code Mode), ctx.subagents, packages/components, packages/improvement
- URL: <https://github.com/PrimeIntellect-ai/prime-agent>
- Summary: An MIT-licensed open-source coding and research agent built on a Recursive Language Model abstraction: a persistent Python REPL plus durable harness state (supplemental prompts, memories, skill descriptions) that the agent itself refines. `rlm(...)` calls are how it spawns subagents and uses tools programmatically; `/refine` reviews the current trajectory and applies small evidence-backed updates to the supplemental harness state; a background daemon keeps sessions alive and an autonomous mode runs under configurable budgets. - Adopt: This is the closest public thing to Daliesk's goal 4 and it is MIT. The `/refine` loop is exactly the harness auto-improvement we are building, but its updates are unversioned free text with no certificate and no experiment — that is our differentiator, so measure it rather than copy it. The programmatic-subagent-via-REPL pattern (`rlm(...)`) is worth testing against our `code-runtime` Code Mode Consumer: one Python program calling several delegations beats N tool round-trips on token cost.

### JIT-Agent: Scaling Harness Intelligence via Just-in-Time Harness Evolution

- Date 2026-08-26 · kind model · role threat · evidence primary · goals 1, 4 · seams bundle, composition-manifest, preset, self-modification, workflow
- URL: <https://arxiv.org/abs/2608.25593>
- Summary: Trains a 27B model (from Qwen3.6-27B) whose output is an executable, task-specific agent harness for an arbitrary off-the-shelf backbone, under a fixed four-module protocol of memory, planning, action and capability orchestration. HarnessFactory re-implements 13 representative scaffolds (ReAct, plan-and-execute, DAG planners, hierarchical and recursive systems) under that common interface as a seed bank. Three training stages: task-conditioned customisation from teacher examples, bounded repair trajectories learned from failed generations, and Evo-GDPO, which rewards candidates that overtake the current archive frontier while normalising reward, latency and cost separately. Across nine benchmarks it improves every matched backbone-benchmark pair: GLM-5.2 average 74.1 to 81.8 (+7.7), DeepSeek-V4-Flash 66.7 to 75.5 (+8.8), with +24.8 on DeepPlanning-Shopping and +20.2 on DeepPlanning-Travel. Against five fixed harnesses (Claude Code, Codex, OpenCode, Hermes, NanoBot) it wins 4 of 6 controlled settings and has the lowest token and cost in all six, cutting per-case cost 14.9-54.1% (about 36% average). Code open.
- Adopt: The four-module protocol maps onto Daliesk's plugin composition, so the transferable idea is that a preset can be generated per task rather than authored per profile. Test whether per-task composition beats a small set of authored presets before building a generator. Reject the framing that a bespoke harness per instance is auditable: content-addressed component identity is harder to maintain when the composition is model-authored at request time.

### SwarmWorld: Stigmergic Technological Evolution in Societies of Language-Model Agents

- Date 2026-08-26 · kind environment-hub · role baseline · evidence primary · goals 2, 4 · seams experiments, fleet, observatory, shifts, subagent, workflow
- URL: <https://arxiv.org/abs/2608.26081>
- Summary: MIT build a persistent, materially constrained multi-agent world where initially homogeneous LLM agents with no assigned roles explore, process resources, build persistent artifacts and author executable controllers that keep running between agent decisions. Cognition is separated from consequence: agents propose within fixed action and material schemas, a deterministic simulator decides what is legal and what functions, and evaluation removes all agents and replays the frozen technological state under eight unseen disturbance schedules. Ablations isolate communication, cross-agent program inheritance and physical stigmergy, compared against an endpoint-wise best-of-N envelope of matched isolated agents. Result is a bounded swarm advantage: shared worlds produce broader and more resilient portfolios and agents differentiate into exploration, construction, maintenance and coordination roles, but isolated search can still hold the strongest single artifact and explicit culture does not win on every endpoint (at N=200 the no-explicit-culture condition gives the largest discovery gain, +0.069). Robustness assay: random removal of 50% of agents leaves 0.983 of artifacts connected under full culture, targeted high-degree removal only 0.596. Code and data released.
- Adopt: Adopt the falsifiability standard for any multi-agent claim: compare against a best-of-N envelope of the same compute run independently, and evaluate the artifacts after removing the agents. Adopt the targeted-knockout assay for the fleet, where a small set of high-degree districts is likely to be disproportionately load-bearing. Reject the assumption that inter-agent communication is what buys the gain: shared persistent artifacts alone were competitive.

### TOPAS: Workflow-Aware Prefix-State Scheduling for Multi-Agent LLM Serving

- Date 2026-08-26 · kind paper · role input · evidence primary · goals 1, 4 · seams budget-policy, fleet, shifts, subagent, workflow
- URL: <https://arxiv.org/abs/2608.25523>
- Summary: USTC and HFUT formalise the tradeoff between keeping an agent's long system-prompt KV cache resident and having memory left to batch concurrent requests. Diagnostic: serving same-agent requests together roughly doubles the mean running batch (9.3-11.5 against 4.7-5.0) and alternating between two agent prefixes takes 1.8-1.9x the makespan for identical work. Locality-first (longest prefix match) and progress-first (SRPT) policies each fail in complementary ways. TOPAS scores post-decision states that jointly choose which prefixes stay resident and which requests are admitted, trading expected reduction in each task's longest remaining service path against near-term prefix reuse, minus prefix-movement and preemption costs, with task-level aging to prevent starvation. Implemented on SGLang: mean/p99 job completion time down up to 39.8%/49.4% on synthetic DAGs, 9.8% mean on MetaGPT-SOP, 22.0%/26.6% on MetaGPT-TL. Scheduler overhead 1.9 ms per decision, 0.31% of wall time.
- Adopt: Adopt the scheduling insight for fleets and shifts: when many districts run concurrently against one serving pool, grouping same-preset work is worth more than fine-grained fairness, and interleaving distinct system prompts is directly costly. Relevant only when Daliesk serves its own weights; irrelevant against a third-party API. Test the grouped-versus-alternating diagnostic on the fleet before building a scheduler.
- Tags: kv-cache, multi-agent-serving, prefix-caching, scheduling, sglang

### Prime Agent: A Self-Improving RLM Harness

- Date 2026-08-24 · kind framework · role threat · evidence primary · goals 1, 4 · seams agent-loop, compaction, self-modification, session-log, skill, subagent
- URL: <https://arxiv.org/abs/2608.23552>
- Summary: Open-source harness from Prime Intellect (with Princeton and MIT) organising agent state as L0 weights / L1 active context / L2 persistent IPython REPL and recursive subagents / L3 disk-backed history, memories, skills, prompts and subagent specs, changed by fine-tuning, compaction, agentic garbage collection and versioned refinement respectively. Recursive rlm() subagents communicate through daemon-mediated queues; an Agents View lets humans attach to live sessions. Reject the persistent-REPL-as-primary-interface choice until measured against the plugin tool surface. Test the out-of-loop-experiment count as a scorekeeper fact: it discriminates harnesses where pass rate does not.

### verifiers 0.3.0 and prime-rl 0.8.0: multi-agent RL

- Date 2026-08-07 · kind framework · role input · evidence primary · goals 3, 4 · seams ctx.environments, ctx.fleet, ctx.judge, ctx.trajectories, packages/mcp
- URL: <https://www.primeintellect.ai/blog/multi-agent-systems>
- Summary: Multi-agent support released in verifiers 0.3.0 and prime-rl 0.8.0. Two abstractions carry it: `Agent.run(task: Task, *, runtime: Runtime) -> Trace` produces one trace, and `Env.run(task: Task, agents: Agents) -> None` programs the full multi-agent control flow and collects every agent run into an episode. This expresses agentic judging (a solver graded by a judge), self-play and user simulation as ordinary environments, with programmable credit assignment across roles, Hierarchical GRPO for role-aware comparison and Role-Conditioned Advantage Estimation where roles have structurally different reward distributions. The verifiers v1 vocabulary is directly relevant: a Taskset is the loader for work to evaluate or train on; a Harness is 'the program the model is run in, e.g. Claude Code, Codex or mini-swe-agent'; an Agent is harness x model x runtime policy; a Trace records the message graph, rewards, metrics, errors and one ModelCall record per provider exchange; a Toolset is a set of task-defined tools installed as MCP servers into harnesses that support them.
- Adopt: Align our `dsh-trajectory/1` record with their Trace so a Daliesk run can be consumed by prime-rl without a bespoke converter — the per-ModelCall record (model, sampling, finish reason, usage, timing, error) is close to what our session log already holds. Their 'harness x model x runtime' Agent triple is exactly our fleet cell; adopting the naming costs nothing and buys interoperability. Their Toolset-as-MCP-server convention is a ready-made way to inject environment-specific tools through `packages/mcp` instead of forking a preset per environment.

### AI Village: the longest-running public multi-agent village

- Date 2026-06-16 · kind repo · role baseline · evidence primary · goals 4 · seams compaction seam, ctx.observatory, ctx.sessions, ctx.shifts
- URL: <https://theaidigest.org/village>
- Summary: AI Digest has run a village of over 15 agents — the most capable model from each leading lab plus the best open-source model, split into #best and #rest rooms — every weekday since 1 April 2025, eight hours a day from 09:00 to 17:00 PT, at an order of $10k per month. Agents consolidate memory every 40 actions and, when memory fills the context window, are prompted to rewrite it shorter while keeping what they can; a search-history tool queries earlier periods, so memory persists indefinitely across goal changes. Every action and the full historical context are public, and the dataset is available to researchers on Hugging Face. DeepSeek-V3.2 participates without multimodality and works through bash instead of screenshots. Village agents also run outreach: they file GitHub issues on other agent projects and maintain a machine-readable embassy repository with `llms.txt` and `.well-known/agent.json`.
- Adopt: The public-by-default record with a researcher dataset is the model for our observatory, and it is a year ahead of us on operating discipline. Their memory design is the anti-pattern for us: a model rewriting its own memory shorter is lossy and unauditable, which is exactly what 'model-visible equals logged' plus our compaction seam prevents. Use their published cost as a sanity check on district budgets.
- Tags: always-on, memory, multi-agent, public-results, village
