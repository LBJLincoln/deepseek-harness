### Terminal-Universe: Turning Agent Trajectories into Scalable Terminal Environments

- Date 2026-09-03 · kind environment-hub · role input · evidence primary · goals 3, 4 · seams certificates, curator, environment-runner, environments-registry, trajectory-export
- URL: <https://arxiv.org/abs/2609.04148>
- Summary: Qwen Team (Alibaba) with Tsinghua invert the usual pipeline: instead of rolling trajectories out of environments, they reconstruct environments from recorded trajectories. Deterministic replay of read/write/edit operations restores each touched file to its earliest observed state (excluding agent-created files), then an agentic completion step supplies missing files and dependencies without leaking the solution, and an agentic judge keeps only workspaces sufficient for their recovered task. From 359,593 source trajectories across six public corpora they obtain 68,263 reconstructed and 37,273 task-sufficient environments; agentic completion raises sufficiency from 40.2% to 93.5% (terminal) and 20.1% to 77.1% (SWE), and mean files per workspace from 2.9 to 22.4. Each environment is re-queried four ways: intent recovery, single-workspace synthesis, cross-workspace tasks mined from directional dependency edges, and multi-round user-feedback sessions. SFT on 32.0k verifier-filtered trajectories (1.42B tokens) lifts Qwen3.5-27B by +11.9 on Terminal-Bench 2.1 and +13.8 on EvoCode-Bench v2 MT@4; re-solving beats imitating source trajectories 52.1 against 36.7.
- Adopt: Adopt directly: Daliesk's session log already records every tool call, so trajectory-to-environment reconstruction turns the transcript archive into a registry without exporting anything. Adopt their three-stage pipeline including the sufficiency judge, and the finding that re-solving a recovered task beats imitating the recorded trajectory. Note their limitation: one teacher generates task, solution and verifier, so errors in the solution are invisible to its own tests - use an independent model for verifier construction.

### SwarmWorld: Stigmergic Technological Evolution in Societies of Language-Model Agents

- URL: <https://arxiv.org/abs/2608.26081>
- Summary: MIT build a persistent, materially constrained multi-agent world where initially homogeneous LLM agents with no assigned roles explore, process resources, build persistent artifacts and author executable controllers that keep running between agent decisions. ### The Verification Horizon: No Silver Bullet for Coding Agent Rewards

- Date 2026-06-24 · kind paper · role input · evidence primary · goals 3, 4 · seams certificates, environment-runner, guard, scorekeeper
- URL: <https://arxiv.org/abs/2606.26300>
- Summary: Qwen Team position paper plus four reward constructions. ### Hardening Agent Benchmarks with Adversarial Hacker-Fixer Loops (and Terminal Wrench)

- Date 2026-06-08 · kind benchmark · role input · evidence primary · goals 3, 4 · seams certificates, environment-runner, environments-registry, guard, shifts
- URL: <https://arxiv.org/abs/2606.08960>
- Summary: CMU with Fewshot Corp. Audits 1,968 tasks across Terminal-Bench 1.0/2.0, Terminal-Bench-Pro, OpenThoughts-TB-dev and SETA with three frontier attackers given only the task description; 323 (16%) are hackable, including 13 of 89 Terminal-Bench 2.0 environments. Released as Terminal Wrench: 323 hackable environments and 3,632 confirmed hack trajectories. The hacker-fixer loop alternates three agents - a hacker seeking exploits, a fixer patching the verifier, and a solver that vetoes over-restrictive patches - augmented by verifier source access for the hacker and a shared cross-task defence pool. On KernelBench, held-out attack success falls 62% to 0% (documented exploits) and 76%/61% to 0% for stronger blind Gemini 3.1 Pro and Claude Opus 4.7. On 77 Terminal Bench tasks, hinted ASR 50.4% to 39.4% and unhinted 39.2% to 16.7%, while benign pass rate falls 76.1% to 65.2%. Task 001's final KernelBench verifier contains code contributed by fixers on 13 other tasks.
- Adopt: Adopt the three-role loop, especially the solver veto: a fixer without it silently blocks legitimate solutions, which in a certificate-first design means silently invalidating correct runs. Adopt a shared defence pool so a hardening fix on one environment propagates across the registry, and run the loop as a scheduled shift rather than a reaction to a discovered exploit. Budget for the 11pp legitimate-solution loss.
