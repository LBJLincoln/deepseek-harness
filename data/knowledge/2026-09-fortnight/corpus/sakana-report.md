# Sakana's "multi router", and multi-model routing for agentic coding

Window: 2026-07-27 to 2026-09-07. Older items appear only as the origin of a line of work.

## 1. What "multi router" is

The lab lead's "multi router structure" is **Sakana Fugu**, a family of *orchestrator models* launched 2026-06-22 and documented in the Sakana Fugu Technical Report ([arXiv:2606.21228](https://arxiv.org/abs/2606.21228), v1 2026-06-19, v2 2026-06-23). It is not AB-MCTS/TreeQuest, not ShinkaEvolve, and not the Darwin Gödel Machine line. Those continue, but the routing work has moved to two ICLR 2026 papers that Fugu productises: **TRINITY** ([arXiv:2512.04695](https://arxiv.org/abs/2512.04695)) and **the Conductor** ([arXiv:2512.04388](https://arxiv.org/abs/2512.04388)).

Two variants, two different algorithms — both reimplementable:

**Fugu (latency variant, from TRINITY).** A pre-trained LM backbone with a *lightweight selection head* in parallel to the LM head. For a pool of `L` workers the head maps one hidden state `h in R^d` to `L` logits; the query is dispatched to the argmax worker. Crucially the orchestrator's *text is never generated* — the decision is read off an early-token hidden state, so orchestration adds no autoregressive decode. Training is two-stage: (i) SFT against a **soft target distribution** — run every worker `n` times on each verifiable task, average rewards into `s_i = (r_i1 ... r_iK)`, softmax with temperature tau, minimise `KL(p_i || pi_theta(.|q_i))`, training only the head plus *singular-value scales* of selected backbone matrices; (ii) **sep-CMA-ES** on end-to-end multi-turn tasks harvested from real Claude Code, Codex and OpenCode trajectories, maximising `J(theta)=E_tau[R(tau)]` with binary terminal reward under a fixed turn budget `B`. Granularity is **one worker per turn**, re-decided at every turn from the interaction state. TRINITY's ancestor adds a role (Thinker/Worker/Verifier) and terminates when the Verifier ACCEPTs or the turn budget `K=5` is exhausted; total trainable parameters under 20K over a Qwen3-0.6B backbone.

**Fugu-Ultra (quality variant, from the Conductor).** A 7B LM trained with GRPO (no KL penalty) to emit an entire workflow as three parsed Python lists — `model_id`, `subtasks` (natural-language instructions), `access_list` (which prior outputs each worker may see) — of up to 5 steps over Gemini-3.1-Pro, Claude-Opus-4.8 and GPT-5.5. Reward: 0 if unparseable, 1 if the final output matches the solution, 0.5 otherwise. Ultra adds long-horizon function calling: workflow state is tracked so each agent's tool loop returns to it, agents are **isolated within a workflow** (to prevent "orchestration collapse", where the first agent's path fixes everyone's), but share memory *across* workflows so tools are not re-run.

Reported results (technical report Table 1; baselines are provider-reported): SWE-Bench Pro **73.7** (Ultra) / 59.0 (Fugu) vs Opus 4.8 69.2, GPT-5.5 58.6, Gemini 3.1 54.2 — though the non-public Fable 5 reports 80.0. Terminal Bench 2.1 **82.1** / 80.2 vs 74.6 / 78.2 / 70.3. LiveCodeBench 93.2 / 92.9. GPQA-Diamond 95.5 / 95.5. The Conductor paper reports a 7B conductor at 77.27 average vs GPT-5's 74.78 across seven tasks; TRINITY claims a LiveCodeBench record of 86.2 +/- 0.5% pass@1, while in its own *controlled* 4K-token setting it scores 0.615 against 0.58 for GPT-5 — the gap between those two numbers is a budget artefact, not a contradiction.

The finding most relevant to Daliesk is qualitative and in section 4.1.2 of the technical report: on Terminal Bench, **Fugu alternates GPT-5.5 and Claude-Opus-4.8 within a single trajectory, calling in Opus at particular critical debugging points**. That is per-step model selection inside an agent loop, and it is the mechanism the harness's subagent and LLM seams would have to expose.

## 2. What actually landed in the window

Sakana shipped product, not new routing algorithms, between 27 July and 7 September.

The load-bearing item is **["Toward base-model-independent orchestration: validating a Gemma 4 Fugu"](https://sakana.ai/fugu-gemma4/), 2026-08-10**: the conductor was retrained on Gemma 4 (Apache 2.0) instead of the Qwen-based original and "achieved performance comparable to the existing conductor model" with equivalent cost reduction, against a control of **random model assignment** normalised to cost 1.0. Sakana's conclusion — different families can serve as the conductor base, so pool and conductor layer modularise independently, with domestic-model conductors named as the sovereignty motivation — is the same argument a European lab would make. Note the honest limit: proprietary eval set, relative costs only, no absolute numbers.

Also in window: the [`SakanaAI/fugu`](https://github.com/SakanaAI/fugu) repo (updated 2026-08-24, 996 stars, **no licence shown**) is a shell installer, not the model — `curl -fsSL https://sakana.ai/fugu/install | bash` then `claude-fugu` or `codex-fugu`, i.e. Fugu substituting itself for the model behind Claude Code and Codex. [ShinkaEvolve](https://github.com/SakanaAI/ShinkaEvolve) (Apache 2.0) saw commits on 2026-08-21 with no release past v0.0.7 (2026-06-02); [ALE-Bench](https://github.com/SakanaAI/ALE-Bench) (Apache 2.0) updated 2026-09-05. Sakana Chat gained Fugu on 2026-08-13; the Namazu Japanese-language API shipped 2026-08-03.

Just outside the window, two items frame it: **Fugu-Cyber** ([2026-07-21](https://sakana.ai/fugu-cyber-release/), CyberGym 86.9%, CTI-REALM 72.1%, gated by application review), and NVIDIA's [2026-07-15 announcement](https://nvidianews.nvidia.com/news/japans-enterprises-and-startups-build-industry-specialized-ai-with-nvidia-nemotron-open-models) that Nemotron is being integrated into Fugu's pool. Meanwhile **[TreeQuest/AB-MCTS](https://github.com/SakanaAI/treequest)** (Apache 2.0, 565 stars, 17 commits) shows no in-window activity: adaptive-branching search over several models has been superseded, inside Sakana, by learned orchestrators.

Two commercial facts matter more than any benchmark. Fugu is **unavailable in the EU/EEA** (GDPR compliance stated as in progress), and its weights and orchestration code are closed — the papers are the only reimplementable artefact. Pricing is subscription ($20/$100/$200 per month) or tokens ($5/$30 per 1M for Ultra), with multi-agent calls billed at the highest-tier model's rate rather than stacked.

## 3. The wider field: routing for coding agents

The window was unusually productive, and the results point in a consistent direction.

**Per-step routing inside agent loops works when the signal is progress, not difficulty.** [ProgRouter](https://arxiv.org/abs/2608.25992) (2026-08-26) scores workflow progress from four views (outcome regime, subtask completion, progress trend, state-quality delta), predicts each candidate model's *progress gain*, and selects per dispatch step under a Lyapunov virtual queue enforcing a long-run cost budget; 93.0% on HumanEval Plus within a 4,800 J budget and 79.4% on MBPP at 3,376 J, best on every metric there, concentrating 84.3% of calls on Qwen2.5-Coder-0.5B. [TACIT-Switch](https://arxiv.org/abs/2608.27911) (2026-08-28) makes the handoff *permanent and adaptively timed*: a mixture-cure threshold model over cumulative trajectory risk, trained from teacher-annotated censored intervention windows, no teacher at deployment. ALFWorld 48.5% (4B->27B) against 22.4% for a fixed-prefix SWE-Router analogue and 50.7% for pure-27B; DABench 73.1% at lower cost than pure-27B's 68.7%. Neither has SWE-bench evidence.

**Escalation can be fired mid-generation.** [Bayesian Self-Escalation](https://arxiv.org/abs/2608.24087) (2026-08-25) frames intra-generation handoff as optimal stopping over a *learned* competence posterior (not raw entropy), with a regret bound making calibration the binding constraint. Its real-model check on MBPP (Qwen2.5-Coder 1.5B->7B, 257 tasks) reaches 74.7% at **0.98x junior-only compute**, versus post-hoc routing's 75.0% at 1.41x, because aborting doomed generations pays for the senior calls. Junior alone 62.3%, senior 80.9%.

**Cascade routing is being reformulated as decision-making, not prediction.** [RLCascadeRouter](https://arxiv.org/abs/2608.15817) (2026-08-16) drops the quality estimator entirely, treating stop-or-pick-next as an MDP; on LLMRouterBench it reaches 68.81% macro-average against Avengers-Pro's 67.84 and GPT-5's 65.12, and at a matched ~67% cuts cost 20.8% versus Avengers-Pro and 31.6% versus GPT-5. It absorbs unseen models without retraining (90.99% retention). [Pandora's Router](https://arxiv.org/abs/2608.20316) (Google DeepMind, 2026-08-20) formalises *the cost of deciding* as Pandora's Box with non-obligatory inspection, giving closed-form reservation prices under a Gaussian signal model; it matches exhaustive value estimation while querying the expensive estimator far less. Neither covers agentic coding.

**Infrastructure exists now.** [LLMRouter + xRouteBench](https://arxiv.org/abs/2608.06867) (UIUC, 2026-08-07) gives 16+ routers behind one interface, an 18-model pool and 4,767 instances, with three findings worth internalising: learned routers beat the strongest fixed model by 14.6% relative; **router rankings reverse under tighter cost budgets**; and multi-turn routing does *not* consistently beat single-turn.

**Vendors already do the job.** OpenRouter Fusion (API release 2026-06-13) fuses a panel of models via a judge and reports 64.7% on Perplexity's DRACO against solo GPT-5.5's 60.0% at roughly half the cost (secondary). Claude Code exposes per-subagent model selection and Cursor 3 per-agent routing (secondary). And Sakana's own installer replaces the model *behind* Claude Code. Daliesk's differentiator therefore cannot be "we route"; it has to be that routing decisions are logged session events reconstructable from the log, and that certificates — not judges — decide.

## 4. Negative results, and how to measure

Three in-window papers should govern the experiment design.

**The Handoff Tax** ([arXiv:2608.24358](https://arxiv.org/abs/2608.24358), AWS Agentic AI, 2026-08-25) is the most important. SWE-bench Verified, all 500 instances, mini-swe-agent, Haiku 4.5->Opus 4.7 and GPT-5.6 Luna->Sol, seven difficulty-calibrated switch points, **58,000 agent runs / 2M API calls / 36B tokens**. Result: escalating mid-trajectory while passing the full transcript recovers **less than half** the cheap-to-strong quality gap (QRec 47% Claude, 36% GPT) and costs 4.0x/6.1x the cheap model — for Claude, $1.61 against $0.72 for simply starting on Opus (CSRet -285%). The interface preference *reverses with direction*: **dropping** the cheap model's trajectory improves escalation (QRec 64% at $0.94), while **preserving** the strong model's trajectory is what makes downshift work. Mechanism: raw escalation makes each strong step 2.2x costlier (context inflation), while trajectory-drop downshift takes 1.6-2.0x more cheap steps (rediscovery). Downshift, not escalation, is the profitable direction.

**Most of the LLM Routing Gap Is Task Type** ([arXiv:2608.23023](https://arxiv.org/abs/2608.23023), 2026-08-25) executes 14 models x 294 questions twice at temperature 0 and seed 42. **5.37% of the 4,116 model-question cells flip their correct bit on identical re-execution.** The oracle-minus-best-single gap is 29 items (9.86pp); a *static task-type lookup, fitted once and never updated*, recovers 21 of them, and adding language leaves 6 of 294 (2.04%) — below the reproducibility floor. The static table answers 262/294 at $3.33 per run against the best single model's 245 at $7.69. It sits downstream of the "routing plateau" result (arXiv:2606.07587) that 21 routing methods land within a fraction of a point of each other. Related: [Budget-Dependent Rankings](https://arxiv.org/abs/2608.12150) (2026-08-12) shows the best model *changes identity* with the token budget on all three benchmarks tested, and a budget-aware router captures only 14.1% of a +27.8pp oracle gap.

**Routing must be priced per completed task.** PayPal's [T2MO](https://arxiv.org/abs/2608.08528) (2026-08-09) gives the rule: `E[cost | m,c] = C_m(c) + (1 - P_m(c)) * [C_M(c) + W]`, so a candidate displaces the incumbent only when `P_m(c) > 1 - (C_M - C_m)/(C_M + W)`. Their measured in-harness pass rates for one cheap model — 100/100/47% on Git-workflow easy/medium/hard, but 100/50/25% on Frontend — show displacement is a property of the *(task category, difficulty)* cell, never the category.

## Hypotheses Daliesk can test on a subscription

Assume one vendor CLI subscription giving a cheap, a mid and a top tier through the operator's Claude Code installation (subagent seam, MCP tool bridge, LLM route). **Common measurement for every hypothesis**: certified rate on identical restored environment fixtures, checks run by the environment runner; matched total token budget across arms; cost per certified task in tokens and in currency; attempts recorded per environment; paired seeds; and — per H5 — at least three repetitions per cell before any effect under 5pp is claimed. Every routing decision is a logged session event.

**H1 — The handoff tax replicates on our environments.** *Prediction*: escalating from cheap to top tier mid-run while passing the full transcript recovers <50% of the cheap-to-top certified-rate gap and costs more per certified task than starting on the top tier. *Baseline*: top-tier-only at the same budget. *Source*: arXiv:2608.24358.

**H2 — Dropping the cheap transcript beats carrying it.** *Prediction*: escalating with the worktree and the certificate preserved but the cheap tier's transcript discarded beats raw-transcript escalation by >=10pp certified rate at equal or lower cost per certified task. *Baseline*: raw-transcript escalation (the H1 arm). *Source*: arXiv:2608.24358 (Traj-drop QRec 64% vs Raw 48%).

**H3 — Downshift is the profitable direction.** *Prediction*: authoring the certificate and plan on the top tier, then downshifting to the cheap tier for implementation with the top tier's transcript **preserved**, retains >=80% of top-tier certified rate at <=60% of cost per certified task. *Baseline*: top-tier-only. *Source*: arXiv:2608.24358 (downshift dominates escalation; preserving strong-model context is what makes it work). This is the hypothesis best aligned with certificates-before-code.

**H4 — A static department table beats a learned router.** *Prediction*: a fixed model-per-department lookup (spec digest -> cheap; implementation -> mid; integration and debugging -> top), fitted once on the environments registry, is within 2pp of any learned per-task router while costing less. *Baseline*: a learned per-environment router trained on our own certified runs. *Source*: arXiv:2608.23023 (21/29 of the oracle gap recovered by a static task-type table).

**H5 — Our own certificates flip on re-execution.** *Prediction*: re-running identical fixtures at fixed seed flips >=3% of environment x model certified verdicts, so any routing win below ~5pp is unresolved from a single paired run. *Baseline*: the assumption of determinism currently implicit in paired-seed experiments. *Source*: arXiv:2608.23023 (5.37% cell flips at temperature 0). This is a prerequisite for trusting H1-H4, and cheap to run.

**H6 — Repeated attempts on one tier beat routing across tiers.** *Prediction*: at matched token budget, k independent top-tier attempts selected by certificate outcome beat any per-step cross-tier routing on certified rate and on cost per certified task. *Baseline*: the best per-step router from H1-H3. *Source*: arXiv:2608.22191 (Risa lifts SWE-bench Verified 44.9 -> 48.2% but only *matches* plain text consensus, with a 60.9% oracle still open) plus the routing plateau.

**H7 — Expected-cost-per-certified-task routing never loses money.** *Prediction*: applying T2MO's routing boundary per (department, difficulty) cell displaces strictly fewer cells to the cheap tier than token-cost minimisation, and its realised cost per certified task is never higher. *Baseline*: token-cost minimisation on the same cells. *Source*: arXiv:2608.08528, Proposition 1 (escalation dominance).

**H8 — In-loop progress signals beat pre-task difficulty prediction.** *Prediction*: a permanent handoff fired from cumulative in-loop risk (repeated tool calls, stalled diff, repeatedly failing checks) reaches within 5pp of top-tier certified rate at <=1.2x cheap-tier compute, beating any router that commits before the run starts. *Baseline*: pre-task routing on environment metadata. *Source*: arXiv:2608.27911 (TACIT-Switch beats task-, step- and fixed-prefix routing), arXiv:2608.24087 (74.7% at 0.98x junior compute), arXiv:2608.25992.
